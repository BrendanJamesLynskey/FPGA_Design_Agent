End-to-end FPGA Agent

An agent that closes the loop: it builds a design, measures it on real hardware, and uses what it measures to decide its next step.

Built and measured on a Digilent Nexys A7-100T (Artix-7). Next: AMD Kria KR260 and ZedBoard (Zynq-7000).

Describe a block in plain English. The agent asks about what you left out, writes the design and its tests, builds it with Vivado and programs the board. Everything that comes back, from a timing report to a test over the board's serial link, is read by code, and a failed check sends the work back to the part of the agent that can fix it.

The loop, on the bench

This is the classic agent loop of plan, act, observe and decide, drawn with the parts of the real set-up. The role agents plan and write. The design then goes through the simulators, Vivado and the board, and the instruments measure the board's pins. Each part returns something a program can read, which enters a gate. The controller sends a pass on to the next stage and a failure back to the role that owns it.

Can the whole loop run without a person?

Every leg of the loop is a measurement a program can read, so the whole loop can be automated. That is the project's aim and its potential, not yet its result. Most legs already run with no one at the bench; the rest are listed below with what still needs a person.

What it does

The agent follows the stages of AMD's UltraFast methodology: an interview to settle what the spec leaves open, a plan, the RTL and its tests, then Vivado 2025.2 through synthesis and place and route to a bitstream. The runs shown here used Anthropic's Claude Sonnet (claude-sonnet-5-5) through Claude Code. The agent shows how it is built: a controller in code over a small team of model agents, each with a narrow job, inside a harness that decides what each model sees and may do.

How it is checked

A model that writes a design and its tests can make the same mistake in both. So the agent's own tests never decide. Each task has hidden tests, written in advance against an independent model of the spec and themselves checked by mutation testing. Timing must be met after routing, and the board has the last word.

What has been shown so far

On 11 development tasks the agent passed every hidden test in 13 of 21 runs. In 6 more its own checks passed and the hidden tests failed, each time because it read the spec differently from the test author. The fixes made since are not yet measured.

Development tasks are the ones used to find faults, so these figures are a record of the work, not a score. The score will come from held-out tasks; the first attempt was stopped before any result was analysed. A hand-built reference design passes all its tests on the board. One design the agent built, in a Deep Agents smoke run on the small T1 design, has been programmed onto the board: it passed 3 of 3 serial-link tests and failed its captures of internal signals, so no design the agent built has yet passed every test on the board.
