Problems / H. Video and image processing

Colour bars on the Nexys A7 VGA connector at 1280 x 720

c9_nexys_vga_720p Course tier course part 9 H Video and image processing Nexys A7-100T

The problem

A video output for the Nexys A7 board that draws eight vertical colour bars on its VGA connector as a high-definition picture. The design counts pixels and lines to make the horizontal and vertical sync pulses that tell a monitor where each line and frame begins, and puts the bar colours out in step with them. The picture is blank outside the visible area and while the reset button is held. A small status register reports whether the video clock has locked.

Where it is used. Every monitor, projector and capture device is driven by a timing generator like this one. FPGA boards use the same structure for test patterns and as the first stage of a video pipeline.

Adapted from a project in the owner's FPGA design course (the course itself is private).

The spec the agent is given

Colour bars on the Nexys A7 VGA connector at 1280 x 720

I want the Nexys A7-100T to put eight vertical colour bars on its VGA connector as a 1280 x 720 picture at 60 Hz. (My capture dongle rejects 640 x 480, so it has to be 720p.)

  • Inputs: the 100 MHz board clock CLK100MHZ, the centre button BTNC (a reset while pressed) and the switches SW[1:0] (the board's SW bus; the other switches are unused). Outputs: VGA_R[3:0], VGA_G[3:0], VGA_B[3:0], VGA_HS, VGA_VS, and LED[0], which lights when the video clock is stable. Use the board's own pin names.
  • Timing: the CEA-861 1280 x 720 at 60 Hz timing: pixel clock 74.25 MHz, 1650 pixel clocks per line (1280 active, 110 front porch, 40 sync, 220 back porch) and 750 lines per frame (720 active, 5 front porch, 5 sync, 20 back porch). Both sync pulses are positive (idle low, high during the sync).
  • Picture, when SW[1:0] = 00: eight bars of 160 pixels each, left to right white, yellow, cyan, green, magenta, red, blue, black, at full intensity (a lit colour channel is 4'b1111). Everywhere outside the 1280 x 720 active area the colour outputs are zero. What the other switch values show is up to you; I only test 00.
  • The colour outputs and both sync outputs leave the chip aligned with each other: the first white pixel appears exactly 220 pixel clocks after the horizontal sync pulse ends, and the first picture line exactly 20 lines after the vertical sync pulse ends.
  • While BTNC is pressed, or the video clock is not yet stable, the outputs show no picture (colours zero).
  • The design must close timing at the pixel clock.
  • I will watch the outputs for a frame in simulation and measure the line and frame periods, the sync widths and polarity, the position of the picture against the sync pulses, and the colours of the bars. (In my simulation the clock input is treated as the pixel clock; in the real design it is the 100 MHz board clock.)
  • The test shell is on the USB-UART at 115200 baud, as for every board design; its window needs only one status register for this design. The design ID is "V720".

Test hooks: top module c9_nexys_vga_720p_top, ports named as in the board's master XDC, the test shell's CLKS_PER_BIT, TIMEOUT_CYCLES and BUILD_STAMP parameters as top-level parameters, and a one-bit parameter SIM_DIRECT_CLOCK (default 0): when 1 the CLK100MHZ input is used directly as the pixel clock (no clock generator in the design, the clock counts as stable). There are no other time constants.

Exactly spec.md. Anything it leaves open, the agent has to ask about.

What the hidden tests check

The requirements in the hidden spec, and how each is shown to hold:

  • REQ-01 line period 1650, hs width 40, frame 750 lines, vs width 5 lines, both positive (shown by simulation)
  • REQ-02 picture 220 clocks and 20 lines after the end of the sync pulses; eight 160-pixel bars with the stated colours; black outside the active area (shown by simulation)
  • REQ-03 colours are 0 while BTNC is pressed (shown by simulation)
  • REQ-04 timing closes at 74.25 MHz (shown by report analysis)
The full behaviour rules from hidden/spec.yaml

timing

  • H 1280+110+40+220 = 1650 clocks, V 720+5+5+20 = 750 lines; hs and vs idle low, high during sync (positive polarity)

pattern

  • SW[1:0] = 00 -> eight bars of 160 pixels, 4-bit channels, colours FFF FF0 0FF 0F0 F0F F00 00F 000 left to right; black outside the active area

alignment

  • colour and syncs leave from one output register rank; the first white pixel is 220 clocks after the hs falling edge, the first picture line is 20 lines after the vs falling edge

reset

  • while BTNC is pressed or the clock is not locked the colour outputs are 0

sim

  • parameter SIM_DIRECT_CLOCK = 1 makes the clock input the pixel clock (no MMCM, locked = 1); the bench uses it. With 0 an MMCM makes 74.25 MHz from the 100 MHz clock (VCO 742.5 MHz: DIVCLK_DIVIDE 5, CLKFBOUT_MULT_F 37.125, CLKOUT0_DIVIDE_F 10)

led

  • LED[0] = video clock locked (1 in simulation with SIM_DIRECT_CLOCK = 1); the other LEDs are 0

data

  • the bench measures one whole frame after BTNC is released (line period, hs width, vs width in lines, frame period, picture position against hs and vs, bar colours at and next to every bar edge, blanking)

Settled assumptions

  • the LEDs stay off. nothing is asked of them.

// c9_nexys_vga_720p_top.sv: board top (Nexys A7-100T, master-XDC port names), test shell DESIGN_ID "V720".
// Reference design for course task c9_nexys_vga_720p: 1280x720@60 colour bars (vga_bars_720p) plus the shell window (one status register).
// SIM_DIRECT_CLOCK = 1: CLK100MHZ is the pixel clock and no MMCM is built (the bench uses it).
module c9_nexys_vga_720p_top #(
    parameter int          CLKS_PER_BIT     = 868,
    parameter int          TIMEOUT_CYCLES   = 100_000,
    parameter logic [31:0] BUILD_STAMP      = 32'h0,
    parameter bit          SIM_DIRECT_CLOCK = 1'b0
) (
    input  logic        CLK100MHZ,
    input  logic        CPU_RESETN,
    input  logic        BTNC,
    input  logic [15:0] SW,
    output logic [3:0]  VGA_R,
    output logic [3:0]  VGA_G,
    output logic [3:0]  VGA_B,
    output logic        VGA_HS,
    output logic        VGA_VS,
    output logic [15:0] LED,
    input  logic        UART_TXD_IN,
    output logic        UART_RXD_OUT
);
    logic        clk, rst, win_wr, win_rd, locked;
    logic [6:0]  win_addr;
    logic [31:0] win_wdata, win_rdata;

    assign clk = CLK100MHZ;
    reset_sync u_rst (.clk(clk), .rst_n_async(CPU_RESETN), .rst(rst));

    fpga_shell #(.CLKS_PER_BIT(CLKS_PER_BIT), .TIMEOUT_CYCLES(TIMEOUT_CYCLES),
                 .DESIGN_ID(32'h56373230), .BUILD_STAMP(BUILD_STAMP)) u_shell (
        .clk(clk), .rst(rst), .uart_rx(UART_TXD_IN), .uart_tx(UART_RXD_OUT),
        .win_addr(win_addr), .win_wr(win_wr), .win_rd(win_rd), .win_wdata(win_wdata), .win_rdata(win_rdata));

    vga_bars_720p #(.SIM(SIM_DIRECT_CLOCK)) u_video (
        .CLK100MHZ(CLK100MHZ), .BTNC(BTNC), .SW(SW[1:0]), .LED0(locked),
        .VGA_R(VGA_R), .VGA_G(VGA_G), .VGA_B(VGA_B), .VGA_HS(VGA_HS), .VGA_VS(VGA_VS));

    // the MMCM's LOCKED output belongs to the pixel-clock world: a two-flop synchroniser brings it into the system clock before the LED and the status register use it
    (* ASYNC_REG = "TRUE" *) logic [1:0] locked_sync = 2'b00;
    always_ff @(posedge clk) locked_sync <= {locked_sync[0], locked};
    wire locked_s = locked_sync[1];

    assign LED = {15'd0, locked_s};

    always_ff @(posedge clk) begin
        win_rdata <= 32'd0;
        if (win_rd && win_addr == 7'h00) win_rdata <= {31'd0, locked_s};
        if (rst) win_rdata <= 32'd0;
    end
endmodule

// Part 9 lesson 2 reference solution: a test-pattern generator.
module tpg #(
    parameter int W = 160,
    parameter int H = 120
) (
    input  logic        clk,
    input  logic        de,
    input  logic [11:0] x,
    input  logic [11:0] y,
    input  logic [1:0]  sel,
    input  logic [7:0]  frame,
    output logic        de_q,
    output logic [3:0]  r,
    output logic [3:0]  g,
    output logic [3:0]  b
);
    localparam int BAR_W = W / 8;
    function automatic logic [11:0] bar_colour(input int idx);
        case (idx)
            0: bar_colour = 12'hFFF;
            1: bar_colour = 12'hFF0;
            2: bar_colour = 12'h0FF;
            3: bar_colour = 12'h0F0;
            4: bar_colour = 12'hF0F;
            5: bar_colour = 12'hF00;
            6: bar_colour = 12'h00F;
            default: bar_colour = 12'h000;
        endcase
    endfunction

    int ox, oy;
    logic [11:0] px;
    always_comb begin
        ox = (2 * int'(frame)) % (W - 32);
        oy = int'(frame) % (H - 32);
        px = 12'h000;
        case (sel)
            2'd0: px = bar_colour(int'(x) / BAR_W);
            2'd1: px = (((x >> 3) ^ (y >> 3)) & 12'd1) ? 12'hFFF : 12'h000;
            2'd2: px = {3{4'((int'(x) * 16) / W)}};
            2'd3: px = (int'(x) >= ox && int'(x) < ox + 32 && int'(y) >= oy && int'(y) < oy + 32) ? 12'hFFF : 12'h888;
        endcase
    end
    always_ff @(posedge clk) begin
        de_q <= de;
        {r, g, b} <= de ? px : 12'h000;
    end
endmodule

// P9-2 reference: 1280x720@60 colour bars on the Nexys A7 VGA connector (CEA-861 timing, 74.25 MHz pixel clock, positive syncs). SIM = 1 swaps the MMCM for a wire.
// (Copy of the lab top labs/p9_video/vga_pattern_top_720p.sv; PIX_25_175 = 1 selects the 74.25 MHz MMCM settings.)
// Part 9 lab 1 (Nexys A7-100T, VGA): the test patterns of lesson 2 on a monitor, 640 x 480 at about 60 Hz.
//
// 100 MHz oscillator -> MMCME2_BASE -> pixel clock: 25.1748 MHz (VCO 900 MHz = 100 MHz x 9, CLKOUT0 divide 35.75; 6.9 ppm from 25.175) or, with
// PIX_25_175 = 0, exactly 25.000 MHz (VCO 600 MHz, divide 24). The timing generator and pattern generator are the course's reference solutions
// (solutions/p9l02_vtg, solutions/p9l02_tpg). SW[1:0] picks the pattern (bars, checkerboard, ramp, moving box); BTNC is a reset. Both cross into the pixel clock through two-flop synchronisers (07a1c).
// The pattern generator registers its colour, so hs and vs are delayed by one clock to stay aligned with it (lesson 2, section 5).
// SIM = 1 swaps the MMCM for a wire so the file also runs in Icarus (labs/p9_video/test_lab_vga.py).
module vga_bars_720p #(
    parameter bit SIM = 1'b0,
    parameter bit PIX_25_175 = 1'b1
) (
    input  logic        CLK100MHZ,
    input  logic        BTNC,
    input  logic [1:0]  SW,
    output logic        LED0,
    output logic [3:0]  VGA_R,
    output logic [3:0]  VGA_G,
    output logic [3:0]  VGA_B,
    output logic        VGA_HS,
    output logic        VGA_VS
);
    logic pix_clk, locked;
    assign LED0 = locked;                  // lit when the MMCM has locked
    generate
        if (SIM) begin : g_sim
            assign pix_clk = CLK100MHZ;
            assign locked  = 1'b1;
        end else begin : g_mmcm
            logic clkfb, clk0, clk0_b;
            MMCME2_BASE #(
                .CLKIN1_PERIOD(10.000),
                .DIVCLK_DIVIDE(PIX_25_175 ? 5 : 1),
                .CLKFBOUT_MULT_F(PIX_25_175 ? 37.125 : 6.000),
                .CLKOUT0_DIVIDE_F(PIX_25_175 ? 10.000 : 24.000)
            ) u_mmcm (
                .CLKIN1(CLK100MHZ), .CLKFBIN(clkfb), .CLKFBOUT(clkfb), .CLKOUT0(clk0), .LOCKED(locked), .PWRDWN(1'b0), .RST(1'b0),
                .CLKOUT0B(), .CLKOUT1(), .CLKOUT1B(), .CLKOUT2(), .CLKOUT2B(), .CLKOUT3(), .CLKOUT3B(), .CLKOUT4(), .CLKOUT5(), .CLKOUT6(), .CLKFBOUTB()
            );
            BUFG u_bufg (.I(clk0), .O(pix_clk));
        end
    endgenerate

    // BTNC and SW come from the 100 MHz oscillator's world (a button and slide switches), not from the pixel clock: each goes through a two-flop synchroniser
    // (ASYNC_REG keeps both flops together and tells Vivado's CDC check the crossing is handled)
    (* ASYNC_REG = "TRUE" *) logic [1:0] btn_sync = 2'b00;
    (* ASYNC_REG = "TRUE" *) logic [1:0] sw_sync0 = 2'b00, sw_sync1 = 2'b00;
    always_ff @(posedge pix_clk) begin
        btn_sync <= {btn_sync[0], ~BTNC};
        sw_sync0 <= SW;
        sw_sync1 <= sw_sync0;
    end

    // reset: held while the MMCM is unlocked or BTNC is pressed, released synchronously
    logic [2:0] rst_sr = '0;
    always_ff @(posedge pix_clk or negedge locked)
        if (!locked) rst_sr <= '0;
        else         rst_sr <= {rst_sr[1:0], btn_sync[1]};
    wire rst_n = rst_sr[2];

    logic hs, vs, de, sof, eol;
    logic [11:0] x, y;
    vtg #(.H_ACT(1280), .H_FP(110), .H_SYNC(40), .H_BP(220), .V_ACT(720), .V_FP(5), .V_SYNC(5), .V_BP(20), .HS_POL(1'b1), .VS_POL(1'b1)) u_vtg (
        .clk(pix_clk), .rst_n(rst_n), .hs(hs), .vs(vs), .de(de), .x(x), .y(y), .sof(sof), .eol(eol));

    logic [7:0] frame = '0;
    always_ff @(posedge pix_clk) if (sof) frame <= frame + 8'd1;

    // the timing generator shows h = 0, v = 0 (an active pixel) while it is held in reset, so de is gated with rst_n: no lit pixels during reset
    logic de_q;
    logic [3:0] r, g, b;
    tpg #(.W(1280), .H(720)) u_tpg (.clk(pix_clk), .de(de & rst_n), .x(x), .y(y), .sel(sw_sync1), .frame(frame), .de_q(de_q), .r(r), .g(g), .b(b));

    // tpg registers the colour (one clock), so hs and vs take one extra register too; then everything leaves the chip from one final register rank
    logic hs_d, vs_d;
    always_ff @(posedge pix_clk) begin
        hs_d <= hs;
        vs_d <= vs;
        VGA_R  <= r;
        VGA_G  <= g;
        VGA_B  <= b;
        VGA_HS <= hs_d;
        VGA_VS <= vs_d;
    end
endmodule

// Part 9 lesson 2 reference solution: a video timing generator.
module vtg #(
    parameter int H_ACT = 640, H_FP = 16, H_SYNC = 96, H_BP = 48,
    parameter int V_ACT = 480, V_FP = 10, V_SYNC = 2,  V_BP = 33,
    parameter bit HS_POL = 1'b0,
    parameter bit VS_POL = 1'b0
) (
    input  logic        clk,
    input  logic        rst_n,
    output logic        hs,
    output logic        vs,
    output logic        de,
    output logic [11:0] x,
    output logic [11:0] y,
    output logic        sof,
    output logic        eol
);
    localparam int H_TOT = H_ACT + H_FP + H_SYNC + H_BP;
    localparam int V_TOT = V_ACT + V_FP + V_SYNC + V_BP;
    logic [11:0] h, v;
    always_ff @(posedge clk) begin
        if (!rst_n) begin
            h <= '0;
            v <= '0;
        end else if (h == H_TOT - 1) begin
            h <= '0;
            v <= (v == V_TOT - 1) ? 12'd0 : v + 12'd1;
        end else begin
            h <= h + 12'd1;
        end
    end
    wire h_in_sync = (h >= H_ACT + H_FP) && (h < H_ACT + H_FP + H_SYNC);
    wire v_in_sync = (v >= V_ACT + V_FP) && (v < V_ACT + V_FP + V_SYNC);
    assign de  = (h < H_ACT) && (v < V_ACT);
    assign hs  = h_in_sync ? HS_POL : ~HS_POL;
    assign vs  = v_in_sync ? VS_POL : ~VS_POL;
    assign x   = h;
    assign y   = v;
    assign sof = de && (h == 0) && (v == 0);
    assign eol = de && (h == H_ACT - 1);
endmodule

"""Acceptance tests of c9_nexys_vga_720p against model.py (hidden from the agent).

The bench treats the clock input as the pixel clock (SIM_DIRECT_CLOCK = 1). One whole frame after the button is released is measured with edge triggers and
timed samples (benchmark/lib/vga_sampler.py), not a Python callback on every clock.
"""

from __future__ import annotations

import cocotb
from benchmark.lib.bench import Board
from benchmark.lib.vga_sampler import edge_clock, now_clock, rgb, sample
from cocotb.triggers import Edge, First, FallingEdge, RisingEdge, Timer
from model import BAR_W, BARS, DESIGN_ID, FRAME_LINES, H_ACT, H_BP, H_SYNC, LINE, STATUS, V_ACT, V_BP, V_SYNC, colour_at

INPUTS = {"BTNC": 1, "SW": 0}


async def settled(dut, n: int = 4):
    """Wait a few clocks past Board.start (all outputs are defined by then)."""
    for _ in range(n):
        await RisingEdge(dut.CLK100MHZ)


@cocotb.test()
async def test_identity_status_and_blank_while_pressed(dut):
    b = Board(dut, dict(INPUTS))
    await b.start()
    assert await b.shell_id() == DESIGN_ID
    await b.expect(STATUS, 1, "STATUS: video clock locked")
    assert int(dut.LED.value) & 1 == 1, "LED[0] must be lit when the video clock is stable"
    for _ in range(40):                                   # BTNC pressed since before the start
        await RisingEdge(dut.CLK100MHZ)
        assert rgb(dut) == 0, f"colour {rgb(dut):03X} while BTNC is pressed"


@cocotb.test(timeout_time=60_000_000, timeout_unit="ns")
async def test_pressing_the_button_blanks_the_picture(dut):
    """Free-running picture first (BTNC low), then BTNC pressed in the middle of a bar: the colours go to zero."""
    b = Board(dut, {"BTNC": 0, "SW": 0})
    await b.start()
    seen = False
    for _ in range(4000):
        r = await First(Edge(dut.VGA_R), Edge(dut.VGA_G), Edge(dut.VGA_B), Timer(80_000, "ns"))
        if rgb(dut) != 0:
            seen = True
            break
    assert seen, "no picture within a line and a half with BTNC low"
    for _ in range(6):
        await RisingEdge(dut.CLK100MHZ)
    assert rgb(dut) != 0, "the bar ended before the test pressed BTNC"
    dut.BTNC.value = 1
    for _ in range(16):
        await RisingEdge(dut.CLK100MHZ)
    for k in range(40):
        await RisingEdge(dut.CLK100MHZ)
        assert rgb(dut) == 0, f"colour {rgb(dut):03X} {k + 16} clocks after BTNC was pressed"
    dut.BTNC.value = 0


@cocotb.test(timeout_time=200_000_000, timeout_unit="ns")
async def test_one_frame_geometry_and_colours(dut):
    b = Board(dut, dict(INPUTS))
    await b.start()
    assert await b.shell_id() == DESIGN_ID
    assert int(dut.VGA_HS.value) == 0 and int(dut.VGA_VS.value) == 0, "sync outputs must idle low"
    dut.BTNC.value = 0                                    # release: the raster runs
    hr0 = await edge_clock(dut.VGA_HS, rising=True)
    hf0 = await edge_clock(dut.VGA_HS, rising=False)
    hr1 = await edge_clock(dut.VGA_HS, rising=True)
    line = hr1 - hr0
    assert line == LINE, f"line period {line} pixel clocks, expected {LINE}"
    assert hf0 - hr0 == H_SYNC, f"hs width {hf0 - hr0}, expected {H_SYNC}"
    v0 = await edge_clock(dut.VGA_VS, rising=True)
    v1 = await edge_clock(dut.VGA_VS, rising=False)
    assert (v1 - v0) == V_SYNC * LINE, f"vs width {(v1 - v0) / LINE} lines, expected {V_SYNC}"
    assert (v1 - hf0) % LINE in range(0, LINE), "vs edge position"
    # picture line 0 starts 20 lines after the vs pulse ends, and its first pixel is 220 clocks after an hs pulse ended
    w0 = v1 + V_BP * LINE
    assert (w0 - hf0 - H_BP) % LINE == 0, f"first picture pixel {(w0 - hf0) % LINE} clocks after an hs pulse ended, expected {H_BP}"
    want: list[tuple[int, int, str]] = []                 # (clock, colour, what)
    want.append((v1 + (V_BP - 1) * LINE + 80, 0, "line 19 after vs (back porch)"))
    want.append((w0 - 1, 0, "pixel before the first picture pixel"))
    for x in (0, 1, 159, 160, 319, 320, 479, 480, 639, 640, 799, 800, 959, 960, 1119, 1120, 1279):
        want.append((w0 + x, colour_at(x, 0), f"line 0, x {x}"))
    want.append((w0 + H_ACT, 0, "first pixel after the picture on line 0"))
    for k in range(8):
        want.append((w0 + 360 * LINE + BAR_W * k + 80, BARS[k], f"line 360, bar {k} centre"))
        want.append((w0 + 360 * LINE + BAR_W * k, BARS[k], f"line 360, bar {k} first pixel"))
        want.append((w0 + 360 * LINE + BAR_W * (k + 1) - 1, BARS[k], f"line 360, bar {k} last pixel"))
    for dy in (719,):
        want.append((w0 + dy * LINE + 80, colour_at(80, dy), f"last picture line {dy}"))
    want.append((w0 + V_ACT * LINE + 80, 0, "line after the picture"))
    want.append((w0 + (V_ACT + 2) * LINE + 700, 0, "front porch line"))
    want.sort()
    got = await sample(dut, [c for c, _, _ in want], ("rgb",))
    bad = [(w[2], f"{g[0]:03X}", f"{w[1]:03X}") for w, g in zip(want, got) if g[0] != w[1]]
    assert not bad, f"{len(bad)} samples differ (what, RTL, expected): {bad[:6]}"
    v2 = await edge_clock(dut.VGA_VS, rising=True)
    assert v2 - v0 == FRAME_LINES * LINE, f"frame period {(v2 - v0) / LINE} lines, expected {FRAME_LINES}"

BARS = [0xFFF, 0xFF0, 0x0FF, 0x0F0, 0xF0F, 0xF00, 0x00F, 0x000]

LINE = H_ACT + H_FP + H_SYNC + H_BP          # 1650 pixel clocks

BAR_W = 160


def colour_at(x: int, y: int) -> int:
    """12-bit colour (R in [11:8]) of picture position (x, y); anything outside the 1280 x 720 area is black."""
    if 0 <= x < H_ACT and 0 <= y < V_ACT:
        return BARS[x // BAR_W]
    return 0
