Envelope generator for a synthesiser voice, behind the test shell

c12_adsr_envelope Course tier course part 12 O Audio Nexys A7-100T

The problem

The envelope generator of a synthesiser voice. When the key goes down the level rises in steps (attack), then falls to a held level (decay to sustain), and when the key is released it falls to zero (release). All steps are straight lines and happen only on sample ticks. A new key press starts again from wherever the level happens to be.

Where it is used. Envelope generators shape the loudness or brightness of every note in hardware and software synthesisers, from analogue modular systems to digital keyboards and plug-ins.

Adapted from a project in the owner's FPGA design course (the course itself is private).

The spec the agent is given

Envelope generator for a synthesiser voice, behind the test shell

I am building a hardware synthesiser voice on the Nexys A7-100T and need an ADSR (attack, decay, sustain, release) envelope that steps once per sample tick, with linear segments. I want to exercise it entirely from the test shell.

  • Inputs: a tick (the sample tick: everything below happens only on a clock where the tick is present; on all other clocks the outputs hold), gate (the key is down), and four 16-bit values that are read on every tick: atk_inc (the level added per tick during the attack), dec_dec (subtracted per tick during the decay), sus_lvl (the sustain level) and rel_dec (subtracted per tick during the release). Outputs: level (unsigned 16 bits) and state (3 bits: 0 idle, 1 attack, 2 decay, 3 sustain, 4 release), both showing the result of the latest tick from the clock after it.
  • After reset: level = 0, state = idle, and the gate is considered to have been low. CPU_RESETN does this and clears the loaded values.
  • On each tick, in this order of priority: 1. If gate is high and it was low at the previous tick: state becomes attack (the level is not changed on this tick, so a re-trigger starts from the present level). 2. Otherwise, if gate is low, it was high at the previous tick, and the state is not idle: state becomes release (level unchanged on this tick). 3. Otherwise by state: attack: if level + atk_inc reaches 65535 or more, the level is 65535 and the state becomes decay; else the level grows by atk_inc. Decay: if the level is at or below sus_lvl, the state becomes sustain (level unchanged); else if level - sus_lvl is at most dec_dec, the level becomes sus_lvl and the state becomes sustain; else the level falls by dec_dec. Sustain and idle: hold. Release: if the level is at most rel_dec, the level becomes 0 and the state idle; else the level falls by rel_dec.
  • The block must close timing at 100 MHz.
  • Over the shell I set the gate and the four values, give a "tick" command that presents the tick for 1 to 16 consecutive clocks, and read the level and the state back. I will run a script of about 900 ticks (full notes, early releases, re-triggers during decay and release, extreme step sizes and sustain levels, with gaps between the ticks) and compare level and state after every tick, and some boundary cases (a level that lands exactly on a limit).
  • The shell runs at 115200 baud on the USB-UART. The design ID is "ADSR".

Test hooks: top module c12_adsr_envelope_top, ports named as in the board's master XDC, and the test shell's CLKS_PER_BIT, TIMEOUT_CYCLES and BUILD_STAMP parameters as top-level parameters. There are no other time constants.

Exactly spec.md. Anything it leaves open, the agent has to ask about.

What the hidden tests check

The requirements in the hidden spec, and how each is shown to hold:

  • REQ-01 level and state after every tick equal the model (shown by simulation)
  • REQ-02 outputs hold on clocks where there is no tick (shown by simulation)
  • REQ-03 timing closes at 100 MHz (shown by report analysis)
The full behaviour rules from hidden/spec.yaml

rules

  • as spec.md, exact; the previous gate is updated on enabled clocks only; the four values are sampled on every tick

tick

  • a write to TICK with N in [4:0] presents the tick for N consecutive clocks (N = 0: nothing); the gate and the values are held in their registers throughout

hold

  • between ticks LEVEL, STATE and SNAP do not change

Settled assumptions

  • the LEDs stay off. nothing is asked of them.

// Part 12 lesson 5 solution: a linear ADSR.
module adsr (
    input  logic        clk,
    input  logic        rst_n,
    input  logic        en,
    input  logic        gate,
    input  logic [15:0] atk_inc,
    input  logic [15:0] dec_dec,
    input  logic [15:0] sus_lvl,
    input  logic [15:0] rel_dec,
    output logic [15:0] level,
    output logic [2:0]  state
);
    logic gate_d;
    logic [16:0] sum;
    always_comb sum = {1'b0, level} + {1'b0, atk_inc};
    always_ff @(posedge clk) begin
        if (!rst_n) begin
            level <= '0; state <= 3'd0; gate_d <= 1'b0;
        end else if (en) begin
            gate_d <= gate;
            if (gate && !gate_d) state <= 3'd1;
            else if (!gate && gate_d && state != 3'd0) state <= 3'd4;
            else case (state)
                3'd1: if (sum >= 17'd65535) begin level <= 16'd65535; state <= 3'd2; end else level <= sum[15:0];
                3'd2: if (level <= sus_lvl) state <= 3'd3;
                      else if (level - sus_lvl <= dec_dec) begin level <= sus_lvl; state <= 3'd3; end
                      else level <= level - dec_dec;
                3'd4: if (level <= rel_dec) begin level <= '0; state <= 3'd0; end else level <= level - rel_dec;
                default: ;
            endcase
        end
    end
endmodule

// c12_adsr_envelope_regs.sv: the shell window of course task c12_adsr_envelope (gate, four values, tick command, level and state).
module c12_adsr_envelope_regs (
    input  logic        clk,
    input  logic        rst,
    output logic [15:0] led,
    input  logic [6:0]  win_addr,
    input  logic        win_wr,
    input  logic        win_rd,
    input  logic [31:0] win_wdata,
    output logic [31:0] win_rdata
);
    logic        gate_r;
    logic [15:0] atk_r, dec_r, sus_r, rel_r, level;
    logic [4:0]  tleft;
    logic [2:0]  state;
    wire         en = (tleft != 5'd0);

    assign led = 16'd0;

    adsr u_core (.clk(clk), .rst_n(!rst), .en(en), .gate(gate_r), .atk_inc(atk_r), .dec_dec(dec_r), .sus_lvl(sus_r), .rel_dec(rel_r),
                 .level(level), .state(state));

    always_ff @(posedge clk) begin
        if (en) tleft <= tleft - 1'b1;
        if (win_wr) begin
            case (win_addr)
                7'h00: gate_r <= win_wdata[0];
                7'h01: atk_r  <= win_wdata[15:0];
                7'h02: dec_r  <= win_wdata[15:0];
                7'h03: sus_r  <= win_wdata[15:0];
                7'h04: rel_r  <= win_wdata[15:0];
                7'h05: tleft  <= win_wdata[4:0];
                default: ;
            endcase
        end
        win_rdata <= 32'd0;
        if (win_rd) begin
            case (win_addr)
                7'h00: win_rdata <= {31'd0, gate_r};
                7'h01: win_rdata <= {16'd0, atk_r};
                7'h02: win_rdata <= {16'd0, dec_r};
                7'h03: win_rdata <= {16'd0, sus_r};
                7'h04: win_rdata <= {16'd0, rel_r};
                7'h06: win_rdata <= {16'd0, level};
                7'h07: win_rdata <= {29'd0, state};
                7'h08: win_rdata <= {13'd0, state, level};
                default: ;
            endcase
        end
        if (rst) begin
            gate_r <= 1'b0; atk_r <= '0; dec_r <= '0; sus_r <= '0; rel_r <= '0; tleft <= '0; win_rdata <= 32'd0;
        end
    end
endmodule

"""Acceptance tests of c12_adsr_envelope against model.py (hidden from the agent)."""

from __future__ import annotations

import cocotb
from benchmark.lib.bench import Board
from model import ATK, DEC, DESIGN_ID, GATE, LEVEL, REL, SNAP, STATE, SUS, TICK, boundary_script, run, script

REGS = (GATE, ATK, DEC, SUS, REL)


async def play(b: Board, sc: list[list[int]], what: str, per_tick_check: bool = True) -> None:
    """Run a script tick by tick (one tick per TICK write), writing only the registers that change, and compare level and state after every tick."""
    want = run(sc)
    cur = [None] * 5
    for k, row in enumerate(sc):
        for reg, v, c in zip(REGS, row, cur):
            if v != c:
                await b.write(reg, v)
        cur = list(row)
        await b.write(TICK, 1)
        snap = await b.read(SNAP)
        got = [snap & 0xFFFF, snap >> 16]
        assert got == want[k], f"{what}: tick {k} (gate/atk/dec/sus/rel {row}): RTL level/state {got}, model {want[k]}"


@cocotb.test()
async def test_identity_and_reset(dut):
    b = Board(dut, {})
    await b.start()
    assert await b.shell_id() == DESIGN_ID
    for off in (GATE, ATK, DEC, SUS, REL, LEVEL, STATE, SNAP):
        await b.expect(off, 0, f"reset value of {off:#x}")


@cocotb.test()
async def test_course_script(dut):
    b = Board(dut, {})
    await b.start()
    await play(b, script(), "script")


@cocotb.test()
async def test_boundaries(dut):
    b = Board(dut, {})
    await b.start()
    await play(b, boundary_script(), "boundaries")


@cocotb.test()
async def test_holds_between_ticks_and_consecutive_tick_clocks(dut):
    b = Board(dut, {})
    await b.start()
    await b.write(ATK, 700)
    await b.write(DEC, 50)
    await b.write(SUS, 3000)
    await b.write(REL, 400)
    await b.write(GATE, 1)
    await b.write(TICK, 1)                       # gate rises: attack, level unchanged
    await b.expect(SNAP, 1 << 16, "after the gate rises")
    await b.cycles(300)                          # no tick: nothing moves, however long we wait
    await b.expect(SNAP, 1 << 16, "no tick, no change")
    await b.write(TICK, 5)                       # five consecutive tick clocks = five attack steps
    await b.expect(LEVEL, 3500, "five consecutive ticks")
    await b.expect(STATE, 1, "still attacking")
    await b.write(TICK, 16)                      # 16 more: 3500 + 11200 = 14700 (attack continues)
    await b.expect(LEVEL, 14700, "sixteen consecutive ticks")
    await b.write(GATE, 0)
    await b.cycles(200)
    await b.expect(SNAP, 14700 | 1 << 16, "the gate alone does nothing without a tick")
    await b.write(TICK, 1)
    await b.expect(SNAP, 14700 | 4 << 16, "release on the first tick after the gate falls")
    await b.reset()
    await b.expect(SNAP, 0, "SNAP after reset")
    await b.expect(ATK, 0, "ATK after reset")

"""Reference model for P12-1 (linear ADSR envelope): the rules of the spec, tick by tick. Standalone: python only."""
import random


def script(seed=12):
    rng = random.Random(seed)
    s = []

    def note(n_on, n_off, atk, dec, sus, rel):
        s.extend([[1, atk, dec, sus, rel]] * n_on)
        s.extend([[0, atk, dec, sus, rel]] * n_off)

    note(60, 80, 1500, 600, 30000, 900)
    note(10, 70, 4000, 1000, 40000, 700)          # early release during the attack
    note(40, 100, 20000, 300, 0, 5000)            # sustain at 0
    note(15, 6, 60000, 65535, 65535, 65535)       # extreme steps
    for _ in range(18):
        note(rng.randrange(1, 25), rng.randrange(1, 25), rng.randrange(1, 9000), rng.randrange(1, 9000), rng.randrange(65536), rng.randrange(1, 9000))
    s.extend([[1, 100, 50, 20000, 400]] * 20)     # slow attack, interrupted by a re-trigger during release
    s.extend([[0, 100, 50, 20000, 400]] * 5)
    s.extend([[1, 100, 50, 20000, 400]] * 30)
    s.extend([[0, 100, 50, 20000, 400]] * 40)
    return s[:900]


def boundary_script():
    """Levels that land exactly on a limit: release at level == rel_dec, decay at level - sus == dec_dec, attack reaching 65535 exactly,
    sustain level raised above the level during the decay, and a re-trigger from the middle of a release."""
    s = [[0, 0, 0, 0, 0]] * 3
    s += [[1, 1000, 50, 20000, 1000]] * 2 + [[0, 1000, 50, 20000, 1000]] * 3       # level 1000, released with rel = 1000 exactly
    s += [[0, 0, 0, 0, 0]] * 2
    s += [[1, 65535, 535, 65000, 100]] * 4 + [[0, 65535, 535, 65000, 100]] * 3     # attack in one step, decay lands on sus with dec = level - sus exactly
    s += [[1, 30000, 100, 65535, 100]] * 3 + [[1, 5535, 100, 65535, 100]] * 2      # 60000 + 5535 = 65535 exactly
    s += [[0, 5535, 100, 65535, 60000]] * 3 + [[0, 5535, 100, 65535, 4000]] * 3
    s += [[1, 100, 3000, 5000, 100]] * 1 + [[1, 65535, 3000, 5000, 100]] * 2        # decay from the top
    s += [[1, 100, 3000, 5000, 100]] * 3 + [[1, 100, 3000, 60000, 100]] * 3         # sustain raised above the falling level
    s += [[0, 100, 3000, 60000, 7000]] * 2 + [[1, 700, 3000, 60000, 7000]] * 3      # re-trigger in the middle of a release
    s += [[0, 700, 3000, 60000, 65535]] * 3
    return s


def run(sc):
    level, state, gate_d, out = 0, 0, 0, []
    for gate, atk, dec, sus, rel in sc:
        if gate and not gate_d:
            state = 1
        elif not gate and gate_d and state != 0:
            state = 4
        elif state == 1:
            if level + atk >= 65535:
                level, state = 65535, 2
            else:
                level += atk
        elif state == 2:
            if level <= sus:
                state = 3
            elif level - sus <= dec:
                level, state = sus, 3
            else:
                level -= dec
        elif state == 4:
            if level <= rel:
                level, state = 0, 0
            else:
                level -= rel
        gate_d = gate
        out.append([level, state])
    return out
