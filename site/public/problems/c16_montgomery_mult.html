Problems / D. Cryptography and security

Montgomery multiplier behind the test shell

c16_montgomery_mult Course tier course part 16 D Cryptography and security Nexys A7-100T

The problem

A multiplier for large numbers that works modulo a third number, using the Montgomery method, which replaces division with shifts and additions. The time from start to done is the same whatever the inputs, so that timing reveals nothing about the numbers, and the block reports how many clocks it took.

Where it is used. Modular multiplication of this kind is the inner loop of RSA and elliptic-curve cryptography. Constant-time behaviour is a standard requirement against timing attacks.

Adapted from a project in the owner's FPGA design course (the course itself is private).

The spec the agent is given

Montgomery multiplier behind the test shell

I want a block for the Nexys A7-100T's FPGA that multiplies two 64-bit numbers modulo a third, in the "Montgomery" way public-key cryptography uses, and I want to exercise it entirely from the test shell.

  • Inputs: a, b and n, each 64 bits, with n odd and a and b smaller than n, loaded over the shell, and a "start" command that requests the product for one clock.
  • Output: r = a x b x 2^-64 mod n, that is, the number r smaller than n for which r x 2^64 leaves the same remainder as a x b when divided by n. A "done" flag says r is ready; "busy" is high between the start and the done. r keeps its value until the next start. A new start will not come while it is busy.
  • The number of clocks from start to done must be exactly the same for every input (zero operands, operands equal to n minus one, and everything in between), and no more than 100. This is a security requirement: the time must not tell an observer anything about the numbers. The block measures this and I can read the number of clocks of the last product.
  • No divide operators and no remainder operators, and no floating-point blocks. CPU_RESETN clears the loaded numbers, busy and done.
  • I will check a few dozen products exactly, with moduli of 64 and of 40 bits, and I will compare the number of clocks of all of them. LED0 shows done and LED1 shows busy. The shell runs at 115200 baud on the USB-UART. The design ID is "MONT".

Test hooks: top module c16_montgomery_mult_top, ports named as in the board's master XDC, and the test shell's CLKS_PER_BIT, TIMEOUT_CYCLES and BUILD_STAMP parameters as top-level parameters. There are no other time constants.

Exactly spec.md. Anything it leaves open, the agent has to ask about.

What the hidden tests check

The requirements in the hidden spec, and how each is shown to hold:

  • REQ-01 r equals the model for every tested product, with 64-bit and 40-bit moduli and the edge operands (0, 1, n-1) (shown by simulation)
  • REQ-02 CLOCKS is the same for every tested product and at most 100 (shown by simulation)
  • REQ-03 BUSY and DONE follow START as described and r holds until the next START (shown by simulation)
  • REQ-04 The design closes timing at 100 MHz with no unconstrained path (shown by report analysis)
The full behaviour rules from hidden/spec.yaml

function

  • r = a * b * 2^-64 mod n with r < n, for odd n < 2^64 and a, b < n (a, b, n may be 40-bit or 64-bit values; n odd).

timing

  • The number of clocks from START to done is the same for every input and at most 100 (the reference takes 66). CLOCKS reports it.
  • No data-dependent early exit; no division or remainder operators.

handshake

  • START clears DONE; BUSY is high from the clock after START until done; DONE and r hold until the next START.

leds

  • LED[0] = DONE, LED[1] = BUSY, the other LEDs are 0.

// c16_montgomery_mult_regs.sv: the shell window of course task c16_montgomery_mult.
module c16_montgomery_mult_regs (
    input  logic        clk,
    input  logic        rst,
    output logic [15:0] led,
    input  logic [6:0]  win_addr,
    input  logic        win_wr,
    input  logic        win_rd,
    input  logic [31:0] win_wdata,
    output logic [31:0] win_rdata
);
    logic [63:0] a_r, b_r, n_r, r_w;
    logic        st, busy, done, run, got, dn;
    logic [7:0]  clk_cnt, clocks;

    assign led = {14'd0, busy, dn};

    montgomery #(.W(64)) u_core (.clk(clk), .rst_n(!rst), .start(st), .a(a_r), .b(b_r), .n(n_r), .busy(busy), .done(done), .r(r_w));

    always_ff @(posedge clk) begin
        st <= 1'b0;
        if (win_wr) begin
            case (win_addr)
                7'd0: a_r[31:0]  <= win_wdata;
                7'd1: a_r[63:32] <= win_wdata;
                7'd2: b_r[31:0]  <= win_wdata;
                7'd3: b_r[63:32] <= win_wdata;
                7'd4: n_r[31:0]  <= win_wdata;
                7'd5: n_r[63:32] <= win_wdata;
                7'd6: begin st <= 1'b1; dn <= 1'b0; end
                default: ;
            endcase
        end
        if (st) begin run <= 1'b1; clk_cnt <= 8'd1; end
        else if (run) clk_cnt <= clk_cnt + 8'd1;
        if (done) begin dn <= 1'b1; run <= 1'b0; clocks <= clk_cnt; end
        win_rdata <= 32'd0;
        if (win_rd) begin
            case (win_addr)
                7'd0: win_rdata <= a_r[31:0];
                7'd1: win_rdata <= a_r[63:32];
                7'd2: win_rdata <= b_r[31:0];
                7'd3: win_rdata <= b_r[63:32];
                7'd4: win_rdata <= n_r[31:0];
                7'd5: win_rdata <= n_r[63:32];
                7'd7: win_rdata <= {30'd0, busy, dn};
                7'd8: win_rdata <= dn ? r_w[31:0] : 32'd0;
                7'd9: win_rdata <= dn ? r_w[63:32] : 32'd0;
                7'd10: win_rdata <= {24'd0, clocks};
                default: ;
            endcase
        end
        if (rst) begin
            a_r <= '0; b_r <= '0; n_r <= '0; st <= 1'b0; run <= 1'b0; dn <= 1'b0; clk_cnt <= '0; clocks <= '0; win_rdata <= 32'd0;
        end
    end
endmodule

// source: solutions/p16l05_montgomery/montgomery.sv (course file, unchanged below this line)
// Part 16 lesson 5 exercise: a bit-serial Montgomery multiplier of parameterised width. For an ODD modulus n < 2^W and operands a, b < n it computes r = a * b * 2^-W mod n.
//   Algorithm (radix 2): S = 0; for i = 0 .. W-1: S = S + a[i] * b; if S is odd, S = S + n; S = S / 2.  After W steps S < 2n; one conditional subtraction gives r = S - n if S >= n else S.
//   start (one clock, only while !busy): take a, b, n. One bit of a per clock: W clocks, then one clock for the final subtraction. busy is high from the clock after start until r is ready; done is high for
//   exactly one clock then, and r keeps its value until the next start.  Latency: counting the edge that sampled start as edge 1, done is high after edge W+2 (edge 1 loads, edges 2..W+1 are the steps,
//   edge W+2 subtracts). It must be the same for every a, b and n: no data-dependent early exit, and the final subtraction is a multiplexer, not a branch in time. rst_n is synchronous, active low,
//   clears busy and done. S needs W+2 bits (S < 2n plus the addends before halving).
module montgomery #(
    parameter int W = 64
) (
    input  logic         clk,
    input  logic         rst_n,
    input  logic         start,
    input  logic [W-1:0] a,
    input  logic [W-1:0] b,
    input  logic [W-1:0] n,
    output logic         busy,
    output logic         done,
    output logic [W-1:0] r
);
    logic [W-1:0]  ar, br, nr;
    logic [W+1:0]  s;
    logic [$clog2(W+2)-1:0] cnt;
    logic          fin;
    logic [W+1:0]  sum, sum2;
    always_comb begin
        sum = s + (ar[0] ? {2'b00, br} : '0);
        sum2 = sum[0] ? sum + {2'b00, nr} : sum;
    end
    always_ff @(posedge clk) begin
        done <= 1'b0;
        if (!rst_n) begin busy <= 1'b0; fin <= 1'b0; end
        else if (!busy) begin
            if (start) begin ar <= a; br <= b; nr <= n; s <= '0; cnt <= '0; busy <= 1'b1; fin <= 1'b0; end
        end else if (!fin) begin
            s <= sum2 >> 1;
            ar <= ar >> 1;
            cnt <= cnt + 1'b1;
            if (cnt == W - 1) fin <= 1'b1;
        end else begin
            r <= (s >= {2'b00, nr}) ? (s - {2'b00, nr}) : s[W-1:0];
            busy <= 1'b0;
            done <= 1'b1;
        end
    end
endmodule

"""Acceptance tests of c16_montgomery_mult against model.py (hidden from the agent)."""

from __future__ import annotations

import cocotb
from benchmark.lib.bench import Board, peek
from model import (A_HI, A_LO, B_HI, B_LO, CLOCKS, DESIGN_ID, N_HI, N_LO, R_HI, R_LO, START, STATUS, bench_cases,
                   mont_mul)

M32 = 0xFFFFFFFF


async def product(b: Board, a: int, bb: int, n: int, what: str) -> int:
    for off, v in ((A_LO, a), (A_HI, a >> 32), (B_LO, bb), (B_HI, bb >> 32), (N_LO, n), (N_HI, n >> 32)):
        await b.write(off, v & M32)
    await b.write(START, 1)
    await b.cycles(110)
    await b.expect(STATUS, 1, f"{what}: DONE and not BUSY")
    r = await b.read(R_LO) | await b.read(R_HI) << 32
    want = mont_mul(a, bb, n)
    assert r == want, f"{what}: a=0x{a:X} b=0x{bb:X} n=0x{n:X}: RTL r=0x{r:X}, model 0x{want:X}"
    clocks = await b.read(CLOCKS)
    assert 1 <= clocks <= 100, f"{what}: {clocks} clocks (must be at most 100)"
    return clocks


@cocotb.test()
async def test_identity_and_reset(dut):
    b = Board(dut, {})
    await b.start()
    assert await b.shell_id() == DESIGN_ID
    for off in (A_LO, N_HI, STATUS, R_LO, R_HI, CLOCKS):
        await b.expect(off, 0, f"reset value of {off}")

@cocotb.test()
async def test_constant_time(dut):
    """The number of clocks is the same for every product, small and large operands, many moduli."""
    b = Board(dut, {})
    await b.start()
    seen = set()
    for k, (a, bb, n) in enumerate(bench_cases()):
        seen.add(await product(b, a, bb, n, f"timing {k}"))
    assert len(seen) == 1, f"the number of clocks depends on the data: {sorted(seen)}"


@cocotb.test()
async def test_registers_and_reset(dut):
    b = Board(dut, {})
    await b.start()
    a, bb, n = bench_cases()[0]
    await product(b, a, bb, n, "first")
    await b.write(A_LO, 0x12345678)
    await b.expect(A_LO, 0x12345678, "A_LO")
    await b.expect(R_LO, mont_mul(a, bb, n) & M32, "r holds until the next START")
    await b.write(R_LO, 0xFFFF)
    await b.write(START, 1)
    await b.cycles(110)
    led = await peek(b.clk, dut.LED)
    assert led == 1, f"LED {led:04X}: only LED0 (DONE) is lit"
    for off in (0x0B, 0x41, 0x7F):
        await b.expect(off, 0, "unmapped")
    await b.reset()
    await b.expect(STATUS, 0, "DONE after reset")
    await b.expect(A_LO, 0, "A after reset")

"""P16-4 model: 64-bit Montgomery products a * b * 2^-64 mod n (standalone: python only)."""
import hashlib
import math
import random
import struct


def mont_mul(a, b, n, w=64):
    return a * b * pow(1 << w, -1, n) % n


def cases():
    rng = random.Random(19)
    out = []
    for t in range(40):
        n = rng.getrandbits(64) | (1 << 63) | 1 if t % 4 else rng.getrandbits(40) | (1 << 39) | 1
        out.append((rng.randrange(n), rng.randrange(n), n))
    n = (1 << 64) - 59                                                            # a 64-bit prime
    out += [(0, 5, n), (1, n - 1, n), (n - 1, n - 1, n), (n - 1, 1, n)]
    return out


def reference_output():
    return {"cases": [{"a": a, "b": b, "n": n, "r": mont_mul(a, b, n), "clocks": 66} for a, b, n in cases()]}


# ---- benchmark wrapper: the shell register map (from spec.yaml) ----
DESIGN_ID = 0x4D4F4E54          # "MONT"
A_LO, A_HI, B_LO, B_HI, N_LO, N_HI, START, STATUS, R_LO, R_HI, CLOCKS = range(11)


def bench_cases():
    """First 14 course products (mixed 64/40-bit moduli), the four edge cases, and a 64-bit prime modulus case or two."""
    c = cases()
    return c[:14] + c[40:44] + [c[20], c[27], c[33]]
