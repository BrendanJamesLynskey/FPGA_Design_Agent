How the problems are made

  1. The request. A short request in plain English, written as a user would ask. It leaves things out on purpose, so the agent has to ask. Every answer is settled in a hidden full spec (ports, clocks, reset, register map, behaviour, requirements), and a stand-in user answers only from that. spec.md, hidden/spec.yaml
  2. The hidden tests. A cocotb bench drives the design through the board's pins, or through the test shell over the serial link, and compares it with the model. The agent never sees it. hidden/acceptance.py
  3. The independent model. A golden model written from the hidden spec alone, never from RTL. The animation on each page runs it. hidden/model.py
  4. The reference design. Hand-written RTL that passes every test and every flow gate. It proves the task can be done on the board; it is not agent output. ref/rtl/
  5. The mutants. Deliberate bugs, each a small edit to the reference. Every one must fail the hidden tests, which shows the tests can tell a right design from a nearly right one. hidden/mutants.yaml
  6. The held-out draw. A seeded draw holds out about a third of each tier. Benchmark v2 holds out one task in every block of three per domain and tier, drawn from the frozen files, so nobody chooses which. More on benchmark v2.

Course-tier tasks are adapted from the owner's FPGA design course (Parts 9 to 16; the course itself is private). Code on these pages is from the repository under its MIT licence.
