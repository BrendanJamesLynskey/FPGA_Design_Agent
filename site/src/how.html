How it works

A staged flow with a gate at the end of each stage. The model proposes; scripts and tools judge. Nothing the model wrote about its own work counts.

A real run, step by step

Stages

Stages 0 to 9 follow the AMD UltraFast methodology (UG949) for implementation. Each stage ends in checks run by code, and a failed check sends the run back to the stage that can fix it.

StageNameWhat it produces
0InterviewA signed-off spec.yaml: ports, clocks, reset, latency, assumptions with reasons, open questions. The user, or a stand-in oracle in evaluations, answers.
1PlanBlock diagram, clocking plan, every clock-domain crossing, resource budget for the xc7a100t.
2RTL, bench, gates V0 to V3SystemVerilog and constraints; a bench compared with a golden model written from the spec alone; the four verification gates below.
3ConstraintsPins and clocks checked against the board's master XDC.
4SynthesisSynthesis reports and gates.
5ImplementationPlace and route, bitstream.
6Timing closureSetup and hold slack at the target clock.
7Power closureVectorless power estimate and its gate.
8DRC closureDesign rule, methodology and clock-domain-crossing reports.
9Board and debugProgram the board, run tests over its USB-UART, capture internal signals with a logic analyser core. Always waits for a human to approve programming.

The gates V0 to V3

Adopted from OpenTitan's development stages, replacing the parts that need a paid simulator. They sit inside stage 2: the stage cannot end until V3 passes and lint is clean.

GateWhat it requires
V0 planA test plan, the blind golden model and the bench modules exist.
V1 test planEvery statement in the spec is traced to a test, an assertion, a cover point or a formal task, and each requirement names how it will be shown to hold (simulation, formal, hardware or analysis).
V2 tests completeDirected and constrained-random tests pass on every seed; checkers are bound and none fires.
V3 coverage closedFunctional bins and cover properties all hit, line and toggle coverage at stated thresholds, several seeds passing, and a mutation score at its threshold.
V-HWStage 9: the board bring-up against the model passes.

Independent tests from the spec alone

In evaluation The agent's own testbench never counts as a pass. A planned second line of defence writes tests from the signed-off spec only, without seeing the RTL, and runs them against the design. It is built and replayed offline on development tasks. Whether it catches escapes on held-out tasks is a separate pre-registered comparison (eval-2), and no result is claimed for it here.

Mutation testing

A bench that passes proves little unless it can fail. Deliberate bugs ("mutants") are injected into the RTL and the bench must kill them. On the hand-built T1 design, {{board.mutants}} mutants were made. The first full run killed {{board.mutation_first_run_pct}}% and {{board.mutation_survivors_first}} survived, both in reset behaviour. A test for reset state was added because of those survivors, and then all {{board.mutants_killed}} of {{board.mutants}} were killed. The first number is the unbiased one.

The knowledge bank

A private bank of Agent Skills the agent loads on demand: generic RTL techniques, AMD-vendor know-how, Artix-7 family and device facts, the Nexys A7 board, and the procedures above. The bank has {{packs.sections}} section ids. Its contents stay private; layers and sizes are public, with hashes, so a scored run can prove which version it read.

The Claude Code arm and the tools

The model runs as headless Claude Code, one call per turn, with every built-in tool switched off. It sees only our MCP server, which gives each role only the tools its stage needs: lint, simulate, mutate, formal, build, gates, search_docs, load_skill, and file tools limited to the role's own directories. Programming the board and bring-up are never exposed to the model; the harness does those after a human approves. The same stage graph also runs with other models, so harness and model can be compared. Development runs on this site used {{dev.model.0}}, Vivado {{board.vivado}}.
