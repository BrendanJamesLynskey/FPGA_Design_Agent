FPGA Design Agent

An agentic FPGA design environment: from a plain-English request to a bitstream proven on the board

Describe a block in plain English. Language-model agents interview you about what you left out, write the spec, a model of it, the tests and the SystemVerilog, then drive the simulators and Vivado {{board.vivado}} to a bitstream and test it on a Digilent Nexys A7-100T. Every stage ends in a check run by code, not by a model, and a failed check sends the work back to the agent that owns it.

What is agentic about it, and what stops it

The agents decide

  • what to ask about a request before anything is written
  • the spec, a model of it, the tests, the RTL and the constraints
  • what to change after a failed check, within that stage's budget
  • which tools to call: simulators, lint, Vivado reports and the knowledge bank

Code stops them

  • a controller in code, not a model, picks the next stage
  • gates read the tools' reports; a model cannot argue past them
  • each agent may read and write only its own files
  • visits per stage and {{agent_graph.run_limits.turns}} turns per run, then the run ends
  • its own tests never decide: hidden tests, checked by mutation testing, do

A person approves

  • the signed-off spec
  • anything that touches the board
  • wiring the instruments, and every merge

What is hard about it

A model that writes a design and its tests can make the same mistake in both, so a passing test proves little. The agent therefore splits the work: one agent writes a model of the spec without seeing the RTL, another writes the tests from the spec and that model, and the result is judged by hidden tests written in advance. Vivado run from a script also does less than a careful engineer would: it drops constraints, misses clock crossings and lets over-broad timing exceptions hide failures. Beyond the flow shows where, and what the environment adds. And the board is where a design meets real pins and real time, so every result the board returns is read by code and can send the work back.

Designed by Brendan Lynskey. The loop, on the bench

This is the agent loop of plan, act, observe and decide, drawn with the parts of the real set-up. The agents plan and write; the design goes through the simulators, Vivado and the board; and each part returns something a program can read, which enters a gate. A pass moves on to the next stage, a failure goes back to the agent that owns it.
