Inspect it

Everything the agent writes is open to inspection. You do not have to read it.

The agent holds the implementation know-how, so that you can spend your attention on the specification and on whether the evidence is thorough enough. Nothing is hidden from you: the RTL, the generated documents, the tool reports, the checkpoints and the run records are all there, and this page says where and how to open them.

Rebuilding it yourself

Each design carries a build.yaml and the flow that builds it is in flow/. A build writes its checkpoints and reports under the design's build/ directory; a design's README.md states the part, the clocks, the build and the run commands, and what was verified.

One command to open the design in Vivado: not yet available. Brief 118 is building python -m flow inspect <design>, which finds the checkpoints and generates a Vivado project with the sources, constraints and simulation sets, and a view for people without Vivado. This page will link its documentation when it lands. Until then, the checkpoint route above works.

What to look at first

You are not meant to audit the RTL line by line. Start from the evidence: the traceability matrix lists each requirement and the checks that cover it, and each cell links to its record. Open the implementation where the evidence leaves you unsure, which is the point of keeping it open. The worked example shows how that looked for one design.
