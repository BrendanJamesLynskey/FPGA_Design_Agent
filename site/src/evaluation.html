How it is evaluated

A held-out evaluation, written down and committed before any scored run. The agent at tag eval-1 is frozen while it runs. The full text is the pre-registration. eval-1 was stopped before analysis (the dated note); the next evaluation, the baseline, uses the same method on a larger benchmark.

The idea

Tasks used to improve an agent cannot also measure it. So {{eval.tasks}} tasks were set aside by a fixed random seed before any agent run, and the agent never sees them: not their text, not their tests, not their reference designs. Everything on the results page labelled "development" comes from the other tasks.

Steps

  1. Held-out split. {{eval.tasks}} tasks, drawn by seed from two sets (the first benchmark and the course tier). The files are frozen with checksums, and a check must show zero mismatches before the first run.
  2. A hidden grader. Each task has hidden tests written before any agent run, against an independent golden model, run on Icarus. No language model grades anything. A run passes only if every hidden test passes.
  3. The grader is itself checked. The reference design passes, and {{eval.mutants_per_task}} deliberately broken versions per task ("mutants") must fail.
  4. Three runs per task. {{eval.runs}} runs in all, each from a clean checkout and a fresh directory, in an order fixed in advance by a seed so that no task is run easiest first.
  5. The agent sees only the task text and the board pack. Questions go to an oracle ({{eval.oracle}}) that answers from the hidden spec with a quote check; every question and answer is logged.
  6. Errors are "not run". A run that ends for an infrastructure reason is reported as not run, with evidence. It is never repeated into the result.
  7. Tasks, not runs, are the unit. The headline is pass@1 with a 95% interval from a bootstrap over tasks ({{eval.resamples}} resamples). A Wilson interval on the runs is shown beside it and labelled as ignoring the clustering of runs within tasks.
  8. Escapes. The share of runs where every check the agent ran passed and the hidden tests still failed, split by the check that should have caught it.
  9. No changes during the evaluation. A bug found on the way is written down, fixed afterwards and measured as eval-2 on the same tasks.

How wide will the interval be?

Planned in advance from the {{eval.dev_runs_for_width}} development runs on {{eval.dev_tasks_for_width}} tasks: an expected 95% half-width for pass@1 of about ±{{eval.planned_halfwidth}} points. The width comes from tasks differing in difficulty, so more runs per task barely narrow it. On {{eval.tasks}} tasks a pass rate is known to about that much, and precision for comparisons comes from pairing by task, later.

Limitations, stated up front

  • {{eval.tasks}} tasks give wide intervals.
  • One board, one model, one harness.
  • An LLM oracle stands in for the user during the interview.
  • Icarus is the scoring simulator.
  • Constants (gate floors, caps, timeouts) were all chosen on development tasks.

Held-out task text stays private until the results are published. Nothing on this site comes from a held-out task; a leak scan of the published pages against the private held-out material is part of the release.
