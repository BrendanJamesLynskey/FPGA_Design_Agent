Requirements in full

M141-S-TIMING: No DDR2 timing rule is ever violated on the command stream

For every request sequence and both policies, the command bus never breaks tRCD, tRP and tRPA, tRAS, tRC, tRRD, tFAW, tWR, tWTR, tRTP, tRFC, the read-to-write and write-to-read spacings, the one-command state rules (ACTIVATE to a closed bank, a column command to an open bank, REFRESH with every bank closed), nor the data-bus rules (no overlap, one idle clock between a read and a write burst).

  • simulation test: pass Both policies, six traffic patterns, two timing profiles and three address maps against the behavioural DDR2 model: zero violations, every request served once, order kept, refresh gap within 9 x tREFI, longest wait within the bound: 19 test(s) passed in the recorded run evidence
  • simulation test: pass Sixteen seeded faults in a copy of the RTL (a timing constant short, the dependency check removed, refresh disabled, a wrong bank on the command bus, a wrong row opened) are each caught by the bench: 16 test(s) passed in the recorded run evidence
  • formal: pass SymbiYosys proofs of the timing rules and request order (k-induction with helper invariants, depth 3, at the real data sheet constants and at small ones, both policies), the refresh debt (property-directed reachability), covers, and one mutant per rule that a named assertion catches: 23 test(s) passed in the recorded run evidence

M141-S-ORDER: A request never overtakes an older request to the same burst address when either is a write

Read-after-write, write-after-write and write-after-read order to one burst address is kept; other requests complete in any order.

  • simulation test: pass Sixteen seeded faults in a copy of the RTL (a timing constant short, the dependency check removed, refresh disabled, a wrong bank on the command bus, a wrong row opened) are each caught by the bench: 16 test(s) passed in the recorded run evidence

M141-S-REFRESH: Refresh is never starved

At most REF_POST + 2 refreshes are outstanding at any time, and the gap between two REFRESH commands never exceeds 9 x tREFI (JEDEC's limit with eight postponed); a REFRESH is issued only when one is due.

  • simulation test: pass Both policies, six traffic patterns, two timing profiles and three address maps against the behavioural DDR2 model: zero violations, every request served once, order kept, refresh gap within 9 x tREFI, longest wait within the bound: 19 test(s) passed in the recorded run evidence
  • simulation test: pass Sixteen seeded faults in a copy of the RTL (a timing constant short, the dependency check removed, refresh disabled, a wrong bank on the command bus, a wrong row opened) are each caught by the bench: 16 test(s) passed in the recorded run evidence
  • formal: pass SymbiYosys proofs of the timing rules and request order (k-induction with helper invariants, depth 3, at the real data sheet constants and at small ones, both policies), the refresh debt (property-directed reachability), covers, and one mutant per rule that a named assertion catches: 23 test(s) passed in the recorded run evidence

M141-F-SERVICE: Every request is served exactly once with its own bank, row, column and direction

Each accepted request gets one column command carrying its tag, the bank and column of its address, in the direction asked, on a bank whose open row is the request's row.

  • simulation test: pass Both policies, six traffic patterns, two timing profiles and three address maps against the behavioural DDR2 model: zero violations, every request served once, order kept, refresh gap within 9 x tREFI, longest wait within the bound: 19 test(s) passed in the recorded run evidence
  • simulation test: pass Sixteen seeded faults in a copy of the RTL (a timing constant short, the dependency check removed, refresh disabled, a wrong bank on the command bus, a wrong row opened) are each caught by the bench: 16 test(s) passed in the recorded run evidence

M141-F-BOUND: Every request is served within a bounded wait

A request waits at most AGE_LIM + QD x R_MAX + the refresh cost clocks (verif/formal/run_formal.py:bound), under both policies. Proved at small parameters by bounded model check; measured at the real parameters.

  • simulation test: pass Both policies, six traffic patterns, two timing profiles and three address maps against the behavioural DDR2 model: zero violations, every request served once, order kept, refresh gap within 9 x tREFI, longest wait within the bound: 19 test(s) passed in the recorded run evidence
  • formal: bounded Bounded response of a tracked request, bounded model check to the proved bound plus six clocks at small parameters (a check from reset, not a proof for all time): by_name.live_bmc_tiny_p0.verdict = PASS evidence

M141-F-LINT: The RTL is Verilator -Wall clean and follows the HDL standard's structural rules

Verilator 5 --lint-only -Wall reports nothing on ddr2_sched and ddr2_addrmap; synchronous reset only, no initial blocks, no latches, no derived clocks.

  • simulation test: pass Verilator 5 -Wall clean on both modules: 2 test(s) passed in the recorded run evidence

M141-P-LAT: Median read latency of the latency-first policy on light random reads

Random reads at light load (one request every 40 clocks on average) find a precharged bank, so a read pays ACTIVATE, tRCD and the read latency and nothing else. The bound is a regression bound from the recorded run, not a target. Bound: median read latency at most 13 clocks; condition: POLICY 0, random reads, mean gap 40 clocks, nexys_650 profile (tCK 3077 ps, CL 5), simulation, 3000 reads.

  • simulation measurement: pass Median read latency, latency-first policy, light random reads: measured 12 clocks; bound at most 13 clocks evidence

M141-P-LATTAIL: Tail of the read latency of the latency-first policy on light random reads

The 99.9th percentile of the read latency at light load stays within a refresh's worth of the median (a refresh in progress when a read arrives is the tail). Regression bound, not a target. Bound: 99.9th percentile read latency at most 60 clocks; condition: POLICY 0, random reads, mean gap 40 clocks, REF_POST 4, nexys_650 profile, simulation, 3000 reads.

  • simulation measurement: pass 99.9th percentile read latency, latency-first policy, light random reads: measured 53 clocks; bound at most 60 clocks evidence

M141-P-WINDOW: No read inside a refresh-deferral window waits for a refresh

While ref_defer is high and the postponement allowance is not used up, refreshes that fall due are postponed, so the reads accepted in the window see no tRFC wait (the cost moves to reads after the window). Regression bound, not a target. Bound: maximum read latency inside the window at most 40 clocks; condition: POLICY 0, REF_POST 4, ref_defer high for 5000 of every 12000 clocks, random reads at light load, nexys_650 profile, simulation, 6000 reads.

  • simulation measurement: pass Maximum read latency inside a refresh-deferral window, latency-first, REF_POST 4: measured 28 clocks; bound at most 40 clocks evidence

M141-P-BW: Streaming read bandwidth of the bandwidth-first policy

A sequential read stream keeps the data bus busy: utilisation (data clocks over elapsed clocks) at least 0.95 with the page-interleaved map. Regression bound, not a target. Bound: data-bus utilisation at least 0.95 fraction; condition: POLICY 1, sequential reads, map 0, QD 8, nexys_650 profile, simulation, 4000 reads.

  • simulation measurement: pass Data-bus utilisation, bandwidth-first policy, sequential reads, page-interleaved map: measured 0.9798 fraction; bound at least 0.95 fraction evidence
