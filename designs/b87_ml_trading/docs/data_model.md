# The synthetic order flow, features and label

Everything is generated by `model/lobsim.py` from fixed seeds. No exchange, no market data, no real instrument.

## Microstructure model

One instrument; prices are integer ticks (one tick = 0.01 in the 58A Bench Feed format). The book holds
`levels` = 5 price levels a side, each a queue size in lots; the best bid and ask start one tick apart at 10,000 and
10,001.

A hidden value `v` (ticks) moves by a Gaussian step of `sigma_v` = 0.06 ticks each event, plus a jump of
+/- `jump_ticks` = 3 with probability `p_jump` = 0.002. Nobody sees `v`; it tilts the order flow through the weight
`w = 1 / (1 + exp(-informed * (v - mid)))`, `informed` = 1.6.

Each event is one of:

| Event | Probability | Side | Effect |
|---|---|---|---|
| market order | `p_market` = 0.12 | buy with probability `w` | takes 1-`max_market` (8) lots from the best level; a level that empties is removed, the best price moves one tick away, and a fresh level (geometric size, mean `mean_queue` = 15) appears at the back; the remainder goes on into the next level |
| limit order | `p_add` = 0.48 | bid with probability `w` | 1-`max_add` (6) lots; if the spread is wider than one tick, lands inside it with probability `p_inside` = 0.9 (a new best level), otherwise joins level `min(G - 1, 4)` with G geometric (p = 0.45) |
| cancel | the rest (0.40) | the bid with probability `1 - w` | removes up to `max_add` lots from a level chosen in proportion to its size; an emptied best level moves the price away |

So buying pressure shows up as more buy market orders, more bids added and more asks cancelled. The mid-price follows
`v` only through the queues emptying, which is what the features can see.

## Features (what the fabric computes)

After each event, from the best level of each side and short histories (`FeatureState`, mirrored bit for bit by
`rtl/ml_feat.sv`):

| # | Feature | Bits | Definition |
|---|---|---|---|
| f0 | bid size | 8 | best-bid queue in lots, saturated at 255 (0 if the side is empty) |
| f1 | ask size | 8 | the same for the ask |
| f2 | spread | 4 | ask - bid in ticks, saturated at 15 (15 if a side is empty) |
| f3 | imbalance bucket | 3 | the number of true comparisons among 4b > a, 2b > a, 3b > 2a, b > a, 2b > 3a, b > 2a, b > 4a (b, a = f0, f1); seven shift-and-add compares, no divider |
| f4 | trade signs | 5 | sum of the last 8 trade signs (+1 buyer, -1 seller) + 8 |
| f5 | order-flow imbalance | 8 | sum of the last 16 per-event OFI terms (Cont, Kukanov and Stoikov 2014; each term clipped to +/-127), clipped to +/-127, + 128 |
| f6 | last mid move | 2 | 0 down, 2 up, 1 before the first move |

## Label and splits

- Label: the sign of the mid-price change from the event to 40 events later (0 down, 1 unchanged, 2 up).
- Sessions of 10,000 events; the first 50 events are dropped (the history windows fill) and the last 40 have no label.
- Train: seeds 1001-1020 (198,200 samples); validation: 2001-2002; test: 3001-3010 (99,100 samples). Each session is
  an independent random stream, so no label window crosses a split.
- The test intervals are over the 10 sessions (events within a session are correlated).

## Limits

- One instrument, one regime, stationary parameters; the generator was tuned (spread mostly one tick, the three
  classes roughly balanced) on the validation split only, before any test-split run.
- It is a model with a planted signal: an accuracy here says how well each arm recovers that signal under its
  hardware constraints. It says nothing about a real market.
