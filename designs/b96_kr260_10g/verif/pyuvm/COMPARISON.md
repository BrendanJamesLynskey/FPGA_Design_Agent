# pyuvm or SystemVerilog UVM for this project: what we measured (brief 123)

The same job done twice: the PCS and MAC of `designs/b96_kr260_10g` verified by brief 112's SystemVerilog UVM 1.2 bench in Vivado 2026.1 xsim (`../uvm/`), and by this pyuvm 5.0.0 bench on cocotb 2.0.1 and Icarus 12 (this folder). Same scope, same thirteen tests, same 17 seeded bugs, same coverage bins, same five scoreboard checks. Every number below comes from a file in `results/123_pyuvm_pcs_mac/` (112's own figures from `results/112_uvm_pcs_mac/` and its report), and each row says which. Where a row is an opinion or one author's experience it says so.

## The short answer

- **On this block the two benches reached the same verification result.** All 42 runs pass on the clean RTL in both; the same bugs are killed by the same tests (16 of 17 with all tests, 14 of 17 before the two patterns 112 added after seeing M13 and M15 survive; the 17th, M03, is equivalent and survives in both); the same 213 coverage bins are hit (plus 4 helper bins in pyuvm, 217 of 217).
- **pyuvm is cheaper to run and to wire into CI, and costs more per simulated clock.** Build 0.1 s against 57.9 s; a short test 3 s against 8.5 s; but a long one 31 s against 10 s, because the marginal cost is 2.7 ms a clock against 0.29 ms. It runs wherever cocotb and Icarus run (CI already does); SV UVM needs a Vivado install and cannot run in CI.
- **SV UVM has what pyuvm lacks**, and the lack is measurable: a constraint solver (cocotb-coverage's takes 26 s for one randomisation of a four-field frame item with one cross-field constraint), bound assertions and covergroups the tools understand, the full UVM feature set (arbitration, `p_sequencer`, run-time phases, events, pools, resource DB), and it is the language the industry and interviews use.
- **Recommendation:** pyuvm for agent-written and quick block benches that are already cocotb benches and want agents, sequences and a scoreboard; SV UVM kept for the flagship bench, for anything that needs the solver, bound SVAs or tool coverage, and for interviews. Details and the evidence for each half at the end.

## What this does not show

- **Authorship by an agent.** See row 21: the pyuvm bench was a translation by someone who had the SystemVerilog one open. Time to write, errors per attempt and first-try pass rates were not measured.
- **Blind mutation scores for either bench.** Both benches' tests were written knowing the mutant list; row 8 reproduces the one hindsight step 112 recorded, no more.
- **A different block.** One block, one clock, no GT, no rate matcher. Bigger designs with two clocks, AXI or many interfaces may change the code-size and speed rows (the Python models cost more per clock the more they do).
- **Verilator.** Not installed here, not tried. It would give pyuvm line and toggle coverage and real concurrent assertions on a plain-Verilog top, and a faster simulator core, but cocotb's per-clock Python cost stays.
- **UVM features not exercised**: the factory's overrides, the register layer, callbacks (present in pyuvm 5.0.0, untried), the run-time phases and sequence arbitration (absent).
- **Interoperability.** Both benches share one reading of clause 49; neither closes that.

## Recommendation

1. **Use pyuvm on cocotb for the bench an agent writes, and for quick block benches.** Evidence: the measured results match SV UVM's on this block (rows 7 to 10); no licence, no 58 s build, runs in CI (row 19); the flow already runs cocotb and takes cocotb-coverage exports (row 21); a mutant sweep is 7 minutes against a computed 23 (row 6). Keep the structure (agents, sequences, scoreboard, coverage) when many tests share it, as here; a plain cocotb test is still the right size for one directed check.
2. **Do not use it where Python's per-clock cost decides.** 2.73 ms a clock is 10 times xsim's marginal cost (row 4); a soak of millions of clocks, or a model that does real work each clock, belongs in a compiled bench.
3. **Keep SV UVM for the flagship bench (112) and for what pyuvm cannot do**: solver-driven constrained random (row 15), bound SVAs with sequences (row 14), tool-merged coverage and code coverage with a tier that allows it (rows 12, 13), arbitration, `p_sequencer`, events and the register layer with real tools (row 16). 112 stays as the cross-check: two independent benches that agree are worth more than one.
4. **Interviews: SV UVM first.** The pyuvm bench is a good second story (same concepts, measured comparison); it does not replace the first (row 23).
5. **Cheap next steps, not done here:** install Verilator into `~/.local` and run this bench on it for line and toggle coverage and real assertions (the top is plain Verilog); wire the bench's coverage export to `$FDA_COV_OUT` so the agent's gates see it; do not port other benches wholesale until a second block has been done, because one block does not make a trend.

## For the verification course

*(A short section the course of brief 121 can link to: https://github.com/BrendanJamesLynskey/FPGA_Design_Agent/blob/main/designs/b96_kr260_10g/verif/pyuvm/COMPARISON.md#for-the-verification-course)*

**The same UVM bench in two languages.** UVM is a method, not a language: agents with a driver, monitor and sequencer, sequences that make items, a scoreboard that compares monitors with a reference model, coverage that says what the tests reached, and seeded bugs that say whether the bench can see failures. `designs/b96_kr260_10g` has both versions for the same 10G PCS and MAC: SystemVerilog UVM 1.2 in Vivado's xsim, and pyuvm (UVM classes in Python) on cocotb and Icarus. Read them side by side:

- *Agent*: `env/pcs_mac_agents.sv` against `pcs_mac_pyuvm/agents.py`. The driver is the same loop: get an item, drive the pins, wait for the DUT's ready, `item_done`. Where SV uses a clocking block to sample before the edge, cocotb reads right after `await RisingEdge(clk)` and gets the same values.
- *Scoreboard*: five checks against reference models, paired by clock. The reference model is plain code in both; only the language differs.
- *Coverage*: SV covergroups against cocotb-coverage's decorators. Same bins, same merge across seeds.
- *Mutation testing*: 17 deliberate bugs in a copy of the RTL; a bench that kills 16 of them (the 17th cannot be detected) is shown to see failures. 14 of 17 before two extra tests were written after two bugs survived: that is how a coverage hole becomes a test.
- *What differs*: SV has a constraint solver and bound assertions; pyuvm runs anywhere Python does, builds in a tenth of a second, and is about ten times slower per simulated clock. The table above has the numbers.

Run either: `designs/b96_kr260_10g/verif/uvm/scripts/run_regress.sh --quick` (needs Vivado) or `designs/b96_kr260_10g/verif/pyuvm/scripts/run_regress.py --quick` (needs `pip install pyuvm cocotb-coverage`).
