# VHDL tool measurements: NVC against GHDL under cocotb, VHDL coverage, PSL (brief 156, review item F11)

**Result.** NVC 1.23.1 is installed (without root, from the official release `.deb`) and runs the same cocotb 2.0.1 benches as GHDL.
On six VHDL designs (the four brief 55 task translations, an AXI4-Lite register file, and a 16-tap FIR written for this brief) the three
simulators agree on everything that was checked: every bench passes on all of them, a hand-written fault in each design is caught by every
one of them, and the per-clock output traces are identical (one digest per design across 4 simulator flows x 3 repeats, 12 099 to 85 717
clocks, and also when the trace starts in reset). **No behavioural difference was found.** The difference is speed, and only where the
simulator does the work: with cocotb in the loop the simulator is not the bottleneck (five of six designs run within 15 % of each other,
the exception is the FIR at 3.6 times); a pure-VHDL testbench of the FIR ran **95 times faster on NVC than on GHDL 4.1.0 mcode**
(2.5 s against 237 s for 300 000 clocks, same checksum) and 54 times faster than on GHDL 7.0.0-dev LLVM. Code coverage exists in both: NVC
gives statement, branch, toggle and expression bins and merges databases; **GHDL 4.1.0 (the CI pin) also gives statement coverage
(`--coverage`), contrary to `docs/vhdl.md` before this brief**, but one hit flag per line, and its `ghdl coverage` command crashes when
given two files. PSL runs in GHDL, NVC and SymbiYosys, with different subsets; the two properties of the SystemVerilog twin, and two more,
are proved on the VHDL translation and refuted on a fault by the newer GHDL plugin in under 5 s, and not decided in 60 s by the older one.

## Nulls first

- **Null A (NVC is not measurably different from GHDL under cocotb): not met for the FIR (3.6 times with cocotb, 95 times without),
  met for the register-window designs** (all within 15 %; the time is Python and the cocotb scheduler: 0.4 s start-up on every flow, and
  15.5 to 17.9 s for the 40 000 operations of the FIFO bench whichever simulator).
- **Null B (a behavioural difference between simulators): not found.** Same pass/fail, same trace digest, same assertion values on the
  faults, same 'U' in the first clock of reset, 6 designs.
- **Null C (GHDL has no coverage here): wrong.** GHDL 4.1.0 mcode writes statement coverage. GHDL 7.0.0-dev LLVM has none (gcov flags and
  `--coverage` are rejected), and the gcov route the brief named is not available in either build.
- **Null D (PSL gives one answer in every tool): wrong.** Of 31 constructs, 14 are accepted by some tools and rejected by others (3 more by
  none), and NVC disagrees with GHDL and both formal flows on the verdict of two properties (below).
- **Not shown:** that NVC is faster on large RTL designs in general (one pure-VHDL design, numeric_std-heavy); that NVC runs OSVVM, UVVM or
  VUnit (not tried); behaviour on mixed-language designs (neither tool reads Verilog).

### 2. Simulator comparison under cocotb

Six designs, each with a cocotb bench in [benches/](benches/) written for this brief. The brief 55 benchmark benches go through the SystemVerilog
test shell, which neither GHDL nor NVC reads, so these benches drive the **inner VHDL entity's window bus** directly and check it with the dev
task's own golden model (`benchmark/tasks/<task>/hidden/model.py`, a development task, not held-out material): `sync_fifo_regs` (random
push, pop, flags, threshold; exact against the model), `gray_stepper` (registers, button steps, the auto-stepper by replaying the STEPS
delta), `debounce_bank` (bouncing switches settling, edges, counters), `elevator_fsm` (one call at a time, floor, state, moves), `axil_regs`
(AXI4-Lite with random strobes and back-pressure; a Python model) and `fir16` (below). Each bench also writes a per-clock trace digest of the
outputs.

`fir16` is the larger design (about 250 lines: a package with record and array types, `generate` loops, a 4-level registered adder tree, a
saturating output, a coefficient write port; [rtl/](rtl/)). Its bench checks every output against an integer golden model, the latency of one
isolated sample (6 edges after the sampling edge), a coefficient rewrite and the saturation flag.

Versions: `ghdl-4.1.0-mcode` = GHDL 4.1.0 (Ubuntu 4.1.0+dfsg-0ubuntu2.1) [Dunoon edition] (static elaboration, mcode JIT code generator); `ghdl-7.0.0dev-llvm` = GHDL 7.0.0-dev (6.0.0.r729.g8e642a9a5.dirty) [Dunoon edition] (llvm 21.1.8 code generator); `nvc-1.23.1-jit` = nvc 1.23.1 (1.23.1.r0.gfab54a9) (Using LLVM 18.1.3); `nvc-1.23.1-aot` = nvc 1.23.1 (1.23.1.r0.gfab54a9) (Using LLVM 18.1.3)

### 3. VHDL code coverage

NVC: `nvc -e --cover=statement,branch,toggle,expression,fsm-state --cover-file=...`, run, then `nvc --cover-merge -o merged.ncdb a.ncdb b.ncdb`,
`nvc --cover-export --format=cobertura` (per-line hits, one file per design in [coverage/](coverage/)) and `--format=xml` (bins by kind), and
`nvc --cover-report --per-file -o dir` (HTML, not committed). **Each run needs its own copy of the empty database that `-e` writes**
(a second `-r` otherwise stops with "failed to open coverage database"). Statement, branch, toggle and expression bins have counts.
`fsm-state` found no FSM in any of the six designs (none uses an enumeration-typed state signal; `elevator_fsm` keeps its state in a 2-bit
`unsigned`).

GHDL 4.1.0 mcode: `ghdl -a --coverage`, then `ghdl -r --coverage ...` (the option goes before the top unit; after it GHDL says "unknown run
option"); it writes `coverage-<timestamp>.json` with `'mode': 'stmt'` and one hit flag (0 or 1) per source line, and `ghdl coverage
--format=lcov|gcov|summary file.json` formats it. Per-line coverage works under cocotb (VPI). What did not work: `ghdl coverage` raised
`CONSTRAINT_ERROR ghdlcov.adb:325` for **two input files** (even the same file twice), so merging two runs needs a script
([run_coverage.py](run_coverage.py) `ghdl_merge`: union of the hit flags; its result is accepted by `ghdl coverage`); `--coverage` on a
design containing a PSL `cover` directive stops GHDL at run time with `Covered_Flag` (an internal assertion); `ghdl coverage` given a
`--psl-report` JSON stops with a parse error (that file is PSL cover and assert counts, not code coverage). GHDL 7.0.0-dev LLVM rejects `--coverage`, `-fprofile-arcs` and `-ftest-coverage`
([ghdl_coverage_probe.txt](ghdl_coverage_probe.txt)): gcov instrumentation is not present in either build.

violates, or a cover. A simulator is scored on whether the text is accepted and on the verdict (a testbench violates every `false` probe); SymbiYosys

What a user could guess wrong, from the table:

- **GHDL's simulators have no PSL built-in functions** (`prev`, `rose`, `fell`, `stable`, `onehot`, `onehot0`): 7.0.0-dev says "PSL builtin
  function not supported in simulation", 4.1.0 mcode stops with a compiler "bug occurred" box naming the construct. The formal tools accept
  all of them, and NVC accepts `prev`, `stable`, `onehot` and `onehot0` but stops on `rose` and `fell`. Portable form: a monitor register
  (`x_q <= x`) and a plain Boolean property, as in the Gray stepper below.
- **GHDL 4.1.0 ignored the `-- psl` properties without complaint when `-fpsl` was given at analysis only.** The same design stops with a
  compiler error under `-fpsl` on the run command (a PSL built-in), and ran, passed its bench and printed nothing without it. `-fpsl` must
  be on the elaboration and run commands too (the PSL probe and the Gray run do).
- **Where the PSL goes.** `default clock` in the declarative part of the architecture is accepted by all five tools (NVC accepts it only
  there; GHDL accepts it in the statement part too). Named `sequence` and `property` declarations: the GHDL simulators accept them in the
  statement part, the GHDL plugin stops with a "bug occurred" box on them, NVC rejects them, and no tool accepts them in the declarative part. NVC also rejected
  `assume always`, `restrict`, `fairness` and an `assert ... report ... severity` clause as written.
- **NVC reports a failure on two properties that GHDL and both formal flows pass** (`until`, `next_a[1 to 1]`): the same text, checked by
  reasoning and by BMC to hold. Cause not investigated (the failure is reported one delta after the clock edge, so a sampling difference is
  possible).
- **Strong operators.** `eventually!` and `next!` are not accepted by every tool (`next!` only by NVC); `eventually!` passed in all five when
  the stimulus ended with the obligation met (before the stimulus was changed to end low, GHDL and NVC reported it as failed at the end of the trace).
- **The plugin crashes (a "bug occurred" box, `ASSERTION_ERROR`) on `{req; gnt} |-> {gnt}` (overlapping suffix implication with a
  two-cycle antecedent) in both versions**, while all three simulators accept it.
- Cover directives: simulation prints nothing for them, the formal `cover` task reports reached or unreached (and says which), so cover is
  scored from formal only.
- `within`, `fairness` and `restrict` (GHDL mcode) were rejected by most tools as written; the messages are in the table above.

**The Gray stepper, the same properties in two languages.** The SystemVerilog twin (`benchmark/tasks/t1_gray_stepper/ref/rtl/gray_stepper.sv`)
has `ifdef FORMAL` assertions: REQ-01 (a step that is not a BIN write changes exactly one bit of the Gray register) and the invariant
`rst || gray == bin ^ (bin >> 1)`. [psl/rtl/gray_stepper.vhd](psl/rtl/gray_stepper.vhd) states both in PSL, adds a reset-values property, a
STEPS-counts property and two covers, and an assumption that the first cycle is a reset ([psl/sv/gray_fv.sv](psl/sv/gray_fv.sv) says the same
for the twin). Both time constants are shrunk to 2 so a step is reachable within the 20-clock bound. Each language was run clean and with one
fault (the up-count adds 2: breaks REQ-01).

## Recommendation

1. **Simulator for native VHDL: NVC 1.23.1 by default, GHDL kept as the front end.** Evidence: identical behaviour on 6 designs, the same
   faults caught, faster (3.6 times with cocotb on the FIR, 95 times without), a real coverage tool with merge, an installable pinned release.
   GHDL stays for: lint and synthesis (GHDL's own analysis and the Yosys plugin: NVC feeds neither), formal (the plugin), the netlist route
   under Icarus/Verilator (unchanged), and as the CI-pinned fallback (the CI image has GHDL 4.1.0 from apt). Before NVC becomes the default,
   the flow needs: a pin for CI and the image (the release `.deb` and its sha256 above), `SIM=nvc` in `flow.cocotb_run`, and a check that
   VUnit and OSVVM run on it (not measured here). Nothing is wired by this brief.
2. **Coverage as evidence in trace_v1 (a method and floors, not wired).** Method: elaborate with `--cover=statement,branch,toggle,expression`,
   one database per seed, `--cover-merge` (union), export Cobertura (per-line hits) and NVC's XML (bins per kind), and record the tool and
   version, the command, the database's SHA-256, hits/total per kind and the list of unhit lines, as the Verilator `coverage.dat` summary does
   for SystemVerilog (`flow/verif_gates.py` `merge_code_cov`). Floors, proposed from these six benches (short workloads, not designed for
   V3): statement 90 % (the existing `line_pct` floor; the six measure 93 to 100 %), branch 85 % (new; 90 to 100 % except `debounce_bank` at
   89.6 %), toggle: the existing 75 % would fail three of the six (49 %, 58 %, 73 %: the 32-bit window data buses), so a VHDL toggle floor of
   50 % with an NVC exclude file for unused window bits, or waivers with reasons as for SystemVerilog. Statement bins only is the fallback
   from GHDL's file (a hit flag per line, no merge command that works). The numbers are in the NVC bins table above.
3. **PSL.** Write properties for both simulators in plain Boolean form with monitor registers (no PSL built-ins), `default clock` in the
   declarative part, `-- psl` comments or direct statements, and avoid `assume`, `restrict`, `fairness`, `sequence`/`property` declarations
   and `assert ... report` where NVC must read them; run formal with the OSS CAD Suite plugin (GHDL 7.0.0-dev), not the Ubuntu 4.1.0 one,
   and say which in the result. SystemVerilog twins prove the same REQ properties in the same four seconds, so a VHDL design can carry the
   same property list.
4. **What the agent's VHDL path does next:** (a) a window-bus bench for native VHDL (the shell is SystemVerilog, so the benches here drive
   the inner entity; the flow needs one adapter that drives the shell's protocol onto the entity ports, so the agent's hidden-test route is
   not netlist-only); (b) switch the VHDL `simulate` tool to NVC behind a flag, with the same pass/fail agreement run on the agent's own
   designs; (c) wire coverage into trace_v1 per item 2; (d) the end-to-end VHDL re-run (review 5.4 item 4) after (a) and (b), because the
   agent's tests would then run against VHDL simulation semantics, not a GHDL netlist.

## Known gaps and limits

- Six designs, five of them small register-window designs; one pure-VHDL kernel measurement on one design. Timings are medians of 3 on a
  shared machine (load 4 to 6): differences under about 10 % are not significant.
- The benches drive the inner entity. They are not the brief 55 hidden benches (those need the SystemVerilog shell); the golden models are
  the dev tasks' own.
- NVC and GHDL LLVM were not run with OSVVM, UVVM, VUnit or a mixed-language design; NVC's 'FSM' coverage found no FSM; toggle coverage was not
  tuned (clock and reset toggles are excluded by NVC itself).
- GHDL coverage under cocotb was run on the mcode build only; the LLVM build has none. GHDL's coverage JSON is read by our script
  (a custom single-quoted format).
- PSL: one small design for the constructs, one design for the property pair; `until` and `next_a` on NVC unexplained; the first failing
  step differs between the two languages because the VHDL has a monitor register. Formal results are bounded (depth 20), not proofs.
- The older formal flow's slowness was bisected by hand (one property, no assumption, other z3); the record is a text note, not a script.
- The path rewrite (`sanitise_paths.py`) changed machine paths in the records; raw logs were not kept.
