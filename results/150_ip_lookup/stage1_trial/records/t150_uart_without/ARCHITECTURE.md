# seg_counter architecture (stage 1, board and device planning)

Board: Nexys A7-100T, part xc7a100tcsg324-1. Top module `seg_counter_top`. Single clock domain `clk` at 100 MHz.
Source of truth for behaviour: spec.yaml. Machine-readable form: architecture.yaml (frozen after approval).

## Summary

- Counts 8-digit BCD up by one every TICK_CYCLES (1e8) clk cycles, wrapping 99999999 to 00000000.
- A debounced rising edge of btnc clears the count to 0; the tick counter is not touched.
- cpu_resetn (active low, synchronous, passed through a 2-flop synchroniser on clk) holds the count and tick counter at 0.
- Eight digits are multiplexed on AN0..AN7 (DIGIT_REFRESH_CYCLES each), leading zeros blanked on AN7..AN1, AN0 always lit.
- The provided test shell `fpga_shell` runs over the USB-UART at 115200 8N1 (CLKS_PER_BIT 868) and exposes the design's registers in its window.

## Block diagram

```text
                 +------------------------------- seg_counter_top -------------------------------+
 CPU_RESETN ---->| reset_sync (2-flop) ---> rst                                                  |
                 |                                                                               |
 BTNC --------->| seg_debounce (2-flop + DEBOUNCE_CYCLES) ---- clr_pulse ---+                    |
                 |                                                         v                     |
 CLK100MHZ ---->| seg_tick (27-bit, TICK_CYCLES) ---- tick ----> seg_bcd_count (8 x BCD) ---+     |
                 |                                                  |  count[31:0]          |     |
                 |                                                  v                       v     |
                 |                                          seg_regs (win 0: ID, 1: COUNT)      |
                 |                                                  ^                       |     |
                 |   seg_display (refresh counter, digit mux, BCD->7seg, blanking) <--------+     |
                 +--------|--------------------|-----------------------|-------------------------+
                          v                    v                       v
                    CA..CG (seg)           AN[7:0]                  DP (held off)
  UART_TXD_IN --> fpga_shell (uart_rx, frame FSM, uart_tx) --> UART_RXD_OUT
                          |  win_addr[6:0] / win_wr / win_rd / win_wdata / win_rdata
                          +--> seg_regs
```

Notes on the diagram: `seg_regs` is the only path from the window to the design. The shell's win_addr is ADDR - 0x80, so the
spec offsets map to window addresses as ID at win_addr 0x00 (host ADDR 0x80) and COUNT at byte offset 0x04, i.e. word
index 1 (win_addr 0x01, host ADDR 0x81). The shell's own registers (0x00-0x05) are not reachable from the window.

## Clock plan

| Domain | Clock port | Frequency | Users |
|---|---|---|---|
| clk | CLK100MHZ (E3) | 100 MHz, 10 ns | all sequential logic: tick, count, debounce, display mux, reset synchroniser, UART shell |

No derived or gated clocks, no MMCM or PLL. The UART baud is generated by a counter on clk (CLKS_PER_BIT 868).
Asynchronous inputs: CPU_RESETN, BTNC, UART_TXD_IN. Each is synchronised on clk before use (see Crossings).

## Reset plan

- Input CPU_RESETN is active low on the pin (C12). Inside the design it is inverted once in `reset_sync` and used as
  an active-high `rst`, synchronous to clk. No asynchronous reset is used anywhere in the design.
- The 2-flop synchroniser is the only asynchronous-input stage for CPU_RESETN. Reset is applied only to control state
  (tick counter, count, debounce, display counter), not to the data path of the segment decode.
- The shell's `rst` input is driven by the same internal `rst`.

## Pin list (top-level ports)

Top-level port names are the master XDC's names (FDA-CON-7). The spec's logical names map as follows:
spec `clk` = CLK100MHZ, `cpu_resetn` = CPU_RESETN, `btnc` = BTNC, `uart_rxd` = UART_TXD_IN, `uart_txd` = UART_RXD_OUT,
`seg[6:0]` = CA..CG (scalars, the master XDC has no SEG bus), `dp` = DP, `an[7:0]` = AN[7:0].
Pin numbers come from the master XDC through board_constraints only (listed here for review against the board).

| Port | Dir | Width | Board resource | Pin | I/O standard | Role |
|---|---|---|---|---|---|---|
| CLK100MHZ | in | 1 | CLK100MHZ | E3 | LVCMOS33 | 100 MHz oscillator |
| CPU_RESETN | in | 1 | CPU_RESETN | C12 | LVCMOS33 | CPU RESET button, active low |
| BTNC | in | 1 | BTNC | N17 | LVCMOS33 | centre button, clears count |
| UART_TXD_IN | in | 1 | UART_TXD_IN | C4 | LVCMOS33 | USB-UART receive into the shell (board name is from the host's view) |
| UART_RXD_OUT | out | 1 | UART_RXD_OUT | D4 | LVCMOS33 | USB-UART transmit from the shell |
| CA..CG | out | 1 each | CA..CG | T10 R10 K16 K13 P15 T11 L18 | LVCMOS33 | segments, active low |
| DP | out | 1 | DP | H15 | LVCMOS33 | decimal point, held off (high) |
| AN[7:0] | out | 8 | AN0..AN7 | J17 J18 T9 J14 P14 T14 K2 U13 | LVCMOS33 | digit anodes, active low |

Timing: CLK100MHZ carries a 10 ns create_clock (sys_clk_pin). The asynchronous inputs (BTNC, CPU_RESETN, UART_TXD_IN) and
the display/UART outputs have no timing relationship with clk and are excluded with set_false_path in design.xdc; each
input is synchronised on clk before use.

## Open items for the owner

1. Port names. The top module uses the master XDC names (FDA-CON-7), not the spec's logical names; the mapping above
   is the proposal. Owner to confirm, since the spec's port list (clk, seg[6:0], uart_rxd, uart_txd) must still exist on the top.
2. COUNT window address: the spec offset 0x04 is a byte offset; the window is word addressed, so COUNT is win_addr 1.
