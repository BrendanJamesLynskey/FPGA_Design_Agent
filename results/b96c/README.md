# results/b96c: frequency offset and rate matching on the 10G link (brief 96C)

This folder holds the simulation records, the report_cdc and TXPI probes, the Vivado builds, the board records and the equivalence proof of brief 96C, which added a rate-matching elastic buffer (`designs/b96_kr260_10g/rtl/rate_match.sv`) and TX phase-interpolator ppm controls to the KR260 10GBASE-R design and to its latency variant `lat_all3`.
**Since the owner's decision of 2026-11-19 the buffer is a build option, `RATE_MATCH = 1`; the default build, `RATE_MATCH = 0`, is the receive path of main 6909e43f (brief 97C).** The board ran the rate-matched builds on 2026-11-19: safety accepted, the TX phase-interpolator route gave no relative offset, and the buffer cost 11 clocks (68 ns) of loop latency.

## Records
- `ppm_sim_baseline.json`, `ppm_sim_baseline_stress.json`: the pre-96C design (main 6909e43f) against a simulated partner at +-ppm (the stress run is `B96_PPM_GAPS=12,14,16`). No failure found: the old design crosses events, not a stream.
- `ppm_sim_ratematch.json`: the rate-matched design, 0, +-100, +-300 ppm, 400 frames each (separate tests per point): every frame received, every order fired, counters clean.
- `core_sim.json`: the core bench on the rate-matched design (`RATE_MATCH = 1`), including the tick-to-trade table (12 to 13 clocks in simulation with the Icarus stand-in of the FIFO macro, in-phase clocks).
- `core_sim_default.json`: the same bench at `RATE_MATCH = 0` (main 6909e43f's own bench, `tests/core_cocotb_default.py`): 11 clocks and no echo spread, as 97C, and FEATURES bit 3 and RXV18 to RXV28 read 0.
- `rm_latency_sim.json`, `rm_latency_sim.sh`: the buffer's latency on the Icarus stand-in and on AMD's `xpm_fifo_async` in xsim, four clock phases, one testbench (`sim/tb_rm_latency.sv`): the real macro is 3 to 5 clocks slower (design.md section 9, "Why the simulation missed the latency").
- `eqy_default/`: eqy proof that the default core equals main 6909e43f's core (and lat_all3's), with a failing planted change; limits in its README.
- `hw/20261119_080724/`: the board session (`control`, `all3` = the `rm_ctl` and `rm_all3` builds; `ppm_ctl`, `ppm_all3`): `stage3.json` per variant (restarts, E, L, safety), `ppm_session.json` (calibration, dwell, SYSMON), `program.json`, `session.json`. `hw/20261119_080546/` is the first attempt, refused by the stale-bitstream guard (`rate_match.sv` lint rewrite after the builds; proved equivalent by eqy, the session ran with the build-time file).
- `cdc_probe.*`, `cdcexp/`: the report_cdc experiments on the first (block memory) design: CDC-1 Critical (38) with or without `set_max_delay`, which led to the `xpm_fifo_async` redesign. `tim7.*`, `tim7_probe.tcl`: the TIMING-7 finding through the FIFO memory that `flow/xpm_cdc.tcl` now handles.
- `txpi_probe.*`: TXPI_PPM is settable on the synthesised GTHE4_CHANNEL cell (default 1'b0 from the Wizard).
- `builds/<name>/`: `digest.json` (timing, utilisation, power, gates), `run.json` (memory and wall time), `wall.txt`, and `commit.txt` for the default rebuild, for `control` (the default, `RATE_MATCH = 0`), `rm_ctl`, `rm_all3`, `ppm_ctl` and `ppm_all3`; `builds/gates.md` is the table generated from them by `gen_gates.py`. Bitstreams and the full Vivado logs are local and git-ignored (`designs/b96_kr260_10g/build/base`, `*/build/base`). `builds_pre_tcl/` holds the records of the earlier attempt before the FIFO-memory exception.
- `queue.sh`, `build_one.sh`, `queue.log`: the heavy-slot Vivado queue and its log.

## Measured
**Default rebuild (`control`, `RATE_MATCH = 0`, git 70f57f5a, Vivado 2026.1, 6 GiB scope, 1 thread, 1461.6 s, no scope cap hits, resident peak 4,439 MiB):** all 29 gates pass, DRC and methodology critical warnings 0, WNS +0.221 ns, WHS +0.011 ns, 6,167 LUT, 14,183 FF, 1.087 W (vectorless, Medium confidence), Tj 48.0 C. (More than the base before 96C, `results/b96/build_b`: the GT buffer-status and ppm registers.)
**Rate-matched builds** (`rm_ctl`, `rm_all3`, `ppm_ctl`, `ppm_all3`: `RATE_MATCH = 1`, git f47986f4): all 29 gates pass with methodology critical warnings 0. Setup slack in ns: 0.293, 0.004, 0.135, 0.033; hold slack 0.010 to 0.011; power 0.928, 0.947, 1.102 and 0.930 W; junction 46.9 to 48.2 C. The all3 builds hit the scope's memory cap about 1000 times and used about 700 MiB of swap.
**Board, rate-matched builds (2026-11-19, the `hw/` records):** safety accepted on all four (100 of 100 restarts locked; 500 of 500 orders sent = fired = order_ok; every fault counter 0; SYSMON inside the DS925 windows). The frequency counter read 0.0 ppm at every TX phase-interpolator code: **no relative offset by this route**, every non-zero target unreachable. Loop latency L (medians, clocks): 61 (rm_ctl), 57 (rm_all3), 59 (ppm_ctl, 0 ppm), 57 (ppm_all3, 0 ppm), against 97C's 50 and 46: +11 clocks (68 ns) for the buffer. E (echo) 24.5, 24, 24, 24 against 20.
**Equivalence (`eqy_default/`):** default core against main 6909e43f: proved (219 partitions); lat_all3 at the default against main's lat_all3: proved (218); a planted change fails in its register.
**Default bench (`core_sim_default.json`):** 11 clocks price-word to order, echo 12 with no spread, as 97C. **Real macro (`rm_latency_sim.json`):** 9 to 13 clocks in the buffer against the stand-in's 6.25 to 8.

## Reproduce
`python3 -m pytest designs/b96_kr260_10g/tests` (simulation, Icarus and cocotb; both `RATE_MATCH` settings); `bash results/b96c/eqy_default/run.sh default|all3|mutant` (about 5 minutes each, OSS CAD Suite); `bash results/b96c/rm_latency_sim.sh` (Icarus and xsim 2026.1, about 3 minutes); `bash results/b96c/queue.sh` re-runs the builds through the heavy-slot script (about 25 minutes each, `take_heavy_slot.sh` first; the `control` build is the default, `rm_ctl` and `rm_all3` the buffer builds); `python3 results/b96c/gen_gates.py` regenerates `builds/gates.md`.

## Known gaps and limits
Rate matching under a real frequency offset has **not** been run on hardware: the TX phase interpolator gave none (one reference clock; the user clock follows), so the buffer's insert and delete behaviour under an offset rests on the simulated partner (`ppm_sim_ratematch.json`) and the Python twin; it needs two boards or a second reference. The buffer's latency (+11 clocks on the board) is 4 clocks more than the real-macro simulation explains (`rm_latency_sim.json`, design.md section 9); the stand-in for `xpm_fifo_async` in the benches under-models the macro. The default rebuild (`control`) was not run on a board: its equivalence to main's design rests on the eqy proof (with the limits in `eqy_default/README.md`: crossings as wires, GT a black box, four stated edits) and the 97C bench at the default. The all3 setup slack of 0.004 ns (`rm_all3`) is thin. `lat_all3` at the default was not rebuilt. `rate_match.sv` at HEAD differs from the file the board ran (a lint-only generate-if, proved equivalent by eqy, run order 2026-11-19 ~08:10); the rate-matched builds were not rebuilt from HEAD.
