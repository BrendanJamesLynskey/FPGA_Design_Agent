# Results of brief 151: partitioning blocks, boundary registers and handshakes

Records of the simulation, formal, seeded-fault and Yosys area runs for the three library entries `pipe_reg`, `credit_chan` and
`axi_reg_slice` and for the synthetic large system `partition/rtl/part_sys.sv`, made on 2026-11-21. No Vivado run is among them: the Vivado
points are written and queued (`partition/sweep.py`). The study that uses them is `docs/partitioning_study.md`.

## Records

| File | What it holds |
|---|---|
| `pipe_reg_measure.jsonl` | one line per parameter point of `pipe_reg`: measured latency, throughput, stored beats when stalled, ready response (cocotb, Icarus Verilog 12) |
| `credit_chan_measure.jsonl` | one line per point of `credit_chan`: latency, throughput over a long window, the clock of each of the first sends, the gap after the credits are spent, capacity |
| `part_sys_sim.jsonl` | end-to-end latency, throughput and data checks of the synthetic system at every boundary kind and depth (8 sub-modules cut the system into 9 boundaries; the simulated copy has 4 sub-modules and 5 boundaries) |
| `faults.json` | the 33 seeded faults of the three entries and whether the tests caught each |
| `pipe_reg_formal.json`, `credit_chan_formal.json` | the SymbiYosys jobs (k-induction proofs, covers, the stream rules as SVA) and the planted faults each proof refutes; seconds per job |
| `partition_queue_rows.md` | the Vivado queue rows written by `partition/sweep.py --queue` (appended to `vivado_later_queue.md`), one per sweep group and part |
| `part_sys_yosys.json` | Yosys `synth_xilinx` cell counts of the synthetic system (flattened, no placement) per boundary kind and depth |

## Reproduce

Every file is regenerated by the commands below; the simulation and formal jobs need Icarus Verilog 12 with cocotb 2.0.1 and the OSS CAD Suite release the repository's CI pins.

```
python3 -m pytest -q ip_lib/pipe_reg/tb ip_lib/credit_chan/tb ip_lib/axi_reg_slice/tb partition/tests        # simulation (Icarus, cocotb 2.0.1)
PIPE_REG_RESULTS=results/b151/pipe_reg_measure.jsonl CREDIT_RESULTS=results/b151/credit_chan_measure.jsonl PART_SIM_RESULTS=results/b151/part_sys_sim.jsonl python3 -m pytest -q ip_lib/pipe_reg/tb/test_pipe_reg_rtl.py ip_lib/credit_chan/tb/test_credit_chan_rtl.py partition/tests
python3 flow/net/faults.py --only <fault names of the three faults.yaml files> --json results/b151/faults.json
python3 ip_lib/pipe_reg/formal/run_formal.py --json results/b151/pipe_reg_formal.json          # needs the OSS CAD Suite (FDA_OSS_CAD)
python3 ip_lib/credit_chan/formal/run_formal.py --json results/b151/credit_chan_formal.json
python3 partition/sweep.py --yosys results/b151/part_sys_yosys.json && python3 partition/sweep.py --yosys-update results/b151/part_sys_yosys.json
```

## Known gaps and limits

No Vivado number exists: Fmax, resources after placement and the route share of the boundary paths are the queued runs. Yosys counts are
not Vivado counts and say nothing about timing. The `*_measure.jsonl` files are appended to by the tests, so an old file is replaced
before a new run. The formal proofs are at a width of 4 bits with the sideband off. The latency of the simulated synthetic system is
for 4 sub-modules; for the 8-sub-module system multiply by nine boundaries instead of five.
