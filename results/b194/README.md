# Results of brief 194

Verification profiles and reliability structures measured on the development design `designs/b194_assurance` (Vivado 2026.1, xc7a100tcsg324-1). Method, definitions and what a user could guess wrong: [docs/assurance.md](../../docs/assurance.md). The tables below are generated by `python3 -m flow.assurance_report --write` from the JSON files named under Records.

## Records

| file | what | made by |
|---|---|---|
| `faults.json` | seeded single-event-upset campaign, 8 variants x 6 targets x 300 trials | `designs/b194_assurance/tests/run_faults.py` |
| `costs.json` | area, slack, Fmax estimate, latency of each variant, TMR copies after routing | `python3 -m flow.assurance cost --ctrl`, then `costs` |
| `methods_rtl.json` | lint, directed, seed sweep and formal against seven RTL mutants | `python3 -m flow.assurance_profiles rtl` |
| `methods_netlist.json` | funcsim and timing simulation, `eqy`, planted netlist faults | `python3 -m flow.assurance_profiles netlist` |
| `eqy_ctrl_variants.json` | `eqy` on the control module with one structure at a time | the commands in the report |
| `profile_times.json` | wall time of each profile's checks | `python3 -m flow.assurance_profiles times` |
| `sem_licence.txt` | SEM IP availability on the free tier | Vivado 2026.1 batch Tcl, as written in the file |

## Reproduce

Run these from the repository root; the Vivado steps need Vivado 2026.1 and a heavy slot (`_handoff/take_heavy_slot.sh`), the others need only the simulators and the OSS CAD Suite.

```
python3 designs/b194_assurance/tests/run_faults.py --trials 300 --seed 1   # simulators only
python3 -m flow.assurance_profiles rtl                                        # Icarus, Verilator, SymbiYosys
python3 -m flow.assurance cost --ctrl && python3 -m flow.assurance costs      # Vivado 2026.1, a heavy slot
python3 -m flow.assurance_profiles netlist && python3 -m flow.assurance_profiles times
python3 -m flow.assurance_report --write
```

## Known gaps and limits

- One small design, one run per variant, one seed: no spread between runs is known; the Fmax figures are estimates from the slack at one 5.0 ns constraint.
- 7-series only; no UltraScale+ and no board measurement.
- `fsm_safe_state` was not fault-injected at netlist level; the watchdog's `eqy` FAIL was not investigated to a cause.
- Times are for the checks only (no model time, no independent spec bench, no board) on a design of about 100 LUTs.
- The `ip_release` and `low_latency` rows show the `thorough` and `standard` figures because their extra checks are not run by the flow yet.

### What each verification method catches

Seven RTL bugs planted one at a time in the plain design (`designs/b194_assurance/tests/mutants.py`). `yes` = the method reported a failure on the mutant; the unmutated design passes every method.

| mutant | lint | directed, 1 seed | 8 seeds | formal depth 20 | formal depth 80 |
|---|---|---|---|---|---|
| m1_last_word: the sequencer stops accepting one word early: the last word of every burst is never taken | no | yes | yes | yes | yes |
| m2_checksum_clear: the checksum is not cleared by start: the second burst adds to the first | no | yes | yes | no | no |
| m3_early_done: done is signalled without waiting for the FIFO and the output stage to drain | no | yes | yes | yes | yes |
| m4_count_low_byte: the remaining count is decremented in its low byte only: wrong across a multiple of 256 (bursts above 256 words) | no | yes | yes | no | no |
| m5_len_zero: a burst of length 0 is not special-cased: the sequencer waits for words that never come | no | no | no | yes | yes |
| m6_double_pop: the FIFO is read again while a read is in flight: a word is overwritten in the output register under back-pressure | no | yes | yes | no | no |
| m7_wrap_pointer: the write pointer wraps at 500 instead of 512: wrong only when the FIFO holds more than 500 words | no | yes | yes | no | no |
