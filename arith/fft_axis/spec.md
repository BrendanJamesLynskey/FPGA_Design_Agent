# AXI4-Stream FFT (wrappers of the two FFT architectures) (arith/fft_axis)

Generated by `python -m arith.tools.gen_spec_md` from [spec.yaml](spec.yaml); edit the YAML, not this file. Part of the frequency-domain suite of brief 148 ([../README.md](../README.md)).

The configurable FFT (arith/fft) behind AMBA AXI4-Stream ports, as the owner asked (favour AXI where appropriate): a slave stream of input frames and a master stream of output frames, tdata = {imaginary, real}, tlast on the last beat of every frame, per-frame forward or inverse on tuser (read on the first beat), an active-low synchronous reset aresetn. Two variants with different, stated back-pressure: sdf has NO back-pressure (a pure streaming interface: s_axis_tready is always 1, m_axis_tready must be tied high), burst has FULL back-pressure on both streams. The arithmetic is the wrapped FFT variant's, bit for bit; the wrapper adds a start-of-frame flag, an output beat counter for tlast and, for simulation only, AXI4-Stream protocol checkers (fft_common/axis_checker.sv).

## Function

- input: beats of s_axis_tdata = {imaginary part (W bits), real part (W bits)}, two's complement, W bits each (not padded to a byte boundary, so s_axis_tdata is 2 * W bits); a frame is N = 2**LOGN beats, tlast high on the N-th; s_axis_tuser[0] = 1 selects the inverse transform for the frame and is read on the FIRST beat only
- a beat is transferred when s_axis_tvalid and s_axis_tready are both high in a clock (AXI4-Stream handshake); the wrapper's tready does not depend on tvalid, and the wrapped core never sees a beat that was not transferred
- output: beats of m_axis_tdata = {imaginary, real}, each WO bits (W when SCALE = 1, W + LOGN when SCALE = 0), N beats per frame, tlast on the N-th; natural or bit-reversed order (ORDER) and every other result as arith/fft/spec.md; m_axis_tvalid comes from registers and never depends on m_axis_tready
- sdf, back-pressure NONE: s_axis_tready = 1 always; m_axis_tready is ignored and must be 1 whenever m_axis_tvalid is 1 (the checker flags a violation); s_axis_tvalid must stay high from the first to the last beat of every frame; frames follow with no gap or after at least N/4 idle beats; m_axis_tvalid is high for N consecutive clocks per frame, so tdata and tlast may change in a clock in which tready is low only because the interface forbids tready low
- burst, back-pressure FULL: s_axis_tready is high when idle and during a load, low while computing and unloading; the source may pause (tvalid low) inside a frame and between frames; the sink may stall (m_axis_tready low) at any time and m_axis_tvalid, tdata and tlast are then held (AXI4-Stream stability rule)
- AXI4-Lite: none. There are no run-time configuration registers: the per-frame option (the direction) rides on tuser, and every other option is a compile-time parameter. A run-time scaling schedule, run-time N or a cyclic prefix would need registers and are not provided
- optional AXI4-Stream signals not used: tkeep, tstrb (all beats are data), tid, tdest

Signedness: two's complement parts inside tdata.

Exactness: bit-exact against the model of the wrapped variant (arith/fft/model.py); the accuracy against NumPy is that of arith/fft.

Latency: clocks from the clock in which the first beat of a frame is transferred on s_axis to the clock in which the first beat of the output frame is offered on m_axis (m_axis_tvalid and the first tdata); equal to the wrapped variant's in_sof to out_sof latency, the wrapper adds none. With pauses or a stalled sink the first output beat can only be later.

## Parameters

| Parameter | Constraint | Meaning |
|---|---|---|
| `LOGN` | min 3 | log2 of the frame length N (3 to 12) |
| `W` | min 4 | input sample part width |
| `TW` | min 4 | twiddle width, 4 to 28 |
| `SCALE` | one of [0, 1] | 1: scaled (output W bits, X / N); 0: growing (W + LOGN bits) |
| `RND` | one of [0, 1] | 1: round half up; 0: truncate |
| `ORDER` | one of [0, 1] | 0: natural order out; 1: bit-reversed |
| `CMUL` | one of [3, 4] | twiddle multiplier form |
| `TWSTAGES` | one of [1, 2] | twiddle ROM latency |
| `MULSTAGES` | min 0 | register ranks per complex multiplier, 0 to 3 |

## Variants

Each variant is one SystemVerilog file under `rtl/`, with the same ports. Parameters of the variant beyond the ones above are in its header. The primitive use is what the code is written to infer; it was stated BEFORE any Vivado run and is not a measurement.

| Variant | Module | Latency (clocks) | Trade-off |
|---|---|---|---|
| `sdf` | `fft_axis_sdf` ([rtl/fft_axis_sdf.sv](rtl/fft_axis_sdf.sv)) | `(1<<LOGN)-1+LOGN+((LOGN-1)//2)*(TWSTAGES+MULSTAGES+1)+(0 if ORDER else (1<<LOGN)+1)` | AXI4-Stream without back-pressure: the highest throughput and the least logic, but the sink must never stall and the source must not pause inside a frame |
| `burst` | `fft_axis_burst` ([rtl/fft_axis_burst.sv](rtl/fft_axis_burst.sv)) | `(1<<LOGN)+LOGN*((1<<LOGN)//2+MULSTAGES+3)+1` | AXI4-Stream with full back-pressure: standard handshakes on both sides, so it connects to a DMA or an AXI4-Stream FIFO without a frame buffer, at the burst core's lower throughput |

### Intended primitive use

- `sdf`, Artix-7 (xc7a100t): the wrapped sdf core's (arith/fft/spec.md) plus under 20 LUT and about 3 * LOGN flip-flops; no added DSP or RAM; Fmax as the core
  - K26 (xck26): as a7
- `burst`, Artix-7 (xc7a100t): the wrapped burst core's (arith/fft/spec.md) plus under 20 LUT and about 3 * LOGN flip-flops
  - K26 (xck26): as a7

## Interface contract

Written without knowing the design the block will sit in (brief 148, owner decision 24): this is what a user can rely on and must provide.

- Protocol: AMBA AXI4-Stream on both interfaces, with the back-pressure stated per variant: sdf none (a pure streaming interface), burst full. tlast marks the last beat of each frame; tuser[0] on the first beat selects the direction; there is no AXI4-Lite interface because there are no run-time configuration registers
- Throughput: sdf: one beat per clock in and out, frames back to back or after N/4 idle beats; burst: one frame per N + LOGN * (N/2 + MULSTAGES + 3) + N clocks (no overlap) when neither side stalls
- Latency: as the wrapped variant: sdf, bit-reversed: N - 1 + LOGN + ((LOGN - 1) // 2) * (TWSTAGES + MULSTAGES + 1), natural adds N + 1; burst: N + LOGN * (N/2 + MULSTAGES + 3) + 1
- Reset: aresetn low for at least one clock clears the control state of the wrapper and the core (the data memories are not cleared); a frame in flight is lost; the first frame after reset starts with its first beat
- Clock: one clock, rising edge, no clock enable
- Stalls: sdf: neither stream can be stalled (s_axis_tready 1, m_axis_tready must be 1, tvalid must stay high inside a frame); burst: both can

| Variant | Latency (clocks) | Throughput |
|---|---|---|
| `sdf` | `(1<<LOGN)-1+LOGN+((LOGN-1)//2)*(TWSTAGES+MULSTAGES+1)+(0 if ORDER else (1<<LOGN)+1)` | one beat per clock in and out; no back-pressure (tready fixed) |
| `burst` | `(1<<LOGN)+LOGN*((1<<LOGN)//2+MULSTAGES+3)+1` | one frame per N + LOGN * (N/2 + MULSTAGES + 3) + N clocks when neither side stalls; both streams support back-pressure |

## Integration

- Port timing: m_axis_* come from registers (through the output swap mux and, in natural order, the bank select); s_axis_tready is a register decode (burst) or a constant (sdf); the first stage's input muxes see s_axis_tdata and s_axis_tuser directly. No combinational path from m_axis_tready to m_axis_tvalid or from s_axis_tvalid to s_axis_tready
- Constraints to carry: one clock; the protocol checkers sit between `ifndef SYNTHESIS lines and are not part of the design. A sdf instance must be connected to a sink that never stalls (an AXI4-Stream FIFO or a DMA with a deep enough buffer; a DMA that can deassert tready breaks it)
- Verification after integration: this function has no packaged harness (brief 148 left it out; see the report): rerun its bench (tests/) against your instance, which needs the repository's arith/tools and fft_common helpers.

## What a user could guess wrong

- the sdf variant has NO back-pressure: tie m_axis_tready high; if the sink lowers it while m_axis_tvalid is high the beat is lost, and nothing downstream is told; this is the price of the one-beat-per-clock pipeline
- sdf also requires s_axis_tvalid high for all N beats of a frame once the first beat is sent (no pause inside a frame) and a gap of 0 or at least N/4 beats between frames: an AXI4-Stream source that may pause (a DMA reading memory) needs a frame buffer in front of it, or the burst variant
- tdata is {imaginary, real} with the REAL part in the LOW bits, W bits each and not rounded up to a multiple of 8: byte-oriented AXI4-Stream infrastructure (a width converter, a DMA) needs the widths padded by the integrator
- tuser is read on the first beat only; tuser on the other beats is ignored, and tuser of the output beats does not exist (AMD's FFT carries the bin index on the output tuser: this one does not)
- tlast on the input is used only to find where the next frame starts; a frame of other than N beats is outside the contract and neither flagged nor recovered from (AMD's FFT raises tlast_missing and tlast_unexpected events: this one has no status stream)
- m_axis_tlast is generated by counting output beats, so with a stalled sink (burst) it stays with its beat, as AXI4-Stream requires
- there is no AXI4-Lite interface and no run-time scaling schedule, run-time N or cyclic-prefix option: they are compile-time parameters, or absent
- the SystemVerilog protocol checkers (axis_checker.sv) are simulation-only: they use immediate assertions on the clock edge (no concurrent SVA properties, which the open-source simulators of this repository do not run); they are not in the synthesised design

## Lean, and what is research

Not attempted: the wrapper is control logic around a verified core; the handshake rules are checked by the simulation checkers under random stalls and by a deliberate-violation test, not proved.
