Requirements in full

FFT-F-MODEL: The bit-exact model is right

arith/fft/model.py gives, for every input, the result that spec.md defines. It agrees with an independent formulation (NumPy's FFT (forward and inverse), checked for both variants at every N from 8 to 1024, and the identity that the inverse is the swap of a forward transform), and the conventions that a user could guess wrong (spec.md, last section) are pinned by examples.

  • simulation test: pass The model against independent formulations and the pinned conventions: 25 test(s) passed in the recorded run evidence

FFT-F-EXACT: Every variant is bit-exact against the model

At every parameter point listed in spec.yaml (12 directed or exhaustive points, 8 random ones, across 2 variants), each variant's outputs equal the model's: the directed points drive impulses at every position and tones at every bin (small N), DC, Nyquist, a chirp and corner values, forward and inverse, back to back and after the shortest legal gap; the random points drive random frames with random direction and legal gaps up to N = 4096. Each output frame equals the model bit for bit, the latency from in_sof to out_sof equals the formula, and out_valid is N consecutive clocks.

  • simulation test: pass Every variant against the model at the small points (Icarus + cocotb): directed or exhaustive stimuli: 12 test(s) passed in the recorded run evidence
  • simulation test: pass Every variant against the model at the large points: random stimuli (Icarus + cocotb): 8 test(s) passed in the recorded run evidence

FFT-F-LAT: Latency is as specified and the bench would notice if it were not

Each variant's latency in clocks is the expression in spec.yaml (sdf: (1<<LOGN)-1+LOGN+((LOGN-1)//2)*(TWSTAGES+MULSTAGES+1)+(0 if ORDER else (1<<LOGN)+1); burst: (1<<LOGN)+LOGN*((1<<LOGN)//2+MULSTAGES+3)+1), and the bench, run with a latency two clocks off, fails for every variant, so the passing runs prove the latency rather than assume it.

  • simulation test: pass The bench passes at the stated latency and fails two clocks off, for every variant: 2 test(s) passed in the recorded run evidence

FFT-F-EQUIV: The properties named in formal/jobs.yaml hold, by proof where the tools allow

SymbiYosys with the slang front end checks the properties of formal/jobs.yaml: a proof is by k-induction (for all inputs, any run length) at the parameters listed there, a bounded check holds only to its stated depth. What the jobs say is in each job's `claim`; parameters beyond the listed ones are covered by simulation, not by proof.

  • formal: bounded Bounded model checks from an arbitrary state (5 jobs; depths in formal/jobs.yaml): 5 test(s) passed in the recorded run evidence
  • formal: pass Each formal check refutes a planted fault (the check can fail): 8 test(s) passed in the recorded run evidence

FFT-F-BENCH: The bench catches seeded faults

Every one of the mutants in verif/mutants.yaml (one exact text change each: an inverted condition, a wrong constant, a dropped connection, a wrong width) makes the cocotb bench fail, or is argued equivalent in the file's header; mutants that survive or do not build are reported, never hidden.

  • simulation test: pass The mutation run as a test: no mutant survives, none fails to build: 1 test(s) passed in the recorded run evidence
  • simulation measurement: stale Mutants killed of valid mutants (the record of the last full run): survived = []; invalid = []; valid = 40; score_pct = 100 evidence

FFT-F-PACKAGE: The RTL is lint-clean, and its files agree with the specification and with the Vivado build files

spec.yaml states an interface contract (protocol, throughput, latency, reset, clock, stalls) and integration guidance (port timing, constraints to carry). Every variant passes Verilator -Wall at every point of spec.yaml; its ports and default parameters are the ones spec.yaml states; its header states the intended primitive use before any Vivado run; spec.md is the rendering of spec.yaml; the out-of-context wrapper and the build.yaml for each variant (Artix-7 xc7a100t and K26 xck26, prepared and not run) are current and lint-clean at every point they list, so a Vivado run can start from the repository alone.

  • simulation test: stale spec.yaml against the RTL headers, spec.md against spec.yaml, Verilator -Wall at every point, wrappers and build.yaml current and lint-clean: 5 test(s) passed in the recorded run evidence

FFT-F-BACKPRESSURE: The burst variant honours out_ready: stalling the sink changes nothing but the timing

With out_ready driven low at random (40 per cent of the clocks) the burst variant's output frames equal the model bit for bit, and out_valid, out_sof and the data stay unchanged in every clock in which out_valid is high and out_ready low. The sdf variant ignores out_ready (stated).

  • simulation test: pass The burst variant under a randomly stalled sink: 2 test(s) passed in the recorded run evidence

FFT-F-ACCURACY: Accuracy against NumPy's FFT is measured and stated, per scaling mode

For each variant, scaling mode and several N and twiddle widths, the error of the model (which the RTL equals bit for bit) against the double-precision FFT of NumPy is recorded in verif/results/accuracy.json: worst and rms error in units of the output LSB, and the SQNR and SFDR for a full-scale tone. The recorded worst error of the scaled mode is at most 6 LSB at every recorded point, and the unscaled mode's SQNR for noise-like input is at least 80 dB at every recorded point with twiddles of 16 bits or more (the unscaled word is W + LOGN bits wide, so its error in output LSBs is large for narrow twiddles: the SQNR is the figure to read); these are the bounds the test enforces, and the figures are what the report states, with no claim beyond them.

  • simulation measurement: pass Worst error against NumPy at every recorded point (the record of the last run): worst_lsb_scaled_max = 3.544; sqnr_db_min_unscaled_tw16plus = 85.8; sfdr_db_min_tw16plus = 82.4; points = 80 evidence

FFT-F-ROUNDTRIP: A forward transform followed by an inverse transform returns the input within the stated error

Through the RTL (both variants, the scaled mode), forward then inverse of the same frames returns the input divided by N (the scaled mode divides by N in both directions) to within 3 LSB, at the point of the round-trip test; the inverse is the swap of a forward transform, so forward and inverse results are related exactly by the swap.

  • simulation test: pass Forward then inverse through the RTL returns the input; the inverse is the swap of a forward transform: 2 test(s) passed in the recorded run evidence

FFT-F-FASTCONV: Fast convolution built on the FFT models equals direct convolution within the stated error (model only, phase 0)

arith/fft_common/fastconv.py (overlap-save and overlap-add on the bit-exact FFT models, both variants) equals numpy.convolve of the same samples and taps to within 8 LSB of the output word (N = 128 to 512, L = 1 to 65 taps, W = 16, TW = 18, WH = 24, FH = 14), the two methods agree with each other within the same bound, a unit filter passes the signal within 3 LSB, and a complex input is filtered part by part. This is a Python model and an interface proposal (docs/fft_suite_plan.md section 5), not RTL: the fast-convolution block is the next phase.

  • simulation test: pass Overlap-save and overlap-add models against direct convolution: 7 test(s) passed in the recorded run evidence
