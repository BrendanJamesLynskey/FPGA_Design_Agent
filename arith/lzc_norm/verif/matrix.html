The human specifies the requirements and checks that the verification is thorough enough. The agent holds the knowledge to implement and to verify. Requirements in full

LZN-F-MODEL: The model is the specification: it equals integer arithmetic

For the leading-zero count and normaliser: lz and y equal the bit_length definition for every input at W = 2 to 14 and for random values at W up to 256, and the stagewise log-shifter recurrence computes the same count and word.

  • simulation test: pass Model tests against Python integer arithmetic: 4 test(s) passed in the recorded run evidence

LZN-F-RTL-EXH: Every variant is bit-exact against the model, exhaustively at small widths

Simulation (Icarus 14) of every variant against the model: every input at W = 2 to 16 (powers of two and not), every variant, with input gaps; count, normalised word, order and latency checked.

  • simulation test: pass Exhaustive small widths, every variant: 1 test(s) passed in the recorded run evidence

LZN-F-RTL-RAND: Every variant is bit-exact against the model at large widths

Simulation of every variant against the model: 3000 inputs of every magnitude at W = 24, 32, 33, 48, 64 and 100.

  • simulation test: pass Random and edge vectors at large widths: 1 test(s) passed in the recorded run evidence

LZN-F-LAT: Latency and throughput are what the spec states

The measured latency equals the spec (1, 1, ceil(K / PIPE), 2 clocks) for every variant and the stagewise variant at every PIPE from 1 to K + 1 at W = 9 and 16, one result per clock.

  • simulation test: pass Latency measured per result: 1 test(s) passed in the recorded run evidence

LZN-F-LINT: The RTL is Verilator -Wall clean

Verilator -Wall --lint-only reports nothing for any variant at W = 2, 3, 8, 13, 16 and 32 (stagewise with PIPE = 1, 2 and 40).

  • simulation test: pass Verilator -Wall lint: 1 test(s) passed in the recorded run evidence

LZN-F-MUTANT: The bench catches seeded faults

Each of 16 seeded faults (one text change in the RTL, verif/mutants.yaml) makes the bench fail: killed/total = 16/16. 1 further mutant(s) are equivalent (the same function and timing) and are listed apart with the reason; they are not counted.

  • simulation test: pass The mutant check passes: 1 test(s) passed in the recorded run evidence
  • simulation measurement: pass Mutants killed / total: mutants_summary.killed = 16; mutants_summary.survived = 0 evidence

LZN-F-FORMAL-REF: Every variant equals an independent reference (SymbiYosys)

SymbiYosys with the slang front end: each variant satisfies the characterisation of the count (zero bits above the leading one, y = x << lz with its MSB set; W for x = 0) for all input sequences from reset: 13 jobs at W = 5 to 12; unbounded (abc pdr). Six seeded faults are applied to the RTL and the same proof fails (bounded model checking finds the counterexample), which shows the harness is not vacuous.

  • simulation test: pass The formal reference and fault-catching tests pass: 2 test(s) passed in the recorded run evidence
  • formal: pass Reference proofs: jobs proved unbounded, none failed: summary.reference.proved_unbounded = 13; summary.reference.failed = 0 evidence
  • formal: bounded Six seeded faults each make the proof fail (bounded model checking): summary.mutant.faults_caught = 6; summary.mutant.failed = 0 evidence

LZN-F-FORMAL-PAIR: Variants of the function agree with each other (SymbiYosys)

SymbiYosys with the slang front end, no reference involved: tree against priority loop (W = 8, 11), tree against one-block stagewise (W = 8), and the two-clock tree against two- and three-group stagewise (W = 8, 12) give the same outputs on the same inputs; unbounded (abc pdr).

  • simulation test: pass The variant-pair tests pass: 1 test(s) passed in the recorded run evidence
  • formal: pass Variant pairs proved equal, none failed: summary.pair.proved_unbounded = 5; summary.pair.failed = 0 evidence

LZN-F-LEAN-TREE: The tree leading-zero count is correct for every width 2^k (Lean)

lzc_tree.sv's recursive halving returns a count c with 2^(P-1-c) <= x < 2^(P-c) for every non-zero word of P = 2^k bits and flags a zero word. Proved in Lean, statement not approved; the Lean base case is a one-bit word (the RTL's leaf is two bits: one more unfolding). Zero padding to a non-power-of-two width, the stagewise variants and the barrel shift are not in the Lean model.

  • Lean proof (all widths): statement not approved The recursive-halving count is correct for every word of 2^k bits: it brackets the word and flags non-zero: statement not approved; Arith.Lzc.lzcTree_correct: kernel only; proof of the transcription, transcription tested; recorded build (not re-run) evidence

LZN-F-BUILD: Out-of-context build descriptions are prepared for Artix-7 and K26 (not run)

For every variant of the leading-zero count and normaliser there is a build.yaml and an out-of-context clock constraint for xc7a100t and xck26, current against arith/tools/gen_build.py, consistent with the RTL (top, parameters, sources), with the expected primitive use evaluated for each point; the out-of-context wrapper lints clean and is functionally exact for the always-ready variants; the packaged verification harness (harness/run.py, which a user reruns against their own instance) passes on the library instance with every coverage bin hit. No Vivado run has been made: this requirement is about preparation, not about area, Fmax or power.

  • simulation test: pass Build descriptions current and consistent; wrapper lint and simulation; packaged harness runs on the library instance: 3 test(s) passed in the recorded run evidence
