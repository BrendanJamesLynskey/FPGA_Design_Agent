Requirements in full

FMAXIS-F-MODEL: The bit-exact model is right

arith/fft_mdc2_axis/model.py gives, for every input, the result that spec.md defines. It agrees with an independent formulation (the 2-parallel core's own model (arith/fft_common/fft_ref.py mdc2_frame at SCALE = 0), the block-floating-point rule shared with arith/fft_bfp (a brute-force exponent search is in that function's tests), and the packing of the AXI words (sample 0 in the low half, real part in the low half of a sample)), and the conventions that a user could guess wrong (spec.md, last section) are pinned by examples.

  • simulation test: pass The model against independent formulations and the pinned conventions: 21 test(s) passed in the recorded run evidence

FMAXIS-F-EXACT: Every variant is bit-exact against the model

At every parameter point listed in spec.yaml (5 directed or exhaustive points, 3 random ones, across 1 variants), each variant's outputs equal the model's: the directed points send the bench's frames (impulses, tones, DC, Nyquist, a chirp, corner values, and frames whose largest part is 2**m - 1 so that the normalisation saturates), forward and inverse, from a source that never pauses into a sink that is always ready: every output frame equals the model bit for bit, the exponent on tuser equals the model's on every beat, the first-beat latency equals the formula, the idle clocks between frames are 0 or at least N/8, and the frame period equals N/2 when NB * N/2 >= latency + N/2; the random points send random frames with random idle clocks (including 1 to N/8 - 1, which the wrapper must turn into a legal gap) into a sink that is always ready and into one with random tready.

  • simulation test: pass Every variant against the model at the small points (Icarus + cocotb): directed or exhaustive stimuli: 5 test(s) passed in the recorded run evidence
  • simulation test: pass Every variant against the model at the large points: random stimuli (Icarus + cocotb): 3 test(s) passed in the recorded run evidence

FMAXIS-F-LAT: Latency is as specified and the bench would notice if it were not

Each variant's latency in clocks is the expression in spec.yaml (par2: (1<<LOGN)//2-1+(LOGN-1)+((LOGN-2)//2)*(TWSTAGES+MULSTAGES+1)+TWSTAGES+MULSTAGES+2+(1<<LOGN)//2+2), and the bench, run with a latency two clocks off, fails for every variant, so the passing runs prove the latency rather than assume it.

  • simulation test: pass The bench passes at the stated latency and fails two clocks off, for every variant: 1 test(s) passed in the recorded run evidence

FMAXIS-F-EQUIV: The properties named in formal/jobs.yaml hold, by proof where the tools allow

SymbiYosys with the slang front end checks the properties of formal/jobs.yaml: a proof is by k-induction (for all inputs, any run length) at the parameters listed there, a bounded check holds only to its stated depth. What the jobs say is in each job's `claim`; parameters beyond the listed ones are covered by simulation, not by proof.

  • formal: pass k-induction proofs (6 jobs; parameters in formal/jobs.yaml): 6 test(s) passed in the recorded run evidence
  • formal: pass Each formal check refutes a planted fault (the check can fail): 9 test(s) passed in the recorded run evidence

FMAXIS-F-PACKAGE: The RTL is lint-clean, and its files agree with the specification and with the Vivado build files

  • simulation test: pass spec.yaml against the RTL headers, spec.md against spec.yaml, Verilator -Wall at every point, wrappers and build.yaml current and lint-clean: 5 test(s) passed in the recorded run evidence

FMAXIS-F-AXIS: The AXI4-Stream rules hold on both streams, also with a sink that stalls, and the checkers can fail

On both streams the wrapper's SystemVerilog protocol checkers (fft_common/axis_checker.sv: valid stays high until accepted, tdata, tuser and tlast stable while stalled, no unknowns after reset, tlast on every (N/2)-th beat, no pause inside an input frame) count zero violations in every run of the directed, random, back-pressure and gap benches, including random tready and a sink that holds tready low for three frame times; the checker bench shows that a pause inside a frame and a withdrawn tvalid are counted.

  • simulation test: pass The protocol checkers can fail (a pause inside a frame, a withdrawn tvalid): 1 test(s) passed in the recorded run evidence
  • simulation test: pass A sink that stalls for three frame times and one that is ready one clock in four: no frame lost, the offered beat held, the source held off by the credit: 15 test(s) passed in the recorded run evidence

FMAXIS-F-GAP: Whatever the source does, the core sees 0 or at least N/8 idle clocks between frames, and nothing is lost to the output store

After every beat with tlast s_axis_tready is high for one clock (a frame may follow with no idle clock) and, when no beat is transferred in it, low for N/8 - 1 clocks; the bench measures the idle clocks between every pair of frames under source idles of 0, 1 .. N/8 + 1 clocks and requires 0 or at least N/8, and exactly max(source idle, N/8) for a source idle of 1 or more. At a frame start s_axis_tready is low while NB frames are in the block, so with a sink that stalls for three frame times no frame is lost or altered (every output frame equals the model). With NB * N/2 >= latency + N/2 and a ready sink the frame period is N/2.

  • simulation test: pass The idle clocks between frames under every source idle from 0 to N/8 + 1: 5 test(s) passed in the recorded run evidence
  • simulation test: pass A sink that stalls for three frame times and one that is ready one clock in four: no frame lost, the offered beat held, the source held off by the credit: 15 test(s) passed in the recorded run evidence

FMAXIS-F-EXPONENT: The block exponent is on tuser from the first beat and the words are normalised to W bits

Every output frame's m_axis_tuser equals the model's exponent on every beat (the first beat is the contract), and every output part equals the model's normalised word: including frames whose largest part makes the rounding carry (saturation), frames of very different level back to back (so the exponent of one frame never leaks into the next), and the inverse transform.

  • simulation test: pass Exponent and normalised words against the model, saturation frames included: 5 test(s) passed in the recorded run evidence
