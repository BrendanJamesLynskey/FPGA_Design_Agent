# Fast convolution FIR filter (overlap-save on the streaming FFT, AXI4-Stream data, AXI4-Lite coefficients) (arith/fft_fastconv)

Generated by `python -m arith.tools.gen_spec_md` from [spec.yaml](spec.yaml); edit the YAML, not this file. Part of the frequency-domain suite of brief 161 ([../README.md](../README.md)).

A real FIR filter of up to 3N/4 + 1 taps applied to a complex sample stream by fast convolution (overlap-save): the stream on an AXI4-Stream slave port is cut into blocks of N = 2**LOGN samples that overlap by L - 1, each block goes through a forward FFT (arith/fft sdf, unscaled), a product with the filter's spectrum and an inverse FFT (scaled by 1/N), and the B = N - L + 1 valid outputs of each block leave on an AXI4-Stream master port with full back-pressure. The filter spectrum (N complex words of WH bits, FH fractional bits) is held in a RAM and loaded at run time through an AXI4-Lite register interface, so the filter can be changed between blocks without rebuilding. Built from the FFT suite's blocks (two fft_sdf_r22 pipelines, one fft_cmul) plus a ring buffer, a block controller, an output FIFO with a credit counter and an AXI4-Lite register file. The method is chosen where the filter is long enough that N log N per block beats L multiplies per sample; the throughput is B samples per B + N clocks (the FFT pipelines are fed one block at a time), so it fits filters at sample rates well below the clock. Overlap-add is not built (it needs an output accumulator RAM; the model in arith/fft_common/fastconv.py has both).

## Function

- input stream: one complex sample per beat on s_axis, s_axis_tdata = {imaginary (W bits), real (W bits)}, two's complement, W bits each (not padded to bytes); there is no tlast, tkeep, tuser (the stream has no frames: the block controller forms them); a beat is transferred when tvalid and tready are both high; s_axis_tready is high only while the controller collects the B samples of a block (it is low for the first N clocks after reset, and for N + 1 clocks while a block is fed to the forward FFT, and while the output FIFO lacks room)
- block rule: blocks are made of the last L - 1 samples of the previous block (zeros before the first block) followed by B = N - L + 1 new samples; the block's N outputs of the circular convolution with the filter are computed, the first L - 1 (the wrap-around) are dropped and the other B are the output. The output sample k of the stream is therefore the linear convolution of the input stream with the filter taps at sample k (the zero history before the first sample); only COMPLETE blocks are processed, so after the last input sample B - 1 samples at most stay inside the block controller: flush them by sending zeros
- filter: a real filter h[0 .. L-1] (L = number of taps, a build parameter) given by its spectrum Hq[k] = round(FFT(h zero-padded to N)[k] * 2**FH), k = 0 .. N - 1 in NATURAL order, each part a signed WH-bit integer; the host computes it (arith/fft_common/fastconv.py filter_spectrum is the reference) and writes it through COEF_ADDR, COEF_RE, COEF_IM; the spectrum of a REAL filter is conjugate symmetric, but the block does not require or check it (a complex filter works too); after reset the filter memory is cleared to zero, so the output is zero until a filter is loaded
- arithmetic (bit-exact, arith/fft_fastconv/model.py): forward transform of the block unscaled (W + LOGN bit words, arith/fft sdf, SCALE 0, natural order); the exact complex product with Hq[k]; one rounded right shift of FH bits (round half up when RND = 1, floor when RND = 0); the WI = W + LOGN + GB low bits are kept; inverse transform scaled by 1/N (arith/fft sdf, SCALE 1, in_inverse 1, natural order, WI bit words); the kept outputs are saturated to W bits
- overflow rule: no overflow occurs inside the inverse transform if the absolute gain of the filter, sum of |h|, is at most 2**GB and the input magnitude (re**2 + im**2) is below full scale 2**(2W-2); a filter of larger gain wraps silently inside the transform (the output is then wrong, not saturated). The OUTPUT is saturated to W bits: an output part beyond the range sets the sticky STATUS.SAT bit; saturation by the output stage is exact and the model reproduces it
- registers (AXI4-Lite): see the register map in the contract; the coefficient memory can be written only while STATUS.BUSY is 0 (no block is between its start and the end of its spectral product, and the memory is not being cleared); a commit while BUSY is 1 is refused with SLVERR, changes nothing and sets the sticky DROPPED bit; with a continuous input stream BUSY is nearly always 1 (stop the input and wait for BUSY = 0 before loading a new filter)
- accuracy: against numpy.convolve of the same samples and the unquantised taps the output error is the filter quantisation (the spectrum rounded to FH fractional bits) plus the transform's rounding: measured in verif/results/accuracy.json; the bound the test enforces is stated in the contract

Signedness: all data are two's complement; the filter spectrum parts are signed WH-bit integers (written as 32-bit two's complement words, only the low WH bits are used).

Exactness: bit-exact against the model (arith/fft_fastconv/model.py, the bit-exact FFT models and an exact complex product) for every stream within the overflow rule, including the saturation of the output; against numpy.convolve (and the unquantised taps) the error is bounded as stated in the contract and recorded in verif/results/accuracy.json.

Latency: clocks from the clock in which the last input beat of a block (the B-th since the block started) is transferred on s_axis to the clock in which the first output beat of that block is offered on m_axis, with the pipeline empty, the sink ready and the output FIFO with room.

## Parameters

| Parameter | Constraint | Meaning |
|---|---|---|
| `LOGN` | min 5 | log2 of the transform length N: 5 to 12 (N = 32 to 4096) |
| `L` | min 1 | number of filter taps, 1 to 3N/4 + 1: the block holds B = N - L + 1 new samples, which must be at least N/4 (the frame-gap rule of the streaming FFT) |
| `W` | min 4 | sample part width (input and output) |
| `TW` | min 4 | twiddle width of the two FFTs, 4 to 28 |
| `WH` | min 8 | filter spectrum part width, at least FH + GB + 2 so that |Hq| fits, at most 32 |
| `FH` | min 0 | fractional bits of the filter spectrum (Hq = round(H * 2**FH)) |
| `GB` | min 0 | gain headroom bits: the filter's absolute gain, sum of |h|, must be at most 2**GB |
| `RND` | one of [0, 1] | 1: round half up at every shift; 0: truncate (floor) |
| `CMUL` | one of [3, 4] | multiplier form of the FFT twiddles and of the spectral product: 4 real multipliers or 3 (identical results) |
| `TWSTAGES` | one of [1, 2] | twiddle ROM latency |
| `MULSTAGES` | min 0 | register ranks in each complex multiplier, 0 to 3 |

### Intended primitive use

- `os`, Artix-7 (xc7a100t): N = 1024, L = 257, W = 16, WH = 24, GB = 1, CMUL 4, MULSTAGES 3: the forward FFT's multipliers see up to 16 + 10 = 26-bit operands (2 DSP48E1 per real multiplier, about 32 DSP48E1 for 4 complex multipliers) and the inverse FFT's up to 27 bits (about 32), the spectral product a 26 x 24 multiplier x 4 (16 DSP48E1): about 80 DSP48E1 in all (the K26's DSP48E2 27 x 18 needs 2 x 2 blocks per real multiplier above 18 bits as well: about the same); RAMs: ring 1024 x 32 bits, filter 1024 x 48 bits, FIFO 1024 x 32 bits, the two FFTs' delay lines (about 1023 words of up to 54 bits) and reorder buffers (2 x 2048 words of 26 and 54 bits): about 90 RAMB18 in all; 6 to 10 k LUT; expected Fmax 200 to 300 MHz (the 26 x 24 multipliers are the critical path)
  - K26 (xck26): as a7 with DSP48E2; URAM for the larger memories; Fmax 350 to 500 MHz expected

## Interface contract

Written without knowing the design the block will sit in (brief 139a, owner decision 24): this is what a user can rely on and must provide.

- Protocol: AXI4-Stream slave (samples), AXI4-Stream master (filtered samples, full back-pressure: tvalid, tdata held until tready), AXI4-Lite slave (32-bit registers, one outstanding transaction per channel). Register map: 0x00 ID (RO, 0x46435631), 0x04 CFG0 (RO: [4:0] LOGN, [15:8] W, [31:16] L), 0x08 CFG1 (RO: [7:0] WH, [15:8] FH, [19:16] GB), 0x0C STATUS ([0] BUSY RO, [1] DROPPED sticky W1C, [2] SAT sticky W1C), 0x10 BLOCKS (RO, blocks started), 0x14 COEF_ADDR (RW, [LOGN-1:0]), 0x18 COEF_RE (RW, WH bits), 0x1C COEF_IM (RW; a write commits {COEF_RE, value} at COEF_ADDR when BUSY is 0 and increments COEF_ADDR). Byte address bits [1:0] are ignored; addresses 0x20 and above are unmapped (read 0 with SLVERR, write SLVERR); writes to read-only registers and writes with wstrb other than 4'b1111 get SLVERR and change nothing; a refused commit gets SLVERR, sets DROPPED and does not advance COEF_ADDR; reads have no side effects; reads of STATUS clear nothing
- Throughput: B input samples per B + N clocks on average with no stalls (the input is accepted for B clocks, then paused for N + 1 clocks while the block is fed to the transform), so B / (B + N) samples per clock: for N = 1024 and L = 129 (B = 896) 0.47 samples per clock; a block can start only when the output FIFO has room for its B results (the sink must drain B words per block)
- Latency: 2 * (2 * N + LOGN + ((LOGN - 1) // 2) * (TWSTAGES + MULSTAGES + 1)) + MULSTAGES + L + 7 clocks: the forward and the inverse transform's natural-order latency each, the spectral product's pipeline, the L - 1 dropped words, the feed and the output FIFO
- Reset: aresetn low for at least one clock: the controller, the FFTs' control, the register file and the output FIFO are cleared; for the next N clocks the ring and the filter memory are cleared (s_axis_tready low, STATUS.BUSY 1); the filter is then zero; the histories are zero; a block in flight is lost
- Clock: one clock, rising edge, no clock enable
- Stalls: the input stream is paused (tready low) outside the collect phase; the output stream is stalled by the sink without loss: a block does not start until its results fit in the output FIFO; the FFT pipelines themselves are never stalled

## Integration

- Port timing: every output comes from a register (m_axis_*, s_axil_*) or a decode of the controller's state register (s_axis_tready: one 2-bit compare); no combinational path from any input valid to any output. The longest paths are the two FFTs' complex multipliers and the spectral product (MULSTAGES 3 lets the DSP blocks absorb their registers) and the saturation comparators in front of the FIFO
- Constraints to carry: one clock, no multicycle paths. RAMs: the ring (N x 2W bits, one write port, one read port), the filter memory (N x 2WH, a write port from the register file and a read port), the output FIFO (N x 2W, one write port, one read port) and the FFTs' reorder buffers and delay lines. The protocol checkers (axis_checker.sv, axil_checker.sv) sit between `ifndef SYNTHESIS lines and are not part of the design. The AXI4-Lite interface is 6 address bits wide (the 0x00 to 0x3C window); connect it to an interconnect that decodes the block's base address
- Verification after integration: rerun the packaged harness against your instance ([harness/README.md](harness/README.md)); it needs no other file of this repository.

## What a user could guess wrong

- the output is NOT delayed by the filter's group delay only: the latency is the whole block's: about 4N clocks from the last input sample of a block to the first output of that block, and the output of the LAST B - 1 or fewer input samples stays inside the block controller until the block fills: to see the tail of a stream, send zeros to complete the block. The throughput is B / (B + N) samples per clock, not one sample per clock
- s_axis_tready is LOW for the first N clocks after reset (the ring and the filter memory are cleared), for N + 1 clocks after every B-th sample while the block is fed to the transform, and while the output FIFO lacks room for the block's B results; a source must not assume that it can stream continuously, and a sink that does not drain B words per block throttles the input
- the filter spectrum must be written in NATURAL bin order (k = 0 .. N - 1, the DFT of the zero-padded taps), as signed WH-bit integers scaled by 2**FH; writing the taps themselves is wrong. A REAL filter's spectrum has Hq[N - k] = conj(Hq[k]) but you must write all N bins: the block does not mirror them. COEF_RE must be written BEFORE COEF_IM (the commit is the write to COEF_IM); COEF_ADDR advances by itself, wraps after the last bin, and is not advanced by a refused commit
- a commit while STATUS.BUSY is 1 is refused (SLVERR, DROPPED set), and BUSY is 1 for the whole time a block is in flight: with a continuous stream the filter can almost never be changed; stop the input, wait for BUSY = 0, load, restart. BUSY is also 1 for the first N clocks after reset. Check bresp: a refused commit is also visible only in DROPPED. The filter changes between blocks, never inside one: a commit that is accepted just before a block starts applies to that whole block
- until a filter is loaded the filter is ZERO, not a pass-through: a block of any input gives zeros. The unit impulse is H[k] = 2**FH for every k, which needs WH >= FH + 2
- the absolute gain of the filter, sum of |h|, must be at most 2**GB: a larger gain overflows the inverse transform's WI = W + LOGN + GB bit words and the result wraps silently (not saturated, not flagged: SAT reports only the OUTPUT stage). Choose GB for the largest gain you will ever load, and WH >= FH + GB + 2
- the output is saturated to W bits (exactly as the model), not wrapped, and STATUS.SAT records it; it is a sticky bit: write 1 to bit 2 of STATUS to clear it. Reading STATUS clears nothing
- there is no tlast on either stream and no tkeep or tuser; the output stream has one beat per input sample but delayed by blocks, so the stream boundaries are not preserved; there is no flush input
- tdata is {imaginary, real} with the real part in the LOW W bits (and not padded to bytes); the registers are 32 bits, the filter parts are the low WH bits of the written word (higher bits ignored), and COEF_RE reads back sign-extended; the byte address bits [1:0] are ignored, so 0x1D reads like 0x1C
- the FFTs use the fft_sdf_r22 streaming rule that frames are separated by 0 or at least N/4 idle clocks: the block controller keeps at least B >= N/4 clocks between blocks, which is why L is limited to 3N/4 + 1 (an elaboration-time $error in simulation if L is larger)
- the accuracy is that of the unscaled forward transform, the quantised spectrum and the scaled inverse transform: against numpy.convolve of the unquantised taps the worst output error is a few LSB at W = 16, FH = 14, TW = 18 (verif/results/accuracy.json), larger for a coarser FH, and the error scales with the filter's gain

## Lean, and what is research

Not attempted: the overlap-save identity (circular convolution of a block equals the linear convolution outside the first L - 1 outputs) is checked by the model against numpy.convolve and by the RTL against the model; the register file's handshake rules are checked by the simulation protocol checker and by bounded model checks (formal/jobs.yaml).
