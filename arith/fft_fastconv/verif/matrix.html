Requirements in full

FFC-F-MODEL: The bit-exact model is right

arith/fft_fastconv/model.py gives, for every input, the result that spec.md defines. It agrees with an independent formulation (numpy.convolve of the same samples and the unquantised taps (the overlap-save identity, within the stated bound), the bit-exact FFT models it is built from, and the overlap-save and overlap-add models of arith/fft_common/fastconv.py), and the conventions that a user could guess wrong (spec.md, last section) are pinned by examples.

  • simulation test: pass The model against independent formulations and the pinned conventions: 14 test(s) passed in the recorded run evidence

FFC-F-EXACT: Every variant is bit-exact against the model

At every parameter point listed in spec.yaml (5 directed or exhaustive points, 3 random ones, across 1 variants), each variant's outputs equal the model's: the directed points drive the register defaults, a zero filter (zero output), a filter loaded through the registers and a random stream through it with random stalls on both streams; the random points use random taps, random streams with random stalls, register traffic while the stream runs and a new filter after the stream drains. The whole output stream equals the model bit for bit (no sample lost, added or reordered), the latency from the last input beat of the first block to its first output beat equals the formula, and the three protocol checkers count no error.

  • simulation test: pass Every variant against the model at the small points (Icarus + cocotb): directed or exhaustive stimuli: 5 test(s) passed in the recorded run evidence
  • simulation test: pass Every variant against the model at the large points: random stimuli (Icarus + cocotb): 3 test(s) passed in the recorded run evidence

FFC-F-LAT: Latency is as specified and the bench would notice if it were not

Each variant's latency in clocks is the expression in spec.yaml (os: 2*(2*(1<<LOGN)+LOGN+((LOGN-1)//2)*(TWSTAGES+MULSTAGES+1))+MULSTAGES+L+7), and the bench, run with a latency two clocks off, fails for every variant, so the passing runs prove the latency rather than assume it.

  • simulation test: pass The bench passes at the stated latency and fails two clocks off, for every variant: 1 test(s) passed in the recorded run evidence

FFC-F-EQUIV: The properties named in formal/jobs.yaml hold, by proof where the tools allow

SymbiYosys with the slang front end checks the properties of formal/jobs.yaml: a proof is by k-induction (for all inputs, any run length) at the parameters listed there, a bounded check holds only to its stated depth. What the jobs say is in each job's `claim`; parameters beyond the listed ones are covered by simulation, not by proof.

  • formal: bounded Bounded model checks from an arbitrary state (2 jobs; depths in formal/jobs.yaml): 2 test(s) passed in the recorded run evidence
  • formal: pass Each formal check refutes a planted fault (the check can fail): 6 test(s) passed in the recorded run evidence

FFC-F-PACKAGE: The RTL is lint-clean, and its files agree with the specification and with the Vivado build files

spec.yaml states an interface contract (protocol, throughput, latency, reset, clock, stalls) and integration guidance (port timing, constraints to carry). Every variant passes Verilator -Wall at every point of spec.yaml; its ports and default parameters are the ones spec.yaml states; its header states the intended primitive use before any Vivado run; spec.md is the rendering of spec.yaml; the out-of-context wrapper and the build.yaml for each variant (Artix-7 xc7a100t and K26 xck26, prepared and not run) are current and lint-clean at every point they list, so a Vivado run can start from the repository alone.

  • simulation test: pass spec.yaml against the RTL headers, spec.md against spec.yaml, Verilator -Wall at every point, wrappers and build.yaml current and lint-clean: 5 test(s) passed in the recorded run evidence

FFC-F-AXIL: The AXI4-Lite register file follows the contract's register map and response rules

The ID, CFG0 and CFG1 registers read their documented values; read-only and unmapped addresses answer SLVERR and change nothing; byte address bits [1:0] are ignored; writes with partial strobes are refused with SLVERR and no effect; COEF_ADDR masks its upper bits and wraps; the staging registers read back sign-extended; a commit auto-increments COEF_ADDR and wraps at the last bin; a commit while BUSY (during the clear after reset, and while a block is in flight) is refused with SLVERR, sets DROPPED, does not advance COEF_ADDR and changes nothing; DROPPED and SAT are cleared by writing 1; reads have no side effects; address and data may arrive in either order and the response channels may wait. The AXI4-Lite protocol checker (fft_common/axil_checker.sv) counts no violation. The handshake rules and the response of every executed write are also checked by bounded model checks (formal/jobs.yaml) against shadow state.

  • simulation test: pass The register contract, every access type, with the AXI4-Lite checker: 3 test(s) passed in the recorded run evidence

FFC-F-SAT: Output saturation is exact and reported

With a filter of gain 2**GB and a loud input the output parts that leave the W-bit range are clamped to the nearest end exactly as the model says, STATUS.SAT is set, and it is cleared by writing 1 to it.

  • simulation test: pass A loud input through a filter of gain 2**GB saturates as the model says: 2 test(s) passed in the recorded run evidence

FFC-F-AXIS: The AXI4-Stream rules hold on both streams under random stalls

The checkers on s_axis and m_axis (valid stays high until accepted, tdata stable while stalled, no unknowns after reset) count no violation while both streams stall at random, including a sink so slow that the block controller must wait for output room: no sample is lost, added or reordered. A mutant that makes tvalid depend on tready is killed.

  • simulation test: pass Both streams under random stalls, with the protocol checkers (the random points): 3 test(s) passed in the recorded run evidence

FFC-F-ACCURACY: The filter output equals numpy.convolve within a stated error

For N = 64 to 4096, L from N/8 + 1 to 3N/4 + 1 taps (low-pass, random and delta filters of absolute gain at most 2**GB) and a random complex stream, the output of the model (which the RTL equals bit for bit) differs from numpy.convolve of the same samples and the unquantised taps by at most the recorded error (verif/results/accuracy.json: worst and rms error in output LSB, SQNR) at W = 16, TW = 18, WH = 24, FH = 14; the test enforces a worst error of at most 8 LSB.

  • simulation measurement: pass Error against numpy.convolve at every recorded point (the record of the last run): worst_lsb_max = 3.566; sqnr_db_min = 44.5; points = 16 evidence

FFC-F-HARNESS: The packaged harness runs standalone, passes on the repository's variants and catches faults

arith/fft_fastconv/harness/ (model, bench, SystemVerilog checkers, coverage targets, standalone runner: owner decision 24) needs no other file of the repository. Run against each variant of this function with the checkers beside it, in every mode, it passes and meets every coverage target; against one planted fault (a mutant of verif/mutants.yaml), or with a latency two clocks off, it fails; its model, bench and checker files are the repository's own, generated by arith/tools/gen_harness_fft.py, so they cannot drift.

  • simulation test: pass The harness against the repository's variants, a planted fault and a wrong latency: 3 test(s) passed in the recorded run evidence
