# Verification harness for fft_fastconv (Fast convolution FIR filter (overlap-save on the streaming FFT, AXI4-Stream data, AXI4-Lite coefficients))

Generated by `python -m arith.tools.gen_harness_fft` (arith brief 161); the handwritten parts are `chk_top.sv` and `coverage.yaml`. This folder is a deliverable: rerun it against your own instance after you integrate or change the block. It needs nothing else from the repository.

## What is in it

| File | What |
|---|---|
| `model.py` and its support (`fft_ref.py`, `fastconv.py`) | the bit-exact model of the specification ([../spec.md](../spec.md)), in Python integers |
| `bench.py`, `frames.py`, `fcover.py`, `fft_fastconv_cocotb.py` | the cocotb bench: drives frames or streams (directed stimuli: impulses, tones, corner values; random ones; the stalls and gaps the contract permits), compares every output with the model bit for bit and checks the latency |
| `assertions.sv` | passive SystemVerilog checkers (simulation only): the AXI4-Stream handshake rules on both streams and the AXI4-Lite handshake and response rules on the register interface. Their error counters must stay 0 |
| `chk_top.sv` | your instance with those checkers beside it, used by `run_harness.py --checker` |
| `coverage.yaml` | the coverage targets (events the stimulus must produce, with minimum counts); `run_harness.py` fails a full run that misses one |
| `run_harness.py` | the standalone runner (Icarus Verilog + cocotb) |

## Running it against your instance

Needs `iverilog`, Python 3, `pip install cocotb==2.0.1 pyyaml numpy`.

```
python3 run_harness.py --rtl my_fft_fastconv.sv --top my_module --variant os --params '{"LOGN": 6, "L": 17, "W": 16, "TW": 16, "WH": 20, "FH": 12, "GB": 1, "RND": 1, "CMUL": 4, "TWSTAGES": 1, "MULSTAGES": 2}' --latency 310 --mode all --checker
```

- `--top` must have the ports listed in the specification under the same names, and every parameter of the specification (pass them all in `--params`; the model is built from them).
- `--latency` is your instance's latency in clocks as the specification defines it. Giving a wrong latency fails the run: that is deliberate, it checks the number. The latency of this block's variants (`os`) is stated in `../spec.yaml` as a formula.
- `--mode` is one of `all` (default) or `directed`, `randomised`, `axil`, `saturate`: the modes are the benches of the repository's own tests (stimuli, schedules and checks described in `fft_fastconv_cocotb.py`).
- `--checker` builds your instance next to `assertions.sv`; the run fails if a checker counts a violation. To use the checkers in your own bench instead, instantiate them with the same signals as in `chk_top.sv`.
- Exit status 0 means: every output matched the model, the latency and the checkers were as specified, and (mode `all`) every coverage target was met. `--build-dir` keeps the logs and the coverage files.

## Interface the harness assumes

- Protocol: AXI4-Stream slave (samples), AXI4-Stream master (filtered samples, full back-pressure: tvalid, tdata held until tready), AXI4-Lite slave (32-bit registers, one outstanding transaction per channel). Register map: 0x00 ID (RO, 0x46435631), 0x04 CFG0 (RO: [4:0] LOGN, [15:8] W, [31:16] L), 0x08 CFG1 (RO: [7:0] WH, [15:8] FH, [19:16] GB), 0x0C STATUS ([0] BUSY RO, [1] DROPPED sticky W1C, [2] SAT sticky W1C), 0x10 BLOCKS (RO, blocks started), 0x14 COEF_ADDR (RW, [LOGN-1:0]), 0x18 COEF_RE (RW, WH bits), 0x1C COEF_IM (RW; a write commits {COEF_RE, value} at COEF_ADDR when BUSY is 0 and increments COEF_ADDR). Byte address bits [1:0] are ignored; addresses 0x20 and above are unmapped (read 0 with SLVERR, write SLVERR); writes to read-only registers and writes with wstrb other than 4'b1111 get SLVERR and change nothing; a refused commit gets SLVERR, sets DROPPED and does not advance COEF_ADDR; reads have no side effects; reads of STATUS clear nothing
- Throughput: B input samples per B + N clocks on average with no stalls (the input is accepted for B clocks, then paused for N + 1 clocks while the block is fed to the transform), so B / (B + N) samples per clock: for N = 1024 and L = 129 (B = 896) 0.47 samples per clock; a block can start only when the output FIFO has room for its B results (the sink must drain B words per block)
- Latency: 2 * (2 * N + LOGN + ((LOGN - 1) // 2) * (TWSTAGES + MULSTAGES + 1)) + MULSTAGES + L + 7 clocks: the forward and the inverse transform's natural-order latency each, the spectral product's pipeline, the L - 1 dropped words, the feed and the output FIFO
- Reset: aresetn low for at least one clock: the controller, the FFTs' control, the register file and the output FIFO are cleared; for the next N clocks the ring and the filter memory are cleared (s_axis_tready low, STATUS.BUSY 1); the filter is then zero; the histories are zero; a block in flight is lost
- Clock: one clock, rising edge, no clock enable
- Stalls: the input stream is paused (tready low) outside the collect phase; the output stream is stalled by the sink without loss: a block does not start until its results fit in the output FIFO; the FFT pipelines themselves are never stalled

## What the harness does not cover

- Timing, area and power: nothing here is a Vivado result. The harness checks function against the model, the interface rules and the stated latency, in simulation only.
- A reset in the middle of a frame or a block, and parameter combinations outside the points of `../spec.yaml` (the model supports them; the harness is run at the points you give it).
- The checkers are immediate assertions evaluated on the clock edge, not concurrent SVA properties (the open-source simulator does not run those).
