# Verification harness for the exp2 (Base-2 exponential of a fraction, 2**x for x in [0, 1))

Generated by `python -m arith.tools.gen_harness` (arith brief 139d); the handwritten parts are `assertions.sv`, `chk_top.sv` and `coverage.yaml`. This folder is a deliverable: rerun it against your own instance after you integrate or change the block. It needs nothing else from the repository.

## What is in it

| File | What |
|---|---|
| `model.py` | the bit-exact model of the specification ([../spec.md](../spec.md)), in Python integers |
| `bench.py`, `exp2_cocotb.py`, `harness_common.py` | the cocotb bench: drives one vector per clock (exhaustive at small widths; edge values, runs of ones and random inputs at large ones) and compares every output bit with the model, allowing for your latency |
| `assertions.sv` | a passive SIMULATION checker with the exact function in real arithmetic (the simulator's `$sin`, `$atan2`, `$pow`, `$ln`, `$hypot`) and an error bound in last places; put it beside your instance in your own bench or in the simulator of your choice; its `errors` counter is 0 when the instance is within the bound |
| `chk_top.sv` | your instance with the checker beside it, used by `run_harness.py --checker` |
| `coverage.yaml` | the coverage targets (bins over the inputs and the model's results, with minimum hit counts) that the stimulus must reach; `run_harness.py` fails if one is missed |
| `run_harness.py` | the standalone runner (Icarus Verilog + cocotb) |

## Running it against your instance

Needs `iverilog`, Python 3, `pip install cocotb==2.0.1 pyyaml`.

```
python3 run_harness.py --rtl my_exp2.sv --top my_module --params '{"IW": 12, "OW": 12, "SB": 5}' --latency 2 --variant lerp --mode both --checker
```

- `--top` must have the ports listed in the specification under the same names, and the parameters you pass in `--params` (the harness needs the widths and signedness to build the model).
- `--latency` is your instance's latency in clocks. Giving a wrong latency fails the run: that is deliberate, it checks the number.
- `--variant` names the variant of this library whose model (`model.py`, `model.compute`) your instance is compared with, bit for bit: the variants of this function are not bit-identical to each other, so pass the one yours is, or accept that only the checker's error bound will agree.
- `--err-ulp` sets the checker's error bound in last places; the default is the variant's measured maximum at your parameters plus 0.05 (every input is scanned), or for atan2_mag at W above 7 the maximum over a sample plus 0.25. State your own bound to hold an instance of your own to the accuracy you need.
- `--mode exhaustive` is for small widths only (about 12 operand bits); `randomised` for any width; `both` runs both.
- `--checker` builds your instance next to `assertions.sv`; the run fails if the checker's error counter is not 0. To use the checker in your own bench instead, instantiate it with the same signals as in `chk_top.sv`.
- Exit status 0 means: every vector matched the model, the checker saw no mismatch, and every coverage target was met. `--build-dir` keeps the logs and `coverage.json`.

## Interface the harness assumes

- Protocol: plain registered-or-combinational ports, no handshake: x is sampled every clock and one result leaves, with no valid, ready or backpressure. A caller that needs a valid bit delays its own valid by the variant's latency
- Throughput: one result per clock in every variant (initiation interval 1)
- Latency: per variant, in clocks: table REG (0 or 1), lerp 2, poly2 3, cordic NIT + 1
- Reset: none: no control state; the pipelines hold data only and their outputs are meaningless for latency clocks after power-up
- Clock: one clock, rising edge, no clock-enable and no gating; clk is present but unused when the latency is 0

Parameter names used by the variants of this library (your instance needs the ones the model uses; the others are ignored by the model):

- `IW`: bits of x; table: at most 8; lerp and poly2: more than SB; cordic: IW + 20 > OW + G
- `OW`: bits of y (the result's fractional bits)
- `REG`: table only: 1 registers the output (latency 1), 0 is combinational
- `SB`: lerp (3 to 6) and poly2 (3 to 5): bits of x that select the segment, 2**SB segments
- `NIT`: cordic: iterations (stages), counting the two repeated ones
- `G`: cordic: guard bits below the last place of y; OW + G <= 24

## What it does not check

Timing, power, area and clocking (those are Vivado's), behaviour for parameter values outside the ranges in the specification, X-propagation beyond the first compare, and anything about the surrounding design (handshakes, valid bits, your reset sequencing). A pass shows the instance computes the specified function with the stated latency at the parameters you ran; run it at each parameter set you instantiate.
