Requirements in full

EXP-F-MODEL: The bit-exact model is right

arith/exp2/model.py gives, for every input, the result that spec.md defines. It agrees with an independent formulation (exact rational (Fraction) evaluations of the interpolation and Horner formulas, a floating-point hyperbolic CORDIC, and the maths library's 2**x) on every input at small widths and with Python's integer arithmetic on random large-width inputs, and the conventions that a user could guess wrong (spec.md, last section) are pinned by examples.

  • simulation test: pass The model against independent formulations (exhaustive small, random large) and the pinned conventions: 8 test(s) passed in the recorded run evidence

EXP-F-EXACT: Every variant is bit-exact against its own model

At every parameter point listed in spec.yaml (24 exhaustive points, 12 random ones, across 4 variants), each variant's outputs equal its own model's (model.py, selected by variant) in every clock: every input is driven at the small points; edge values, table break points and random inputs at the large ones. The variants round differently and are not bit-identical to each other; the model of each is the bit-exact definition of that variant, and its distance from the exact function is the accuracy requirement.

  • simulation test: pass Every variant against the model, every input, at the small points (Icarus + cocotb): 24 test(s) passed in the recorded run evidence
  • simulation test: pass Every variant against the model at the large points: edge values, carry runs and random inputs (Icarus + cocotb): 12 test(s) passed in the recorded run evidence

EXP-F-ACC: The error against the exact function is within the stated bound, at every listed point

Each of the 12 accuracy points of spec.yaml states a bound in last places; the model's error against the exact function (the maths library, real arithmetic, unrounded) over EVERY input of that point is at most the bound and within 0.06 of it (so the bound is neither false nor loose). A point not listed has no stated bound.

  • simulation test: pass The model's error against the exact function over every input of every listed point, against the stated bounds: 12 test(s) passed in the recorded run evidence

EXP-F-LAT: Latency is as specified and the bench would notice if it were not

Each variant's latency in clocks is the expression in spec.yaml (table: REG; lerp: 2; poly2: 3; cordic: NIT + 1), and the bench, run with a latency two clocks off, fails for every variant, so the passing runs prove the latency rather than assume it.

  • simulation test: pass The bench passes at the stated latency and fails two clocks off, for every variant: 4 test(s) passed in the recorded run evidence

EXP-F-EQUIV: The error against the exact function is bounded for all inputs, by proof, at a small input width

SymbiYosys with the slang front end compares each variant, delayed by its latency, with the exact function on 8 input bits to 24 fractional bits (a reference ROM written from the maths library, formal/*_ref.sv) and asserts the error stays within the bound of the job, which is the model's measured error at that point plus one unit for the reference's own rounding. A proof is by k-induction (for all inputs, any run length) at the widths in formal/jobs.yaml; wider points are covered by the exhaustive scan of the accuracy requirement and by simulation, not by proof. The quadrant map and the variants' structural identities are inside the checks.

  • formal: pass k-induction proofs of the variants' error bounds against the exact function (7 jobs; widths in formal/jobs.yaml): 7 test(s) passed in the recorded run evidence
  • formal: pass Each formal check refutes a planted fault (the check can fail): 4 test(s) passed in the recorded run evidence

EXP-F-BENCH: The bench catches seeded faults

Every one of the mutants in verif/mutants.yaml (one exact text change each, in the variant's RTL: an inverted condition, a wrong constant, a dropped connection, a lost reset) makes the cocotb bench fail; mutants that survive or do not build are reported, never hidden.

  • simulation test: pass The mutation run as a test: no mutant survives, none fails to build: 1 test(s) passed in the recorded run evidence
  • simulation measurement: pass Mutants killed of valid mutants (the record of the last full run): survived = []; invalid = []; valid = 28; score_pct = 100 evidence

EXP-F-HARNESS: The packaged verification harness is a standalone deliverable that works

arith/exp2/harness holds the model, the cocotb bench, a SystemVerilog checker, coverage targets and a runner that needs nothing else from the repository. Run standalone against every variant (one small exhaustive point and one large random point each, with the checker beside the instance) it passes and the random runs meet every coverage target; run against a planted fault it fails, with and without the checker. Its generated files are the repository's own bench, so they cannot drift.

  • simulation test: pass The packaged harness run standalone on every variant (with the checker and the coverage targets) and on a planted fault: 10 test(s) passed in the recorded run evidence

EXP-F-PACKAGE: The RTL is lint-clean, and its files agree with the specification and with the Vivado build files

spec.yaml states an interface contract (protocol, throughput, latency, reset, clock, stalls) and integration guidance (port timing, constraints to carry). Every variant passes Verilator -Wall at every point of spec.yaml; its ports and default parameters are the ones spec.yaml states; its header states the intended primitive use before any Vivado run; spec.md is the rendering of spec.yaml; the out-of-context wrapper and the build.yaml for each variant (Artix-7 xc7a100t and K26 xck26, prepared and not run) are current and lint-clean at every point they list, so a Vivado run can start from the repository alone.

  • simulation test: pass spec.yaml against the RTL headers, spec.md against spec.yaml, Verilator -Wall at every point, wrappers and build.yaml current and lint-clean: 6 test(s) passed in the recorded run evidence

EXP-F-LEAN-LERP: Linear interpolation stays between the segment's end values, for every width

In a rising segment with break-point value c0 and slope s, the interpolated value (c0 * 2^D + s * d) / 2^D lies between c0 and c0 + s for every position d below 2^D and every D: the table variant cannot overshoot its segment. The statement is the specification and is NOT approved by a human (verif/lean_approvals.yaml is empty), so the proof is shown but not counted as verification. The Lean text is a hand transcription of the RTL's structure; it models no timing or clocking.

  • Lean proof (all widths): statement not approved Linear interpolation stays between the segment's end values: statement not approved; ArithLerp.lerp_between: kernel only; proof of the transcription, transcription not tested; recorded build (not re-run) evidence

EXP-F-LEAN-LERP-MONO: Linear interpolation does not fall as the position grows, for every width

Within a segment of non-negative slope the interpolated value is non-decreasing in the position d, for every D, c0 and s. The statement is the specification and is NOT approved by a human (verif/lean_approvals.yaml is empty), so the proof is shown but not counted as verification. The Lean text is a hand transcription of the RTL's structure; it models no timing or clocking.

  • Lean proof (all widths): statement not approved Linear interpolation does not fall as the position grows: statement not approved; ArithLerp.lerp_mono: kernel only; proof of the transcription, transcription not tested; recorded build (not re-run) evidence

EXP-F-LEAN-HYP: A hyperbolic CORDIC step scales x^2 - y^2 by a constant, for every width

For every direction d = +-1 and every shift (scaled by u = 2^i), the step (u x + d y, u y + d x) multiplies x^2 - y^2 by exactly u^2 - 1, whatever the data: the hyperbolic gain is a data-independent constant. The statement is the specification and is NOT approved by a human (verif/lean_approvals.yaml is empty), so the proof is shown but not counted as verification. The Lean text is a hand transcription of the RTL's structure; it models no timing or clocking.
