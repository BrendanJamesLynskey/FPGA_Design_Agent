# Base-2 exponential of a fraction, 2**x for x in [0, 1) (arith/exp2)

Generated by `python -m arith.tools.gen_spec_md` from [spec.yaml](spec.yaml); edit the YAML, not this file. Part of the arithmetic library of brief 139d ([../README.md](../README.md)).

y = 2**x for an unsigned IW-bit fraction x in [0, 1), the result as 1 + y / 2**OW (the leading one is implicit). Four implementations trade BRAM, DSP, LUTs, latency and accuracy: a direct table (exact to half a last place, at most 8 input bits), a segment table with linear interpolation (one DSP, about 2 to 4 last places at 16 bits), a segment table with a quadratic (two DSPs, about 0.6 last places) and a hyperbolic CORDIC (no DSP and no BRAM, a stage per iteration, about 1 last place). The general exp and 2**x for any x are this core plus a range reduction that the caller owns (see Integration).

## Function

- x is read as the fraction x / 2**IW in [0, 1); y is read as the fraction y / 2**OW in [0, 1); the function is 2**(x / 2**IW) = 1 + y / 2**OW
- y is the variant's own arithmetic result rounded to nearest, ties upward, and clamped to [0, 2**OW - 1]; it is never wrapped
- table: y = round(T[x] / 2**(20 - OW)) where T is a 256-entry table of the exact function with 20 fractional bits, read at x * 2**(8 - IW) (so IW <= 8)
- lerp: the top SB bits of x pick a segment; with the table's value c0 and slope s1 (both 20 fractional bits, exact at the segment ends) and the position d in the segment (DB = IW - SB bits), y = round((c0 * 2**DB + s1 * d) / 2**(20 + DB - OW))
- poly2: the same segments with a quadratic a0 + a1 t + a2 t**2 (t = d / 2**DB) fitted at the three Chebyshev nodes of the segment; Horner in integers: p1 = (a2 d) >> DB (floor), q = a1 + p1, y = round((q d + a0 * 2**DB) / 2**(20 + DB - OW))
- cordic: z = round(x * ln 2) in units of 2**-(OW + G); NIT hyperbolic rotations (shifts 1, 2, 3, 4, 4, 5, ..., 13, 13, 14, ...; 4 and 13 are repeated) drive z to 0 starting from (x, y) = (1 / gain, 0); e**z = x + y; y = round((x + y - 1) / 2**G)
- the four models differ in their rounding steps, so the variants are NOT bit-identical to each other; each variant is bit-exact against its own model (model.py) and within the stated error of the exact function

Signedness: x and y are unsigned.

Exactness: not exact: every variant is within the error stated in 'Accuracy' of the exact 2**x, which includes the rounding of y; the table variant is within half a last place plus the table's own rounding of 2**-21 of the function (0.03 last places at OW = 16, 0.0005 at OW = 8); the others are bit-exact against their own model but not against each other.

Latency: clocks from x being presented to y being valid: table REG, lerp 2, poly2 3, cordic NIT + 1; throughput is one result per clock in every variant.

## Accuracy

Error is |y - 2**x ideal| in units of the last place of y (2**-OW), with the ideal 2**(x / 2**IW) - 1 taken in real arithmetic and not rounded, so a perfectly rounded result has error 0.5. The bound of each listed point is a measured maximum over every input of that point (python -m pytest arith/exp2/tests/test_exp2_accuracy.py), rounded up to 0.01. The error depends on the parameters: lerp falls with 4x per extra SB; poly2 and the table sit near 0.5 to 0.65 once SB and the coefficient precision (20 bits) allow; cordic falls with NIT and G until the rounding of the table constants (about 1 last place at OW = 16). A point not listed has no stated bound: measure it with model.max_error.

### Intended primitive use

- `table`, Artix-7 (xc7a100t): 0 DSP; one 256 x 20 ROM: a 36 Kb BRAM (RAMB36E1 in 18 Kb mode, output register absorbed when REG = 1) or about 100 to 150 LUT6 as distributed ROM; one 21-bit rounding adder; OW FFs when REG = 1
  - K26 (xck26): 0 DSP; as a7 with RAMB36E2 or LUT ROM; CARRY8 for the adder
- `lerp`, Artix-7 (xc7a100t): 1 DSP48E1 (22 x (IW - SB + 1) signed multiply-add); the 2**SB x 44-bit coefficient ROM in distributed RAM (a few dozen LUTs for SB <= 5; possibly a BRAM at SB = 6); about 3 x 22 FFs for the two stages (some absorbed by the DSP)
  - K26 (xck26): 1 DSP48E2; as a7
- `poly2`, Artix-7 (xc7a100t): 2 DSP48E1 (22 x DB then 24 x DB signed multiplies); a 2**SB x 66-bit coefficient ROM in distributed RAM (SB <= 5); about 3 x 24 FFs of stage registers (some absorbed by the DSPs)
  - K26 (xck26): 2 DSP48E2; as a7
- `cordic`, Artix-7 (xc7a100t): 0 BRAM; the x * ln 2 constant multiplier (IW x 21 bits: LUT adders or 1 to 2 DSP48E1); per stage 3 add/subtract (about OW + G + 3 LUTs each in carry chains) and 3 registers of OW + G + 3, OW + G + 3 and OW + G + 2 bits; about 3 x NIT x (OW + G + 3) LUTs in total
  - K26 (xck26): as a7 with CARRY8 chains

## Interface contract

Written without knowing the design the block will sit in (brief 139d, owner decision 24): this is what a user can rely on and must provide.

- Protocol: plain registered-or-combinational ports, no handshake: x is sampled every clock and one result leaves, with no valid, ready or backpressure. A caller that needs a valid bit delays its own valid by the variant's latency
- Throughput: one result per clock in every variant (initiation interval 1)
- Latency: per variant, in clocks: table REG (0 or 1), lerp 2, poly2 3, cordic NIT + 1
- Reset: none: no control state; the pipelines hold data only and their outputs are meaningless for latency clocks after power-up
- Clock: one clock, rising edge, no clock-enable and no gating; clk is present but unused when the latency is 0
- Stalls: none: the pipeline cannot be frozen (no enable)

| `lerp` | `2` | 1 per clock |

## Integration

- Port timing: x goes straight to a ROM address (table, lerp, poly2) or to a constant multiplier (cordic): register x in the caller if it comes from logic. y leaves a register (every variant but the table with REG = 0, and cordic whose output rounding is a short adder after the last stage). table with REG = 1 is a BRAM-friendly read: the ROM output register is the output register. lerp and poly2 put the ROM output in a register before the multiplier, so the DSP is fed by flip-flops
- Constraints to carry: no multicycle or false paths, one clock. DSP variants: keep the register stages un-merged so the DSP's AREG/BREG/MREG/PREG can absorb them (no keep or retiming that moves them). For a range other than [0, 1): exp(x) = 2**(x * log2 e); write x * log2 e = n + f with n an integer and f in [0, 1) (a constant multiplier and a split at the binary point), take 2**f from this core, and shift the result left by n after adding the implicit one back (1 + y / 2**OW); a negative n shifts right. That range reduction is the caller's: this core's contract stops at [0, 1)
- Verification after integration: rerun the packaged harness against your instance ([harness/README.md](harness/README.md)); it needs no other file of this repository.

## What a user could guess wrong

- the leading one is implicit: 2**x = 1 + y / 2**OW, so y has OW fraction bits and the true result has OW + 1 bits; with x = 0 the result is y = 0 meaning exactly 1
- x is a fraction of one, not an integer: x = 2**(IW - 1) means 0.5 and the result 2**0.5 = 1.4142
- the error is not 0.5 ulp for every variant: only the table variant (and poly2 at a good SB) is near it; lerp is several last places at 16 bits and cordic about 1; read the accuracy table of the variant before choosing
- the variants are not bit-identical to each other (different rounding steps): switching variant changes the low bits of y, and a downstream check built on one variant's output will not hold bit for bit on another
- x = 2**IW - 1 is the largest input and gives a result just below 2; the function does not wrap or saturate there, but y is clamped at 2**OW - 1 if rounding reaches it
- table reads a 256-entry table whatever IW is (a narrower IW uses every 2**(8 - IW)-th entry), and IW above 8 is not supported by it; REG other than 0 or 1 behaves as 1
- the parameter ranges (SB inside 3 to 6 for lerp and 3 to 5 for poly2, SB < IW, NIT 4 to 24, OW + G <= 24, IW + 20 > OW + G for cordic) are documented, not enforced by assertions: a value outside them gives wrong results without a message
- no reset and no valid: for latency clocks after power-up the output is not meaningful; there is no clock-enable
