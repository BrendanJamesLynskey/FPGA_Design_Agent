Requirements in full

FPFMA-F-MODEL: The bit-exact model is right

arith/fp_fma/model.py gives, for every input, the result that spec.md defines. It agrees with an independent formulation (an enumeration of every finite value of a tiny format (the nearest one, ties to even), the multiplier and adder models, and the identities a * 1 + c = c + a and a * b + 0 = a * b) on every input at small widths and with Python's integer arithmetic on random large-width inputs, and the conventions that a user could guess wrong (spec.md, last section) are pinned by examples.

  • simulation test: pass The model against independent formulations (exhaustive small, random large) and the pinned conventions: 17 test(s) passed in the recorded run evidence

FPFMA-F-EXACT: Every variant is bit-exact against the model

At every parameter point listed in spec.yaml (11 exhaustive points, 11 random ones, across 2 variants), each variant's outputs equal the model's in every clock: every input is driven at the small points; edge values, runs of ones, and random inputs at the large ones. The function is exact, so there is no error bound.

  • simulation test: pass Every variant against the model, every input, at the small points (Icarus + cocotb): 11 test(s) passed in the recorded run evidence
  • simulation test: pass Every variant against the model at the large points: edge values, carry runs and random inputs (Icarus + cocotb): 11 test(s) passed in the recorded run evidence

FPFMA-F-LAT: Latency is as specified and the bench would notice if it were not

Each variant's latency in clocks is the expression in spec.yaml (fused: STAGES; cascade: STAGES_M + STAGES_A), and the bench, run with a latency two clocks off, fails for every variant, so the passing runs prove the latency rather than assume it.

  • simulation test: pass The bench passes at the stated latency and fails two clocks off, for every variant: 2 test(s) passed in the recorded run evidence

FPFMA-F-EQUIV: The variants are equivalent to a plain reference, by proof where the tools allow

SymbiYosys with the slang front end checks the variants against each other and a plain reference (a single `+` or `*`, or the specification written as RTL). The jobs in formal/jobs.yaml name the widths; a proof is by k-induction (for all inputs, any run length) at the widths listed there, a bounded check holds only to its stated depth. Widths beyond the listed ones are covered by simulation, not by proof.

  • formal: pass k-induction proofs of the variants against the reference (5 jobs; widths in formal/jobs.yaml): 5 test(s) passed in the recorded run evidence
  • formal: pass Each formal check refutes a planted fault (the check can fail): 6 test(s) passed in the recorded run evidence

FPFMA-F-HARNESS: The packaged verification harness is a standalone deliverable that works

arith/fp_fma/harness holds the model, the cocotb bench, a SystemVerilog checker, coverage targets and a runner that needs nothing else from the repository. Run standalone against every variant (one small exhaustive point and one large random point each, with the checker beside the instance) it passes and the random runs meet every coverage target; run against a planted fault it fails, with and without the checker. Its generated files are the repository's own bench, so they cannot drift.

  • simulation test: pass The packaged harness run standalone on every variant (with the checker and the coverage targets) and on a planted fault: 6 test(s) passed in the recorded run evidence

FPFMA-F-LEAN-CARRY: Rounding increment carries into the exponent, for every width

For a packed pattern e * m + f with fraction f < m (m = 2^MAN), adding the rounding increment 1 either raises the fraction by one or, when the fraction is all ones, raises the exponent by one and leaves a zero fraction: the identity fp_pack's single add on the packed {exponent, fraction} pattern rests on, so a significand overflow, a subnormal rounding up to the smallest normal number and a largest finite number rounding up to infinity need no special case. The statement is the specification and is NOT approved by a human (verif/lean_approvals.yaml is empty), so the proof is shown but not counted as verification. The Lean text is a hand transcription of the RTL's structure; it models no timing or clocking.

  • Lean proof (all widths): not run Rounding increment carries into the exponent: no recorded build for this theorem; run `python -m flow.trace_v1 lean-record` evidence

FPFMA-F-LEAN-NORM: Normalising left by NW - 1 - msb puts the leading one at the top, for every width

For a value v with its leading one at bit k (2^k <= v < 2^(k+1)) and k < NW, shifting left by NW - 1 - k places gives a value in [2^(NW-1), 2^NW): the leading one is at bit NW - 1, which is what fp_norm's count lz = NW - 1 - msb does. The statement is the specification and is NOT approved by a human (verif/lean_approvals.yaml is empty), so the proof is shown but not counted as verification. The Lean text is a hand transcription of the RTL's structure; it models no timing or clocking.

  • Lean proof (all widths): not run Normalising left by NW - 1 - msb puts the leading one at the top: no recorded build for this theorem; run `python -m flow.trace_v1 lean-record` evidence

FPFMA-F-LEAN-RNE: The rounding decision is round-to-nearest, ties to even, for every width

For a kept part hi and a discarded part lo below the threshold 2h, incrementing hi exactly when lo > h, or lo = h and hi is odd (the guard-and-sticky rule of fp_pack), gives a value within h of the exact one and, when it is exactly h away, even. The statement is the specification and is NOT approved by a human (verif/lean_approvals.yaml is empty), so the proof is shown but not counted as verification. The Lean text is a hand transcription of the RTL's structure; it models no timing or clocking.
