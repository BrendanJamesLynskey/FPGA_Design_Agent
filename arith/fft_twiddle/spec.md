# Twiddle-factor generator (quarter-wave ROM) (arith/fft_twiddle)

Generated by `python -m arith.tools.gen_spec_md` from [spec.yaml](spec.yaml); edit the YAML, not this file. Part of the frequency-domain suite of brief 148 ([../README.md](../README.md)).

For an index m of a circle of 2**LOGC points (LOGC 2 to 12), (wr, wi) = (cos, -sin) of 2 pi m / 2**LOGC as signed TW-bit numbers of scale 2**(TW-2), so exp(-j 2 pi m / 2**LOGC) = (wr + j wi) / 2**(TW-2). One quarter-wave table of cos(2 pi i / 4096), i = 0 .. 1024, 30 fractional bits, serves every circle size; the quadrant of the index and two reads of the table give cosine and sine. Each table value is rounded half up to TW-2 fractional bits, and negated by the quadrant, so the table is symmetric about zero.

## Function

- the circle has 2**LOGC points and the index m is an unsigned LOGC-bit number; the angle is 2 pi m / 2**LOGC, so a forward transform's twiddle for index m is exp(-j 2 pi m / 2**LOGC) = cos - j sin, which is what (wr, wi) holds
- master table: C[i] = round(cos(2 pi i / 4096) * 2**30) for i = 0 .. 1024, rounded to nearest (computed with 60 decimal digits, so the rounding is exact for these arguments); C[1024] = 0 and C[0] = 2**30
- reading: idx = m * (4096 / 2**LOGC), q = idx / 1024, r = idx mod 1024; the cosine of the first quadrant is C[r] and the sine is C[1024 - r]; the other quadrants fold the same two values with the signs of cos and sin there (q = 1: cos = -S, sin = C; q = 2: cos = -C, sin = -S; q = 3: cos = S, sin = -C, with C = C[r], S = C[1024 - r])
- rounding: each master value is rounded half up to TW-2 fractional bits, (C + 2**(SH-1)) >> SH with SH = 30 - (TW - 2), BEFORE the sign is applied; the result is the master value rounded twice (to 30 bits, then to TW-2 bits), so it may differ from the correctly rounded cosine by one unit in the last place in rare cases; the error against the true value is at most 0.5 + 2**-(32-TW) units in the last place (measured in tests/test_fft_twiddle_model.py)
- wr and wi are in scale 2**(TW-2), so +1.0 and -1.0 are exact (they need TW-1 bits plus sign) and so is 0; 1.0 is never clipped

Signedness: wr and wi are signed two's complement; m is unsigned.

Exactness: a table, not a function: for every index the value is the model's, bit for bit (every index of every simulated circle is checked); the error against the real cosine and sine is at most 0.5 + 2**-(32-TW) units in the last place (scale 2**-(TW-2)).

Latency: clocks from m being presented to wr and wi being valid; the ROM is synchronous, so the minimum is 1; throughput is one index per clock.

## Parameters

| Parameter | Constraint | Meaning |
|---|---|---|
| `LOGC` | min 2 | log2 of the number of points of the circle, 2 to 12 |
| `TW` | min 4 | width of wr and wi, 4 to 28 (the master table has 30 fractional bits) |
| `STAGES` | min 1 | 1: the ROM output register only (folding and rounding follow it combinationally); 2: the outputs are registered too |

Written without knowing the design the block will sit in (brief 139a, owner decision 24): this is what a user can rely on and must provide.

## Integration

- Port timing: STAGES 1: the path from the ROM register through the quadrant folding, the rounding adders and the negation to wr and wi is combinational and about TW bits of carry chain deep; STAGES 2 registers it. Present the index one clock ahead of the data it multiplies (STAGES clocks of latency) or delay the data to match
- Constraints to carry: one clock; no multicycle path. The ROM is inferred as distributed or block RAM by the tool; ask for block RAM (ram_style) only after the first Vivado run shows which is smaller
- Verification after integration: this function has no packaged harness (brief 148 left it out; see the report): rerun its bench (tests/) against your instance, which needs the repository's arith/tools and fft_common helpers.

## What a user could guess wrong

- the table is one quarter wave of a 4096-point circle: a circle of 2**LOGC points reads every (4096 / 2**LOGC)-th angle of it; LOGC above 12 is not supported and not rejected by an assertion
- wi is MINUS the sine: (wr + j wi) is exp(-j angle), the forward-transform twiddle; an inverse transform in this suite does not use the conjugate twiddle, it swaps real and imaginary parts around a forward transform
- the scale is 2**(TW-2), not 2**(TW-1): +1.0 is 2**(TW-2) and the representable range is +-2**(TW-1), so a value of magnitude one has a spare bit; a TW-bit twiddle has TW-2 fractional bits
- the rounding is half up, applied to the master value BEFORE the quadrant sign, so the table is exactly symmetric (negation of the positive-quadrant values); it is not round-half-even and it is not the correctly rounded cosine in every case (double rounding via 30 bits)
- the index is unsigned and the angle is 2 pi m / 2**LOGC (m = 0 is angle 0); an index outside 0 .. 2**LOGC - 1 does not exist (it is LOGC bits wide)
- no reset: for STAGES clocks after power-up the outputs are not meaningful

## Lean, and what is research

Not attempted. The table values are numerical constants (rounded cosines) checked against high-precision arithmetic in the model and by exhaustive simulation; a Lean statement would need a real-number cosine, which core Lean (4.36, no Mathlib) does not have.
