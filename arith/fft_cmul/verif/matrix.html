Requirements in full

FCMUL-F-MODEL: The bit-exact model is right

arith/fft_cmul/model.py gives, for every input, the result that spec.md defines. It agrees with an independent formulation (a second formulation (the three-multiplication identity) in Python integers), and the conventions that a user could guess wrong (spec.md, last section) are pinned by examples.

  • simulation test: pass The model against independent formulations and the pinned conventions: 3 test(s) passed in the recorded run evidence

FCMUL-F-EXACT: Every variant is bit-exact against the model

At every parameter point listed in spec.yaml (10 directed or exhaustive points, 10 random ones, across 2 variants), each variant's outputs equal the model's: every input is driven at the small points (4 operands of 2 to 4 bits); edge values and random inputs at the large ones. The function is exact, so there is no error bound.

  • simulation test: pass Every variant against the model at the small points (Icarus + cocotb): directed or exhaustive stimuli: 10 test(s) passed in the recorded run evidence
  • simulation test: pass Every variant against the model at the large points: random stimuli (Icarus + cocotb): 10 test(s) passed in the recorded run evidence

FCMUL-F-LAT: Latency is as specified and the bench would notice if it were not

Each variant's latency in clocks is the expression in spec.yaml (m4: STAGES; m3: STAGES), and the bench, run with a latency two clocks off, fails for every variant, so the passing runs prove the latency rather than assume it.

  • simulation test: pass The bench passes at the stated latency and fails two clocks off, for every variant: 2 test(s) passed in the recorded run evidence

FCMUL-F-EQUIV: The properties named in formal/jobs.yaml hold, by proof where the tools allow

SymbiYosys with the slang front end checks the properties of formal/jobs.yaml: a proof is by k-induction (for all inputs, any run length) at the parameters listed there, a bounded check holds only to its stated depth. What the jobs say is in each job's `claim`; parameters beyond the listed ones are covered by simulation, not by proof.

  • formal: pass k-induction proofs (6 jobs; parameters in formal/jobs.yaml): 6 test(s) passed in the recorded run evidence
  • formal: pass Each formal check refutes a planted fault (the check can fail): 9 test(s) passed in the recorded run evidence

FCMUL-F-BENCH: The bench catches seeded faults

Every one of the mutants in verif/mutants.yaml (one exact text change each: an inverted condition, a wrong constant, a dropped connection, a wrong width) makes the cocotb bench fail, or is argued equivalent in the file's header; mutants that survive or do not build are reported, never hidden.

  • simulation test: pass The mutation run as a test: no mutant survives, none fails to build: 1 test(s) passed in the recorded run evidence
  • simulation measurement: pass Mutants killed of valid mutants (the record of the last full run): survived = []; invalid = []; valid = 14; score_pct = 100 evidence

FCMUL-F-PACKAGE: The RTL is lint-clean, and its files agree with the specification and with the Vivado build files

spec.yaml states an interface contract (protocol, throughput, latency, reset, clock, stalls) and integration guidance (port timing, constraints to carry). Every variant passes Verilator -Wall at every point of spec.yaml; its ports and default parameters are the ones spec.yaml states; its header states the intended primitive use before any Vivado run; spec.md is the rendering of spec.yaml; the out-of-context wrapper and the build.yaml for each variant (Artix-7 xc7a100t and K26 xck26, prepared and not run) are current and lint-clean at every point they list, so a Vivado run can start from the repository alone.
