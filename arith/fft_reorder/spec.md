# Bit-reverse reorder buffer (ping-pong, continuous frames) (arith/fft_reorder)

Generated by `python -m arith.tools.gen_spec_md` from [spec.yaml](spec.yaml); edit the YAML, not this file. Part of the frequency-domain suite of brief 148 ([../README.md](../README.md)).

A frame of N = 2**LOGN words of WD bits arrives in N consecutive clocks (in_valid, the first word marked by in_sof) and leaves in N consecutive clocks with the word that arrived at position p now at position bitrev(p) (LOGN-bit reversal). It converts the bit-reversed output of a decimation-in-frequency FFT to natural order, and natural order to bit-reversed (bit reversal is its own inverse). Frames may follow each other with no gap: one bank is written while the other is read. Latency from in_sof to out_sof: N + 1 clocks.

## Function

- position p of a word is its index within its frame: 0 for the word with in_sof, 1 for the next, and so on up to N - 1
- the output frame is the input frame with its words permuted: output position k holds the input word of position bitrev(k, LOGN) (the LOGN bits of k in reverse order)
- the output frame starts N + 1 clocks after the input frame's in_sof clock and is N consecutive clocks of out_valid, the first with out_sof
- two banks of N words alternate: frame f is written into bank f mod 2 while frame f-1 is read from the other, so any number of back-to-back frames flow with no gap and no loss

Signedness: not applicable: the words are opaque bit patterns.

Exactness: exact permutation: every input word appears exactly once in the output frame, unchanged.

Latency: clocks from the clock in which in_sof is asserted to the clock in which out_sof is asserted: N + 1 (the whole frame must arrive before the first word of a bit-reversed read can leave, and the read is registered).

- `pingpong`, Artix-7 (xc7a100t): 0 DSP; 2 RAMB18 per 512 words of 36 bits or less (N = 1024, WD = 32: 4 RAMB18 or 2 RAMB36); distributed RAM below about N = 64; about 50 LUT6 and 4 * LOGN flip-flops of control

## Interface contract

Written without knowing the design the block will sit in (brief 139a, owner decision 24): this is what a user can rely on and must provide.

- Protocol: streaming, no back-pressure: in_valid is high for exactly N consecutive clocks per frame with in_sof on the first; frames may be back to back or separated by any number of idle clocks; there is no ready
- Throughput: one word per clock in and out, continuously (initiation interval 1, frames back to back)
- Latency: N + 1 clocks from in_sof to out_sof, for every frame
- Reset: synchronous, clears the write and read counters and the valid flags; the memories hold data and are not reset, so a frame that was in flight is lost
- Clock: one clock, rising edge, no clock-enable
- Stalls: none: there is no way to pause the input or the output; a gap inside a frame (in_valid low between its first and last word) is not allowed and its result is undefined

| Variant | Latency (clocks) | Throughput |
|---|---|---|
| `pingpong` | `(1<<LOGN)+1` | 1 word per clock, frames back to back |

## Integration

- Port timing: the memories are registered-read RAMs: the output word is available in the clock after the read address, then a 2:1 bank select; the output is combinational from registers
- Constraints to carry: one clock, no multicycle paths. Both banks are sized for the largest N used: 2 * N * WD bits
- Verification after integration: this function has no packaged harness (brief 148 left it out; see the report): rerun its bench (tests/) against your instance, which needs the repository's arith/tools and fft_common helpers.

## What a user could guess wrong

- the latency is N + 1, not N: the first word of the output frame leaves one clock after the last word of the input frame has arrived plus the registered read
- a new in_sof inside a frame restarts the frame silently (the words so far are lost, no error); a gap inside a frame is undefined, and nothing flags it
- the permutation is the bit reversal of the position within the frame, so it is its own inverse; it does not know about the FFT's inverse or about scaling
- rst does not clear the memories; a frame in flight when rst is asserted is lost (no test covers a reset in the middle of a frame)
- no out_valid is produced for an idle bank: outputs are only valid for N clocks after each frame (out_d is not meaningful when out_valid is 0)

## Lean, and what is research

Not attempted in Lean: that bit reversal is an involution and a permutation is proved exhaustively for LOGN 1 to 8 with SymbiYosys (formal/jobs.yaml), and by the model's tests for every LOGN up to 12.
