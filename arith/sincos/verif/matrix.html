Requirements in full

SIN-F-MODEL: The bit-exact model is right

arith/sincos/model.py gives, for every input, the result that spec.md defines. It agrees with an independent formulation (an exact rational (Fraction) evaluation of the interpolation formula, a floating-point CORDIC, and the maths library's sin and cos) on every input at small widths and with Python's integer arithmetic on random large-width inputs, and the conventions that a user could guess wrong (spec.md, last section) are pinned by examples.

  • simulation test: pass The model against independent formulations (exhaustive small, random large) and the pinned conventions: 6 test(s) passed in the recorded run evidence

SIN-F-EXACT: Every variant is bit-exact against its own model

At every parameter point listed in spec.yaml (16 exhaustive points, 9 random ones, across 3 variants), each variant's outputs equal its own model's (model.py, selected by variant) in every clock: every input is driven at the small points; edge values, table break points and random inputs at the large ones. The variants round differently and are not bit-identical to each other; the model of each is the bit-exact definition of that variant, and its distance from the exact function is the accuracy requirement.

  • simulation test: pass Every variant against the model, every input, at the small points (Icarus + cocotb): 16 test(s) passed in the recorded run evidence
  • simulation test: pass Every variant against the model at the large points: edge values, carry runs and random inputs (Icarus + cocotb): 9 test(s) passed in the recorded run evidence

SIN-F-ACC: The error against the exact function is within the stated bound, at every listed point

Each of the 9 accuracy points of spec.yaml states a bound in last places; the model's error against the exact function (the maths library, real arithmetic, unrounded) over EVERY input of that point is at most the bound and within 0.06 of it (so the bound is neither false nor loose). A point not listed has no stated bound.

  • simulation test: pass The model's error against the exact function over every input of every listed point, against the stated bounds: 9 test(s) passed in the recorded run evidence

SIN-F-LAT: Latency is as specified and the bench would notice if it were not

Each variant's latency in clocks is the expression in spec.yaml (lerp: 2; poly2: 3; cordic: NIT), and the bench, run with a latency two clocks off, fails for every variant, so the passing runs prove the latency rather than assume it.

  • simulation test: pass The bench passes at the stated latency and fails two clocks off, for every variant: 3 test(s) passed in the recorded run evidence

SIN-F-EQUIV: The error against the exact function is bounded for all inputs, by proof, at a small input width

SymbiYosys with the slang front end compares each variant, delayed by its latency, with the exact function on 8 input bits to 24 fractional bits (a reference ROM written from the maths library, formal/*_ref.sv) and asserts the error stays within the bound of the job, which is the model's measured error at that point plus one unit for the reference's own rounding. A proof is by k-induction (for all inputs, any run length) at the widths in formal/jobs.yaml; wider points are covered by the exhaustive scan of the accuracy requirement and by simulation, not by proof. The quadrant map and the variants' structural identities are inside the checks.

  • formal: pass k-induction proofs of the variants' error bounds against the exact function (6 jobs; widths in formal/jobs.yaml): 6 test(s) passed in the recorded run evidence
  • formal: pass Each formal check refutes a planted fault (the check can fail): 3 test(s) passed in the recorded run evidence

SIN-F-HARNESS: The packaged verification harness is a standalone deliverable that works

arith/sincos/harness holds the model, the cocotb bench, a SystemVerilog checker, coverage targets and a runner that needs nothing else from the repository. Run standalone against every variant (one small exhaustive point and one large random point each, with the checker beside the instance) it passes and the random runs meet every coverage target; run against a planted fault it fails, with and without the checker. Its generated files are the repository's own bench, so they cannot drift.

  • simulation test: pass The packaged harness run standalone on every variant (with the checker and the coverage targets) and on a planted fault: 8 test(s) passed in the recorded run evidence

SIN-F-LEAN-QUAD-SPLIT: The phase splits into a quadrant and an angle without loss, for every width

For every width k, a phase below 4 * 2^k splits into a quadrant (its top two bits) below 4 and an angle (the rest) so that quadrant * 2^k + angle is the phase again. The statement is the specification and is NOT approved by a human (verif/lean_approvals.yaml is empty), so the proof is shown but not counted as verification. The Lean text is a hand transcription of the RTL's structure; it models no timing or clocking.

SIN-F-LEAN-LERP: Linear interpolation stays between the segment's end values, for every width

In a rising segment with break-point value c0 and slope s, the interpolated value (c0 * 2^D + s * d) / 2^D lies between c0 and c0 + s for every position d below 2^D and every D: the table variant cannot overshoot its segment. The statement is the specification and is NOT approved by a human (verif/lean_approvals.yaml is empty), so the proof is shown but not counted as verification. The Lean text is a hand transcription of the RTL's structure; it models no timing or clocking.

  • Lean proof (all widths): statement not approved Linear interpolation stays between the segment's end values: statement not approved; ArithLerp.lerp_between: kernel only; proof of the transcription, transcription not tested; recorded build (not re-run) evidence
