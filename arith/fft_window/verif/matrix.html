Requirements in full

FWIN-F-MODEL: The bit-exact model is right

arith/fft_window/model.py gives, for every input, the result that spec.md defines. It agrees with an independent formulation (exact rational arithmetic of the rounding rule and the bound |y| <= |x|), and the conventions that a user could guess wrong (spec.md, last section) are pinned by examples.

  • simulation test: stale The model against independent formulations and the pinned conventions: 3 test(s) passed in the recorded run evidence

FWIN-F-EXACT: Every variant is bit-exact against the model

At every parameter point listed in spec.yaml (5 directed or exhaustive points, 4 random ones, across 1 variants), each variant's outputs equal the model's: every (xr, xi, w) is driven at the small points; edge values and random inputs at the large ones. The error bound (half a unit in the last place) is the model's rounding.

  • simulation test: pass Every variant against the model at the small points (Icarus + cocotb): directed or exhaustive stimuli: 5 test(s) passed in the recorded run evidence
  • simulation test: pass Every variant against the model at the large points: random stimuli (Icarus + cocotb): 4 test(s) passed in the recorded run evidence

FWIN-F-LAT: Latency is as specified and the bench would notice if it were not

Each variant's latency in clocks is the expression in spec.yaml (dsp: STAGES), and the bench, run with a latency two clocks off, fails for every variant, so the passing runs prove the latency rather than assume it.

  • simulation test: pass The bench passes at the stated latency and fails two clocks off, for every variant: 1 test(s) passed in the recorded run evidence

FWIN-F-EQUIV: The properties named in formal/jobs.yaml hold, by proof where the tools allow

SymbiYosys with the slang front end checks the properties of formal/jobs.yaml: a proof is by k-induction (for all inputs, any run length) at the parameters listed there, a bounded check holds only to its stated depth. What the jobs say is in each job's `claim`; parameters beyond the listed ones are covered by simulation, not by proof.

  • formal: pass k-induction proofs (5 jobs; parameters in formal/jobs.yaml): 5 test(s) passed in the recorded run evidence
  • formal: pass Each formal check refutes a planted fault (the check can fail): 4 test(s) passed in the recorded run evidence

FWIN-F-BENCH: The bench catches seeded faults

Every one of the mutants in verif/mutants.yaml (one exact text change each: an inverted condition, a wrong constant, a dropped connection, a wrong width) makes the cocotb bench fail, or is argued equivalent in the file's header; mutants that survive or do not build are reported, never hidden.

  • simulation test: pass The mutation run as a test: no mutant survives, none fails to build: 1 test(s) passed in the recorded run evidence
  • simulation measurement: pass Mutants killed of valid mutants (the record of the last full run): survived = []; invalid = []; valid = 7; score_pct = 100 evidence

FWIN-F-PACKAGE: The RTL is lint-clean, and its files agree with the specification and with the Vivado build files

spec.yaml states an interface contract (protocol, throughput, latency, reset, clock, stalls) and integration guidance (port timing, constraints to carry). Every variant passes Verilator -Wall at every point of spec.yaml; its ports and default parameters are the ones spec.yaml states; its header states the intended primitive use before any Vivado run; spec.md is the rendering of spec.yaml; the out-of-context wrapper and the build.yaml for each variant (Artix-7 xc7a100t and K26 xck26, prepared and not run) are current and lint-clean at every point they list, so a Vivado run can start from the repository alone.

  • simulation test: pass spec.yaml against the RTL headers, spec.md against spec.yaml, Verilator -Wall at every point, wrappers and build.yaml current and lint-clean: 5 test(s) passed in the recorded run evidence
