# Base-2 logarithm of a mantissa in [1, 2) (arith/log2)

Generated by `python -m arith.tools.gen_spec_md` from [spec.yaml](spec.yaml); edit the YAML, not this file. Part of the arithmetic library of brief 139d ([../README.md](../README.md)).

y = log2(m) for the mantissa m = 1 + x / 2**IW in [1, 2), the result an unsigned OW-bit fraction in [0, 1). Four implementations trade BRAM, DSP, LUTs, latency and accuracy: a direct table (correctly rounded, at most 8 input bits), a segment table with linear interpolation (one DSP), a segment table with a quadratic (two DSPs) and a hyperbolic CORDIC in vectoring mode (no DSP in the iterations, a stage per iteration). The general logarithm of a positive number is this core plus a normalisation that the caller owns (a leading-zero count and shift, as in brief 139b's lzc_norm; see Integration).

## Function

- x is the fraction x / 2**IW in [0, 1), the mantissa is m = 1 + x / 2**IW; y is read as the fraction y / 2**OW in [0, 1): y / 2**OW = log2(m)
- y is the variant's own arithmetic result rounded to nearest, ties upward, and clamped to [0, 2**OW - 1]; it is never wrapped
- table: y = round(T[x] / 2**(20 - OW)) where T is a 256-entry table of log2(1 + u) with 20 fractional bits, read at x * 2**(8 - IW) (so IW <= 8)
- lerp: the top SB bits of x pick a segment; with the table's value c0 and slope s1 (both 20 fractional bits, exact at the segment ends) and the position d in the segment (DB = IW - SB bits), y = round((c0 * 2**DB + s1 * d) / 2**(20 + DB - OW))
- poly2: the same segments with a quadratic a0 + a1 t + a2 t**2 (t = d / 2**DB) fitted at the three Chebyshev nodes of the segment; Horner in integers: p1 = (a2 d) >> DB (floor), q = a1 + p1, y = round((q d + a0 * 2**DB) / 2**(20 + DB - OW))
- cordic: hyperbolic vectoring from (X, Y) = (m + 1, m - 1) in units of 2**-(OW + G): NIT iterations (shifts 1, 2, 3, 4, 4, 5, ..., 13, 13, 14, ...; 4 and 13 are repeated) drive Y to 0 while the angle z accumulates atanh((m - 1) / (m + 1)); ln m = 2 z, so y = round(z * 2 / ln 2 / 2**G), with the constant 2 / ln 2 held to 20 fractional bits
- the four models differ in their rounding steps, so the variants are NOT bit-identical to each other; each variant is bit-exact against its own model (model.py) and within the stated error of the exact function

Signedness: x and y are unsigned.

Exactness: not exact: every variant is within the error stated in 'Accuracy' of the exact log2(m), which includes the rounding of y; the table variant is within half a last place plus the table's own rounding of 2**-21 of the function (0.03 last places at OW = 16, 0.0005 at OW = 8); the others are bit-exact against their own model but not against each other.

Latency: clocks from x being presented to y being valid: table REG, lerp 2, poly2 3, cordic NIT + 1; throughput is one result per clock in every variant.

## Accuracy

Error is |y - log2 ideal| in units of the last place of y (2**-OW), with the ideal log2(1 + x / 2**IW) taken in real arithmetic and not rounded, so a perfectly rounded result has error 0.5. The bound of each listed point is a measured maximum over every input of that point (python -m pytest arith/log2/tests/test_log2_accuracy.py), rounded up to 0.01. log2 has a large second derivative near m = 1, so lerp is worse here than for exp2 (about 3.4 last places at 16 bits and SB = 6); poly2 and the table sit near 0.5 to 0.65; cordic falls with NIT and G down to about 0.55 at OW = 14. A point not listed has no stated bound: measure it with model.max_error.

### Intended primitive use

- `table`, Artix-7 (xc7a100t): 0 DSP; one 256 x 20 ROM: a 36 Kb BRAM (RAMB36E1 in 18 Kb mode, output register absorbed when REG = 1) or about 100 to 150 LUT6 as distributed ROM; one 21-bit rounding adder; OW FFs when REG = 1
  - K26 (xck26): 0 DSP; as a7 with RAMB36E2 or LUT ROM; CARRY8 for the adder
- `lerp`, Artix-7 (xc7a100t): 1 DSP48E1 (22 x (IW - SB + 1) signed multiply-add); the 2**SB x 44-bit coefficient ROM in distributed RAM (a few dozen LUTs for SB <= 5; possibly a BRAM at SB = 6); about 3 x 22 FFs for the two stages (some absorbed by the DSP)
  - K26 (xck26): 1 DSP48E2; as a7
- `poly2`, Artix-7 (xc7a100t): 2 DSP48E1 (22 x DB then 24 x DB signed multiplies); a 2**SB x 66-bit coefficient ROM in distributed RAM (SB <= 5); about 3 x 24 FFs of stage registers (some absorbed by the DSPs)
  - K26 (xck26): 2 DSP48E2; as a7
- `cordic`, Artix-7 (xc7a100t): 0 BRAM; the z * 2 / ln 2 constant multiplier (about 24 x 22 bits: LUT adders or 1 to 2 DSP48E1), registered; per stage 3 add/subtract (about OW + G + 3 LUTs each in carry chains) and 3 registers of OW + G + 3, OW + G + 3 and OW + G + 2 bits; about 3 x NIT x (OW + G + 3) LUTs in total
  - K26 (xck26): as a7 with CARRY8 chains

## Interface contract

Written without knowing the design the block will sit in (brief 139d, owner decision 24): this is what a user can rely on and must provide.

- Protocol: plain registered-or-combinational ports, no handshake: x is sampled every clock and one result leaves, with no valid, ready or backpressure. A caller that needs a valid bit delays its own valid by the variant's latency
- Throughput: one result per clock in every variant (initiation interval 1)
- Latency: per variant, in clocks: table REG (0 or 1), lerp 2, poly2 3, cordic NIT + 1
- Reset: none: no control state; the pipelines hold data only and their outputs are meaningless for latency clocks after power-up
- Clock: one clock, rising edge, no clock-enable and no gating; clk is present but unused when the latency is 0
- Stalls: none: the pipeline cannot be frozen (no enable)

## Integration

- Port timing: x goes straight to a ROM address (table, lerp, poly2) or to the CORDIC's first adder (cordic): register x in the caller if it comes from logic. y leaves a register in every variant but the table with REG = 0; cordic's output is a registered constant multiplier. table with REG = 1 is a BRAM-friendly read: the ROM output register is the output register. lerp and poly2 put the ROM output in a register before the multiplier, so the DSP is fed by flip-flops
- Constraints to carry: no multicycle or false paths, one clock. DSP variants: keep the register stages un-merged so the DSP's registers can absorb them. For a general positive number v: normalise v = m * 2**e with m in [1, 2) (a leading-zero count and a left shift: arith/lzc_norm of brief 139b), take the mantissa's fraction as x, and log2(v) = e + y / 2**OW (the integer e is the exponent and y the fraction here, so the result is the fixed-point number e.y); ln v = log2(v) * ln 2 and log10 likewise by a constant multiply. Zero and negative inputs are the caller's to catch: this core's contract is the mantissa in [1, 2)
- Verification after integration: rerun the packaged harness against your instance ([harness/README.md](harness/README.md)); it needs no other file of this repository.

## What a user could guess wrong

- the input is the mantissa's fraction: x = 0 means m = 1 (log 0, y = 0) and x = 2**IW - 1 means m just below 2 (y just below 1); the leading one is not an input bit
- the output is a fraction of one: log2(m) for m in [1, 2) is in [0, 1), so y has no integer bit; the integer part of the logarithm of a general number is the exponent from the normalisation, outside this core
- the error is not 0.5 ulp for every variant: only the table variant (and poly2 at a good SB) is near it; lerp is several last places at 16 bits and cordic about 1.3; read the accuracy table of the variant before choosing
- the variants are not bit-identical to each other (different rounding steps): switching variant changes the low bits of y
- near m = 1 the function is steepest (slope 1.44 against 0.72 at m = 2), so the lerp and CORDIC errors are larger than for exp2 at the same widths
- table reads a 256-entry table whatever IW is (a narrower IW uses every 2**(8 - IW)-th entry), and IW above 8 is not supported by it; REG other than 0 or 1 behaves as 1
- the parameter ranges (SB inside 3 to 6 for lerp and 3 to 5 for poly2, SB < IW, NIT 4 to 24, OW + G <= 24, IW <= OW + G for cordic) are documented, not enforced by assertions: a value outside them gives wrong results without a message
- no reset and no valid: for latency clocks after power-up the output is not meaningful; there is no clock-enable
