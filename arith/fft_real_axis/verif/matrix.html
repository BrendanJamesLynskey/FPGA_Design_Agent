Requirements in full

FRAXIS-F-MODEL: The bit-exact model is right

arith/fft_real_axis/model.py gives, for every input, the result that spec.md defines. It agrees with an independent formulation (the wrapped core's own model (arith/fft_real/model.py) and the packing of the AXI words (the even sample in the low half of the input word, the real part in the low half of the output word)), and the conventions that a user could guess wrong (spec.md, last section) are pinned by examples.

  • simulation test: pass The model against independent formulations and the pinned conventions: 4 test(s) passed in the recorded run evidence

FRAXIS-F-EXACT: Every variant is bit-exact against the model

At every parameter point listed in spec.yaml (4 directed or exhaustive points, 3 random ones, across 1 variants), each variant's outputs equal the model's: the directed points send the real-FFT bench's frames as AXI4-Stream beats from a source that never pauses: the wrapper itself opens the gap, which the bench measures and requires to equal N/8 exactly, and the first-beat latency equals the formula; the random points send random real frames with random idle times up to N = 2048. Every output frame of N/2 + 1 bins equals the model bit for bit, tlast is on the right beat and the protocol checkers count no error.

  • simulation test: pass Every variant against the model at the small points (Icarus + cocotb): directed or exhaustive stimuli: 4 test(s) passed in the recorded run evidence
  • simulation test: pass Every variant against the model at the large points: random stimuli (Icarus + cocotb): 3 test(s) passed in the recorded run evidence

FRAXIS-F-LAT: Latency is as specified and the bench would notice if it were not

Each variant's latency in clocks is the expression in spec.yaml (post: (1<<(LOGN-1))-1+(LOGN-1)+((LOGN-2)//2)*(TWSTAGES+MULSTAGES+1)+(1<<(LOGN-1))+MULSTAGES+3), and the bench, run with a latency two clocks off, fails for every variant, so the passing runs prove the latency rather than assume it.

  • simulation test: pass The bench passes at the stated latency and fails two clocks off, for every variant: 1 test(s) passed in the recorded run evidence

FRAXIS-F-BENCH: The bench catches seeded faults

Every one of the mutants in verif/mutants.yaml (one exact text change each: an inverted condition, a wrong constant, a dropped connection, a wrong width) makes the cocotb bench fail, or is argued equivalent in the file's header; mutants that survive or do not build are reported, never hidden.

  • simulation test: pass The mutation run as a test: no mutant survives, none fails to build: 1 test(s) passed in the recorded run evidence
  • simulation measurement: pass Mutants killed of valid mutants (the record of the last full run): survived = []; invalid = []; valid = 11; score_pct = 100 evidence

FRAXIS-F-PACKAGE: The RTL is lint-clean, and its files agree with the specification and with the Vivado build files

spec.yaml states an interface contract (protocol, throughput, latency, reset, clock, stalls) and integration guidance (port timing, constraints to carry). Every variant passes Verilator -Wall at every point of spec.yaml; its ports and default parameters are the ones spec.yaml states; its header states the intended primitive use before any Vivado run; spec.md is the rendering of spec.yaml; the out-of-context wrapper and the build.yaml for each variant (Artix-7 xc7a100t and K26 xck26, prepared and not run) are current and lint-clean at every point they list, so a Vivado run can start from the repository alone.

  • simulation test: stale spec.yaml against the RTL headers, spec.md against spec.yaml, Verilator -Wall at every point, wrappers and build.yaml current and lint-clean: 5 test(s) passed in the recorded run evidence

FRAXIS-F-AXIS: The AXI4-Stream rules hold on both streams, and the checkers can fail

On both streams the wrapper's SystemVerilog protocol checkers (fft_common/axis_checker.sv: valid stays high until accepted, tdata and tlast stable while stalled, no unknowns after reset, tlast on every (N/2)-th beat of the input and every (N/2 + 1)-th beat of the output, no stall on the output, no pause inside an input frame) count zero violations in every run of the directed and random benches, the source of which presents the next frame at once and waits on tready. A deliberate-violation test shows each checker can fail (a pause inside a frame, a stalled sink). tvalid is registered and independent of tready by construction.

  • simulation test: pass The protocol checkers can fail (a pause inside a frame, a stalled sink): 1 test(s) passed in the recorded run evidence

FRAXIS-F-GAP: The wrapper enforces the transform's frame gap by back-pressure

After every beat with tlast on the input stream s_axis_tready is low for N/8 clocks (the measured gap rule of the real-input core), and a source that never pauses sees exactly N/8 idle clocks between its frames; every such frame is correct. Mutants that remove the gap, shorten it or lengthen it are killed.

  • simulation test: pass A source that never pauses sees exactly N/8 idle clocks between frames; every frame is right: 4 test(s) passed in the recorded run evidence

FRAXIS-F-HARNESS: The packaged harness runs standalone, passes on the repository's variants and catches faults

arith/fft_real_axis/harness/ (model, bench, SystemVerilog checkers, coverage targets, standalone runner: owner decision 24) needs no other file of the repository. Run against each variant of this function with the checkers beside it, in every mode, it passes and meets every coverage target; against one planted fault (a mutant of verif/mutants.yaml), or with a latency two clocks off, it fails; its model, bench and checker files are the repository's own, generated by arith/tools/gen_harness_fft.py, so they cannot drift.

  • simulation test: pass The harness against the repository's variants, a planted fault and a wrong latency: 3 test(s) passed in the recorded run evidence
