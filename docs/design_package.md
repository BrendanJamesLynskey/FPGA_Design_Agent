# The design package (brief 174)

A design that targets one board is easier to specify with the board's own files than with a description of them. A **package** is one
folder that holds the user's words, every board material the user has, and, optionally, an existing design to change in part. An ingest
step reads the files and writes **facts**, each with its source. The flow's `board.yaml`, the `off_chip:` section and the pin constraints are
checked against those facts, and the spec interview does not ask what a sourced fact already answers.

Why: `boards/kr260/board.yaml` said the PL Ethernet PHYs were Marvell M88E1111 (from the knowledge bank, citing UG1092). AMD's carrier BOM
(XTP757) and schematic (XTP743) say TI DP83867. A package with an ingest step finds that in one command (section 5).

## 1. The folder

```
my_board_design/
  spec.md             the user's words (public)
  package.yaml        the manifest (committed): files, kinds, sources, licences, hashes, board_fixed
  board/              every material the user has: schematic PDF or source, board file (Allegro, ODB++, IPC-2581, KiCad), BOM, vendor XDC and board
                      files, IBIS, data sheets, photos, the user's notes
  refs/               anything else useful: app notes, reference designs, protocol specs
  existing/           optional: an existing design to change in part (section 6)
  board_facts.yaml    generated by ingest (committed): the facts, the conflicts, what could not be read
  existing_inventory.yaml, design.yaml   generated by `existing` (committed)
  .gitignore          generated: the private files
```

### `package.yaml`

```yaml
name: kr260
board: kr260                  # boards/<board>/board.yaml, the flow's own entry that `check` compares with
part: xck26-sfvc784-2LV-c     # optional: declared by the user; used as a fact with confidence user-declared
board_fixed: true             # decision 30: the board is finished, so its series resistors cannot change (off_chip: board_fixed)
ingest: {net_filter: '^(HP[AB]\d|GEM[23]_)'}   # which Allegro nets become facts (regex); default every net not named N<digits>
existing: {change: [lat_hist]}                 # modules the agent may edit (section 6)
files:                        # written by `init`; a person fills source_url, licence and public
  - {path: board/xtp757_kr260_bom.xls, kind: bom, source_url: ..., licence: ..., public: false, sha256: ..., bytes: 53760}
```

`board_fixed: false` (the default) means the user can still change the board; the off-chip check then offers both answers without saying
which applies. A file is **private by default**: only `spec.md` and files a person marked `public: true` are committed. Third-party files
that may not be redistributed (AMD's schematics, BOMs and board files, for example) stay in the package on disk and are git-ignored
(`gitignore` writes `<package>/.gitignore` from the manifest). What is committed is the manifest, with the hashes, and the derived facts. A
clone therefore has the hashes but not the files: `verify` treats a missing private file as absent, not as an error, and `ingest` then says which
files it could not read.

## 2. Commands

| Command | What it does |
|---|---|
| `python -m flow.package init <dir>` | lists the files, keeps what a person wrote in the manifest, refreshes kind and SHA-256 |
| `... verify <dir>` | a changed hash, an unlisted file or a missing public file is a problem (exit 1) |
| `... gitignore <dir>` | writes the `.gitignore` of the private files |
| `... ingest <dir>` | writes `board_facts.yaml` |
| `... allegro-script <dir>` | writes `board/dump_allegro.sh`, the owner-run Allegro dump (section 4) |
| `... check <dir> [--board B]` | compares the facts with `boards/<B>/board.yaml`: conflicts, confirmations, fields missing as data |
| `... offchip <dir>` | an `off_chip:` fragment: `board_fixed`, the trace length per net, series resistors found |
| `... existing <dir>` | inventories `existing/`, writes `existing_inventory.yaml` and the `owned:` list of `design.yaml` |
| `... frozen-check <dir> <work> [--timing-before R --timing-after R]` | the gates on an edited copy of `existing/` (section 6) |

`.xls` BOMs need `xlrd` (not a dependency of the flow: install it in a venv, or save the BOM as `.csv`). PDF text needs `pdftotext`.

## 3. What ingest extracts

Every fact in `board_facts.yaml` is `{key, value, source: {file, locator, sha256}, confidence}`. Confidence is `high` (the file states it as data),
`medium` (read from a label or computed from the file, with the reading named), `low` (a text heuristic: the agent interview does not use
low-confidence facts) or `user-declared`.

| Key | From | Notes |
|---|---|---|
| `part` | `package.yaml` or a Vivado `board.xml` | the SOM's device is not in a carrier-card file, so the user declares it |
| `pin.<port>` (pin, iostandard) | an XDC (Digilent's master files list pins commented out: still read, the locator says so) | the bank per pin is not in an XDC |
| `iostandard.<std>.vcco_v` | the standards the XDC uses | the VCCO the standard needs, `medium`; **not** the VCCO of a bank |
| `clock.<port>` (MHz) | `create_clock` lines | commented-out lines are `medium` |
| `chip.<role>.<family>` (part number, refs, quantity) | the BOM | roles: PHY, memory, USB bridge and PHY, clock buffer; extend `CHIPS` in `flow/package.py` |
| `oscillator.<part>` (MHz, refs) | the BOM rows whose description starts `Osc` | which net an oscillator drives is on the schematic |
| `clock_label.<name>` (MHz, standard) | the schematic text, "25 MHz LVCMOS (PL GEM2&3)" | `medium`: a label in the text |
| `chip_on_schematic.<family>` | the schematic text | corroboration that the BOM part is on the schematic |
| `bom.series_resistors` | the BOM rows `Res <=100 R` | every use of that value, **not only series ones**: the BOM has no nets |
| `series_r.<net>` | schematic text where a net and a resistor reference sit together | `low`: check on the drawing |
| `trace_length_mil.<net>` | an Allegro dump (`nets.csv`) | summed over layers, copper only (no SOM routing), no Dk in the file, so the delay is a range |

**Conflicts.** Two facts with the same key and different values from different files are listed under `conflicts` with both sources. They are
never resolved, and both facts stay in the file. `check` adds the comparison with `boards/<B>/board.yaml` (the part, the PHY, the clock, the
GT reference clock and, when the board has a master XDC, every pin and I/O standard). A fact the board file marked "unconfirmed" and the package now
sources is listed as a confirmation.

**What a user could guess wrong:**

- `bom.series_resistors` is a list of resistor values, not of series resistors. A series resistor is a resistor in a net: that needs the netlist.
- `trace_length_mil` is the carrier copper only. The SOM's own routing and the package are not in it.
- A fact from a private file stays in the committed `board_facts.yaml`, with its file name and hash but not its content. A reader without the
  file can check the hash only against another copy.
- The ingest does not read a KiCad, ODB++ or IPC-2581 board file, an IBIS file or a photo: it lists them under `not_read`.
- No pin-to-net mapping comes from the Allegro dump yet (brief 162's gap), so a port's trace length is chosen by net family by hand.
- The `board_fixed` flag is the user's statement. Nothing in the ingest checks that the board is finished.

## 4. The Allegro parser (owner-run)

An agent must not run a locally built binary on a vendor board file (the auto-mode classifier refuses it, and the KiCad importer is GPL).
`allegro-script` writes `board/dump_allegro.sh`; the owner runs it with `DUMPER=<built dump program>`. The script writes `nets.csv`,
`net_vias.csv`, `layers.csv` and `meta.txt` into `board/allegro_dump/`, and the next `init` and `ingest` pick them up. The raw CSV is a
derived file of the vendor's board file: it stays private; the facts (lengths) are committed.

## 6. An existing design to change in part

`existing/` holds the design as it is: HDL (SystemVerilog, Verilog, VHDL), XDC, a Vivado project (`.xpr`), block designs (`.bd`), IP (`.xci`),
and optionally the last build's reports (`timing_summary.rpt`, `utilization.rpt`) and checkpoint. `spec.md` says what to change, and
`package.yaml` `existing.change` names the modules (ingest reports it as a conflict when `spec.md` never names one of them).

`existing` writes the inventory: the top (a module no other module instantiates; none or several is reported), the hierarchy, each module's
parameters and ports, the clock ports and reset ports of the top (by name), the XDC files with their clocks, the IP (vendor:library:name:version
from `.xci`), the last timing (WNS, TNS, WHS, THS from `report_timing_summary`) and utilisation (LUTs, registers, BRAM, DSP), and a list of what it
could not read.

Every file under `existing/` except the files that define a module named for change is written to `design.yaml` `owned:` (the existing
ownership marks, `docs/design_environment.md` section 7). `frozen-check <dir> <work>` takes an edited copy of `existing/` and fails when:

1. a frozen file is changed or removed (byte for byte, SHA-256);
2. a frozen module's interface (parameters excluded, ports with direction and width text) differs from the inventory;
3. a constraint file that is not frozen has a different number of pinned ports or different clocks, or a new constraint file appears;
4. with `--timing-before` and `--timing-after`: WNS or WHS is worse.

**What it cannot read or check** (listed in `unreadable` where it can be known):

- **Block designs** (`.bd`) are kept and frozen whole; cells, connections and the IP inside are not inventoried.
- **Encrypted HDL** (`` `pragma protect ``) has no interface in the inventory.
- **A project-mode-only flow:** an `.xpr` gives the part and a source count only; strategies and synthesis options are not translated into the flow.
- **VHDL** is read with a simpler parser than Verilog (entities, ports and `entity work.x` or component instances).
- **Port width equality is textual:** `[7:0]` against `[ 7 : 0 ]` is normalised, `[W-1:0]` against `[8-1:0]` is a difference.
- A module's parameters are not part of the interface check.
- **Constraints and timing:** a changed XDC that is not frozen is only checked for pin count and clocks; the "no worse" gate needs the user's own
  after-report, from a run the gate does not make. Nothing re-implements a frozen module to see whether its timing moved.
- The gate does not check that the change touches only the named module's behaviour: that is the verification stages' job.

Pilot 2 (b58a_trigger, `packages/b58a_change/`): change request, "make lat_hist's `lost` counter saturate". Results in
`results/174_design_package/pilot_b58a/`: the testbench `packages/b58a_change/tests/lat_hist_lost_tb.sv` gives `wrapped` on the unchanged module and
`saturated` on the changed one (iverilog 12); `frozen-check` passes for the one-line change; a frozen-file edit, a lost frozen file, a changed
frozen interface and a worse WNS each fail in `flow/tests/test_174_package.py`. No Vivado synthesis was run (both heavy slots were taken).

## 7. The agent hook

`agent/graph/package_facts.py` loads `board_facts.yaml` from the design directory (or `package/`) and `Interview` consults it before it asks.
A question is answered from a fact only when the question has one of these shapes (the question text is matched, so a free-form question is
asked as before): the device ("which part"), the PHY ("PHY", when the board has one PHY family), "pin" or "I/O standard" with a port that has a
`pin.<port>` fact, "series resistor" with a net that has a `series_r.<net>` fact, a clock frequency with a port that has a `clock.<port>` fact.
Facts of confidence `low`, without a source, or with two different values are not used. An answered question is recorded with `by: package`,
the key and the source (file, locator, hash) as evidence, does not count against the 12-question limit, and the ledger shows it as `auto`.
